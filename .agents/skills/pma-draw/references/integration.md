# Integration Guide

How downstream consumers embed or reference a `.rfd.json` generated by pma-draw. Covers four paths:

1. **MDX / React** — import the viewer as a component
2. **Browser SDK** — `<script>` tag, no bundler
3. **URL-loaded JSON** — point the viewer at a hosted `.rfd.json`
4. **Server-rendered SVG** — fetch a static SVG URL, suitable for `<img>` / GitHub / README

---

## 1. MDX / React

Use when the consumer is a docs site (Docusaurus, Nextra, Astro, Next.js app router MDX) or any React app.

### Install

```bash
pnpm add @pma/viewer
# or: npm i @pma/viewer  /  yarn add @pma/viewer
```

### Import (MDX)

```mdx
import { PmaViewer } from '@pma/viewer'
import '@pma/viewer/style.css'

# Ingest Pipeline

<PmaViewer src="/diagrams/ingest.rfd.json" height={560} />
```

### Import (TSX / JSX)

```tsx
import { PmaViewer } from '@pma/viewer'
import '@pma/viewer/style.css'
import data from './diagrams/ingest.rfd.json'

export default function ArchPage() {
  return <PmaViewer data={data} height={560} fitView />
}
```

### Props

| Prop | Type | Default | Notes |
|------|------|---------|-------|
| `src` | `string` | — | URL to a `.rfd.json`. Mutually exclusive with `data`. |
| `data` | `RfdFile` | — | Inline JSON object matching `pma-draw/v1` schema. |
| `height` | `number \| string` | `"60vh"` | Pixel or CSS height. |
| `width` | `number \| string` | `"100%"` | Container width. |
| `fitView` | `boolean` | `true` | Auto-fit all nodes on mount. |
| `interactive` | `boolean` | `true` | `false` disables pan/zoom/drag — good for static docs. |
| `theme` | `"light" \| "dark" \| "auto"` | `"auto"` | `auto` follows `prefers-color-scheme`. |
| `toolbar` | `boolean` | `true` | Show fit-view + export buttons. |
| `onReady` | `(api) => void` | — | Fires after mount; `api` exposes `exportPNG()`, `exportSVG()`, `fitView()`. |

### SSR Notes

- `@pma/viewer` is client-only. In Next.js App Router, wrap with `"use client"` or use `next/dynamic({ ssr: false })`.
- In Astro / Nextra, load via `<PmaViewer client:only="react" />`.

### Minimum Viable Hosted Mount

```html
<!-- in any MDX -->
<PmaViewer src="https://diagrams.example.com/ingest.rfd.json" />
```

## 2. Browser SDK (UMD / script tag)

Use when there is no React, no bundler — a plain HTML page, a CMS, a blog post.

### CDN

```html
<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/@pma/viewer/dist/style.css" />
<script src="https://cdn.jsdelivr.net/npm/@pma/viewer/dist/pma-viewer.umd.js"></script>

<div id="diagram" style="height: 560px"></div>

<script>
  // Option A: inline data
  PmaViewer.mount('#diagram', {
    data: { schema: 'pma-draw/v1', type: 'reactflow', nodes: [...], edges: [...] }
  });

  // Option B: load from URL
  PmaViewer.mount('#diagram', {
    src: '/diagrams/ingest.rfd.json',
    interactive: true,
    theme: 'auto'
  });
</script>
```

### `PmaViewer.mount(selector, options)` returns a handle:

```js
const handle = PmaViewer.mount('#diagram', { src: '...' });

handle.fitView();
const svg = await handle.exportSVG();   // string
const png = await handle.exportPNG();   // data URL
handle.update({ src: '/diagrams/other.rfd.json' });
handle.destroy();
```

### Pinning a version

```html
<script src="https://cdn.jsdelivr.net/npm/@pma/viewer@1.2.3/dist/pma-viewer.umd.js"></script>
```

Pin for reproducible rendering in docs; omit for always-latest.

## 3. URL-Loaded JSON

Use to host diagrams as static assets and reference them from anywhere.

### Hosting

Any static host works — S3, GitHub Pages, Vercel, a CDN bucket. The file must be served with:

- `Content-Type: application/json`
- `Access-Control-Allow-Origin: *` (or the origin of the consumer) — required because the viewer fetches it from another domain
- Cache headers you want (immutable content hash filenames recommended: `ingest.abc123.rfd.json`)

### Reference from the hosted viewer

```
https://viewer.example.com/?src=https://diagrams.example.com/ingest.rfd.json
```

Query params supported by the hosted viewer:

| Param | Effect |
|-------|--------|
| `src` | URL to a `.rfd.json` |
| `theme` | `light` / `dark` / `auto` |
| `fit` | `0` disables auto fit-view |
| `interactive` | `0` makes it read-only |
| `toolbar` | `0` hides the toolbar |
| `zoom` | Override `viewport.zoom` |

### Reference from MDX / React

```mdx
<PmaViewer src="https://diagrams.example.com/ingest.rfd.json" />
```

### Reference from a plain `<a>` / button

```html
<a href="https://viewer.example.com/?src=https://diagrams.example.com/ingest.rfd.json"
   target="_blank">Open diagram ↗</a>
```

### CORS Troubleshooting

| Symptom | Fix |
|---------|-----|
| "Failed to fetch" / opaque error | Ensure host returns `Access-Control-Allow-Origin`; check via `curl -I` |
| JSON loads in browser directly but viewer shows blank | `Content-Type` is likely `text/plain`; fix the host or add `?type=json` |
| 404 on private repo raw URL | Use a signed URL or host from a public bucket / CDN |

## 4. Server-Rendered SVG

Use when the target is a renderer that **cannot execute JavaScript** — GitHub README, GitLab issues, email, PDF exports, markdown previews. The SVG endpoint consumes a `.rfd.json` URL and returns pre-rendered SVG.

### Endpoint

```
GET https://viewer.example.com/render.svg?src=<json-url>
```

Returns `Content-Type: image/svg+xml`.

### Query Params

| Param | Type | Default | Notes |
|-------|------|---------|-------|
| `src` | URL | — | **Required.** URL to the `.rfd.json`. Must be publicly fetchable by the render service. |
| `theme` | `light` / `dark` | `light` | Forces palette; `auto` is not meaningful server-side. |
| `width` | number | auto from bounding box | Pixel width of rendered SVG. |
| `padding` | number | `40` | Padding around the bounding box. |
| `fit` | `1` / `0` | `1` | When `1`, ignore `viewport` and fit all nodes. |

### Use in Markdown / README

```md
![Ingest architecture](https://viewer.example.com/render.svg?src=https://diagrams.example.com/ingest.rfd.json)
```

GitHub renders SVG inline. For dark mode support:

```md
<picture>
  <source media="(prefers-color-scheme: dark)" srcset="https://viewer.example.com/render.svg?src=https://.../ingest.rfd.json&theme=dark">
  <img src="https://viewer.example.com/render.svg?src=https://.../ingest.rfd.json&theme=light" alt="Ingest architecture">
</picture>
```

### Use in HTML / MDX

```html
<img src="https://viewer.example.com/render.svg?src=/diagrams/ingest.rfd.json"
     alt="Ingest architecture"
     style="max-width: 100%" />
```

### Use in `<object>` (preserves internal links)

```html
<object
  data="https://viewer.example.com/render.svg?src=/diagrams/ingest.rfd.json"
  type="image/svg+xml"></object>
```

Nodes with `data.href` become anchor tags in the SVG, clickable in browsers.

### Caching

The SVG endpoint:

- Sets `Cache-Control: public, max-age=300, s-maxage=3600` by default.
- Honors `If-None-Match` / `ETag` — safe to embed in high-traffic pages.
- Treats the `src` URL's own ETag as the primary cache key; bumping the JSON bumps the SVG.

For fully deterministic embeds, include a version hash in the `src` URL (`ingest.abc123.rfd.json`).

### Size & Timeout Limits

| Constraint | Default |
|------------|---------|
| Max `src` response size | 2 MB |
| Max nodes in diagram | 500 |
| Render timeout | 10 s |
| Max output SVG size | 10 MB |

Beyond these, split the diagram — see `design.md` "Multi-zoom architecture" and `SKILL.md` "section-by-section".

### Security Notes

- The SVG service fetches `src` server-side. Only hosts listed in the service's allow-list are accepted; submit your domain to be whitelisted, or self-host the render service for private JSON.
- Returned SVG has inline styles only — no external scripts, no network references — safe to embed in sandboxed contexts.

## Choosing an Integration Path

```
Is the consumer a React / MDX site?
├── yes → Path 1 (MDX component). Use `src` for hosted JSON, `data` for bundled JSON.
│
└── no  → Does the consumer execute JavaScript?
          ├── yes → Path 2 (Browser SDK) — drop a <script> and mount into a div.
          │
          └── no  → Path 4 (Server-rendered SVG) — embed the SVG URL as <img> or ![]().

If the consumer only needs to link out (not inline the diagram):
  → Path 3 (URL to hosted viewer) — a single <a href> opens the interactive viewer.
```

## Handoff Snippets for the Agent

When pma-draw finishes generating a file, include one of these in the handoff message based on likely consumer context:

- **Docs site using MDX**:
  > Saved `docs/architecture/ingest.rfd.json`. Embed in MDX via `<PmaViewer src="/diagrams/ingest.rfd.json" />` after installing `@pma/viewer`.
- **Plain HTML page**:
  > Saved `public/diagrams/ingest.rfd.json`. Include the `pma-viewer` UMD script and call `PmaViewer.mount('#diagram', { src: '/diagrams/ingest.rfd.json' })`.
- **GitHub README**:
  > Saved `docs/architecture/ingest.rfd.json` and pushed to `main`. Reference in README via `![Ingest](https://viewer.example.com/render.svg?src=https://raw.githubusercontent.com/<org>/<repo>/main/docs/architecture/ingest.rfd.json)`.
- **Private repo / internal docs**:
  > Saved `docs/architecture/ingest.rfd.json`. Host the JSON on the internal CDN; open interactively at `https://viewer.internal/?src=<internal-url>` or self-host the SVG service to embed images without exposing the JSON publicly.
