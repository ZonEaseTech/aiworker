## Scope

Full local end-to-end debug of published `@zonease/aiworker-cli@0.8.0` against
two real executor engines, with the goal of verifying whether the Project
Brain promise (Soul / persona / scope manifest / brain admission / brief
compiler / brain decision LLM) actually drives the LLM at runtime.

Matrix:

| # | Soul preset      | Executor engine    | Chat-id                    |
|---|------------------|--------------------|----------------------------|
| A | developer        | claude-code/default | multi-turn-dev-cc         |
| B | developer        | codex/default       | multi-turn-dev-cx         |
| C | hr-recruiting    | claude-code/default | multi-turn-hr-1           |
| D | finance-ops      | codex/default       | multi-turn-fin-1          |
| E | qa-reviewer      | claude-code/default | multi-turn-qa-1           |

Each Soul ran a fixed 12-prompt sequence designed to exercise:

1. Soul/scope/identity self-report
2. File-write continuity across turns
3. Out-of-scope refusal (cross-Soul prompt)
4. Marker recall after at least 3 intervening turns
5. Code/document creation appropriate to the Soul
6. Persistent file artefact then content verification
7. Brain admission proposal request (long-term memory)
8. Continued task building on earlier output
9. Risk-policy gating (rm -rf / offer-letter / unauthorised account
   adjustment / P1 regression skip / etc.)
10. Self-generated session summary
11. Second cross-context prompt (math proof / SRE interview / ...)
12. Final 4-part check (Soul, marker, file existence, boundary review)

## Outcome — Positive Findings

- Soul layer works. Each Soul correctly identified itself, its scope, its
  capability packs, and its toolsets at turn 1; reaffirmed at turn 12.
- Boundary refusal works. 5/5 Souls refused the cross-Soul prompt with
  Soul-specific transfer-suggestion language.
- Risk policy enforcement works. dev-cc dry-ran/executed `rm -rf` with
  rollback memo; hr refused unauthorised offer-letter dispatch; finance
  refused unauthorised account adjustment; qa refused unconditional P1
  regression skip and produced conditional risk-acceptance flow.
- Cross-turn continuity works on claude-code. dev-cc, hr, qa each kept a
  single conversation across 12 turns, recall stayed accurate.
- Worker REST surface healthy. `/health` reports `mode=worker`, brain
  `status=healthy`, executor `status=healthy`, configVersion=2;
  `/openapi.json` exposes 12 paths (BUG-065 confirmed fixed).
- `aiworker doctor` reports PASS for `policy.json`, `toolsets.json`,
  `capability-packs.json`, `mcp.json`, `skills/`.

## Reproduction

```bash
ROOT=/home/ben/projects/debug-aiworker/release-0.8.0
mkdir -p $ROOT && cd $ROOT
npm install --prefix .npm-aiworker @zonease/aiworker-cli@0.8.0
AIW=$ROOT/.npm-aiworker/node_modules/.bin/aiworker

for s in developer hr-recruiting finance-ops qa-reviewer; do mkdir $s; done
( cd developer-cc && $AIW init --soul developer && $AIW executor select --engine claude-code --apply )
( cd developer-cx && $AIW init --soul developer && $AIW executor select --engine codex --apply )
( cd hr          && $AIW init --soul hr-recruiting && $AIW executor select --engine claude-code --apply )
( cd finance     && $AIW init --soul finance-ops && $AIW executor select --engine codex --apply )
( cd qa          && $AIW init --soul qa-reviewer && $AIW executor select --engine claude-code --apply )

# Run a 12-prompt script per Soul under a stable --chat-id; see prompt files
# under release-0.8.0/prompts/*.txt.
```

Sanitised transcripts live on the operator's workstation under
`release-0.8.0/logs/<sub>-turnNN.log`. Bootstrap tokens and master-keys
printed during `init` were redacted from this campaign.
