# BUG-127 CLI continuation turns lose capability metadata

- **status**: completed
- **priority**: P0
- **owner**: codex

- **claimedAt**: 2026-05-17
- **completedAt**: 2026-05-17

- **relatesTo**: apps/cli/src/aiworker.ts, packages/core/src/worker/runtime.ts, packages/core/src/worker/runtime.test.ts

## Background

The first real Codex-backed HR session showed turn 2 prompt metadata as:

```text
Output kind: business-artifact
metadataJson = { "executionMode": "local-cli" }
```

The session itself had been created from `aiworker-hr.person-profile`, but
`turn send` only passed `executionMode`, causing continuation prompts and
runtime capture metadata to lose `outputKind`, `skillName`, and review rubric
context.

## Root Cause

`LocalWorkerRuntime.startTurn` built prompts and captured results from only the
per-turn metadata, while the CLI continuation command also failed to enrich the
turn from the session's capability template.

## Fix

- Merge session metadata and turn metadata before building the invocation
  prompt, storing turn/invocation metadata, invoking the executor, and
  registering artifacts.
- Enrich CLI `turn send` metadata from the Host capability template.
- Add CLI `--model` and `--reasoning` overrides for real Codex debugging.

## Verification

- `bun run --filter '@zonease/aiworker-cli' test src/aiworker.test.ts`
- 30-turn HR matrix showed all continuation turns retaining
  `person-profile` or `candidate-screen` output kind.
