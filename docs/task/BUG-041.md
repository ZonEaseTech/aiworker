# BUG-041 Project-scope engines start outside the project root

- **status**: completed
- **priority**: P1
- **owner**: local
- **createdAt**: 2026-04-30 18:08
- **completedAt**: 2026-04-30 18:26
- **plan**: PLAN-050
- **relatedFeature**: FEAT-031

## 描述

项目级 worker 的运行语义应以当前项目根目录为 engine 工作目录。当前实现虽然把
Soul、Skill、memory 和 MCP 放在 `<project>/.aiworker/`，但 agentic CLI executor
实际收到的 `workspacePath` 默认是 `<project>/.aiworker/local/data-root/workspaces/<conversationId>/`
下的空目录。

这会让 Claude Code、Codex、Cursor 等 engine 不能天然读取项目根目录里的
`AGENTS.md`、`CLAUDE.md`、`.agents/`、`.claude/` 和项目源码，导致项目级 worker
只拥有 AIWorker 自己的 `.aiworker` 配置，却丢失 engine 原生的项目上下文能力。

## 调查结论

已确认的调用链：

1. `resolveAiworkerScope()` 在 project scope 返回 `<project>/.aiworker/local` 作为
   AIWorker home，并保留 `projectRoot`。
2. `WORKER_DATA_ROOT` 默认派生为 `<AIWORKER_HOME>/data-root`。
3. `WorkspaceManager.createWorkspace()` 默认创建 per-conversation 空目录。
4. `Orchestrator.buildAgentRunInput()` 把该 workspace 传给 executor。
5. Claude Code / Codex executor 都用 `workspacePath` 作为子进程 `cwd`。

## 期望行为

1. project scope 的默认 engine `cwd` 是 `projectRoot`，以保留 engine 原生项目文件加载。
2. `.aiworker/AGENT.md`、`SOUL.md`、`USER.md`、`MEMORY.md`、`ROLLUP.md` 进入 system prompt。
3. `.aiworker/local` 继续只存 worker 私有状态，不成为 engine 的语义项目根。
4. user / explicit scope 保持原来的 per-conversation workspace 行为。
5. operator 显式配置 git-origin 或 workspaceRoot 时继续走隔离 workspace，保留手动隔离能力。

## 验收标准

1. project scope 默认 `createWorkspace()` 返回项目根目录，且 dispose / purge 不删除项目目录。
2. explicit/user scope 仍创建 `<WORKER_DATA_ROOT>/workspaces/<conversationId>/`。
3. 配置了 git-origin 或 workspaceRoot 时不启用 project root shared cwd。
4. Orchestrator + Claude Code 回归测试覆盖 project root `cwd`，证明 executor 子进程运行在项目根。
5. Orchestrator 回归测试覆盖 `.aiworker` persona / memory docs 的 system prompt 注入。
6. 聚焦测试、typecheck 和 lint 通过，或记录未通过原因。
