# BUG-039 优化 npx / bunx CLI 启动体验

- **status**: completed
- **priority**: P1
- **owner**: self

- **plan**: PLAN-047

## 描述

`@zonease/aiworker-cli@0.4.8` 的 npm 包当前把 `aiworker` bin 直接指向 Bun bundle：

```json
{
  "bin": {
    "aiworker": "./aiworker.js"
  },
  "engines": {
    "bun": ">=1.1"
  }
}
```

发布产物 `aiworker.js` 第一行是 `#!/usr/bin/env bun`。用户在未安装或 PATH 不含 Bun 的环境中执行：

```sh
npx @zonease/aiworker-cli -h
```

会在 npm 安装提示后失败为底层 shebang 错误：

```text
env: bun: No such file or directory
```

这对首次试用不友好，也没有说明 AIWorker CLI 需要 Bun runtime、如何安装 Bun、如何使用 `bunx`，或如何改用 GitHub Release 的 standalone binary。

验收标准：

1. `npx @zonease/aiworker-cli -h` 在没有 Bun 时不再暴露原始 `env: bun`，而是返回清晰、可执行的安装/替代路径提示。
2. 安装了 Bun 的环境中，`npx` 与 `bunx` 仍能执行真实 CLI，并保持 `--version` / `-h` 输出正确。
3. npm publish artifact 仍从 `apps/cli/dist` 发布，并保留 `drizzle/` 与 `web/` 运行时资源。
4. 发布前的 pack / smoke 验证能覆盖 npm tarball 的 bin 入口。
