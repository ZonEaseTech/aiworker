# BUG-062 `aiworker brain brief` still emits `undefined: not found` artifact line in 0.7.0 when `--artifact` is omitted

- **relatesTo**: BUG-054 (same defect first observed in 0.6.0)

## Observed Behavior

Identical to BUG-054 (already marked `[x]` against 0.6.0) but **still present in published 0.7.0**:

```bash
aiworker brain brief --task "我想理解项目结构"
```

Output includes:

```json
{
  "id": "artifact-summary",
  "source": "artifact-summary",
  "body": "# Referenced artifacts (redacted)\n- undefined: not found in brain artifact registry\n  _All requested artifacts were missing or unreadable._",
  "tokens": 35
}
```

When no `--artifact <id>` flag is passed there should be no synthetic `undefined` artifact request. The current behavior wastes 35 token in every brief and outputs nonsense to the LLM.

## Expected Behavior

Same as BUG-054 expected behavior:

- Skip the `artifact-summary` section entirely when `--artifact` is empty
- OR emit a single benign stub: `# Referenced artifacts\n_None requested._`

## Why this is a separate task vs reopen BUG-054

Per PMA convention "不要修改已 completed 的旧 task", BUG-054 stays `[x]` (it was applied to a 0.6.0 fix path that didn't actually solve the issue against published 0.7.0). New BUG-062 owns the regression, with relatesTo back to BUG-054.

## Reproducer

```bash
DEBUG_ROOT=/home/ben/projects/debug-aiworker/qa-2026-05-04-v0.7.0
cd $DEBUG_ROOT/proj-developer
aiworker brain brief --task "x" \
  | python3 -c 'import json,sys; o=json.load(sys.stdin); print([s for s in o["brief"]["sections"] if s["id"]=="artifact-summary" and "undefined" in s["body"]])'
# expected: []
# actual: [{...,'body':'# Referenced artifacts...undefined: not found...'}]
```

## Validation

After fix, the brief without `--artifact` must not contain any `artifact-summary` section that mentions "undefined".
