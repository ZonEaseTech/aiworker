# BUG-134 Engine asset projection can overwrite promoted profile README

- **priority**: P0
- **owner**: codex

- **claimedAt**: 2026-05-17

## Description

After a clean `aiworker profile promote` wrote the accepted profile README,
subsequent runtime initialization through a CLI read path projected
`engine-assets/workspace/README.md` back over the workspace `README.md`. The
workspace git ledger then committed a second `profile: initialize workspace`
after the approval commit, restoring the starter profile scaffold and losing
the promoted accepted profile from the working tree.

## ActiveForm

Protecting promoted profile README from workspace asset reprojection.

## Acceptance Criteria

- Engine asset workspace projection does not overwrite an existing
  `README.md`.
- Root agent instructions such as `AGENTS.md` and `CLAUDE.md` can still be
  repaired by runtime initialization.
- Regression tests cover promotion followed by runtime re-initialization with
  app-authored engine assets.
- Real disposable CLI debug proves the promoted README survives a follow-up
  CLI read/Web daemon initialization.

## Notes

- 2026-05-17 17:48: Reproduced in
  `/private/tmp/aiworker-hr-prod-fix-20260517-2gs7kH`. Promotion commit
  `861e63a35c5c1e9798607586c2365d580013270b` was followed by
  `b6eb2a3 profile: initialize workspace`, and `README.md` reverted to the
  starter scaffold.

## Results

- Engine asset workspace projection now preserves an existing `README.md`
  instead of overwriting it on runtime initialization.
- The existing root instruction repair behavior remains intact for files such
  as `AGENTS.md` and `CLAUDE.md`.
- Added a runtime regression test that promotes a fenced profile draft, reruns
  runtime initialization with engine assets, and confirms the accepted README
  remains intact.
- Re-promoted the Grace Hopper artifact after the fix; the accepted README
  survived a follow-up CLI `files show` and daemon-served Web load without a
  new scaffold overwrite.
