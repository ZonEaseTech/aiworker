## Description

`aiworker profile promote` accepted a real Codex-generated
`aiworker-profile-readme` fenced draft that still contained review/proposal
state language such as "Agent outputs remain proposals until review" and
"Accepted profile revision ready for HR review." The promotion wrote those
lines into the workspace `README.md`, so product promotion was not fully
enforcing the boundary between reviewable proposal artifact and accepted
profile state.

## ActiveForm

Tightening accepted-profile promotion validation.

## Acceptance Criteria

- Shared promotion validation rejects review-ready, awaiting-approval, and
  proposal-only language inside accepted README drafts.
- CLI, runtime, API, and Web use the same validation path.
- Tests cover the reproduced real phrase shapes, not only the older
  `pending human review` and `promotion requested` examples.
- A real disposable debug run proves the original dirty artifact is blocked
  and a clean reviewed draft still promotes.

## Notes

## Results

- Expanded shared promotion validation with the reproduced real phrases:
  scaffold copy, "Agent outputs remain proposals until review", and "ready for
  HR review".
- Updated HR native skill and workflow guidance so future native skill outputs
  are less likely to place proposal/review lifecycle state inside the accepted
  README draft.
- Added shared, runtime, CLI, and Web regression coverage for the reproduced
  phrase shapes.
- Rechecked artifact `5b397d08-02dc-481c-9714-9b606f865841`; promotion now
  exits non-zero with `profile promotion rejected`.
