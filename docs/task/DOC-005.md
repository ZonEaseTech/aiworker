## 描述

在拉取最新主线后，Brain 层已经累积 Soul module、scope manifest、artifact
registry、schema pack、admission MVP、brief compiler、Worker/Fleet Brain
surface、decision events 等大量实现。0.8.0 QA-006 同时暴露出几个方向性风险：

1. `intent_decision` / `capability_decision` / `quality_gate` 当前仍是
   heuristic + observe-only，却容易被产品表述误解成 "Brain decision LLM 已接管"。
2. admission pipeline 已有 operator approval / worker.db 状态机，但 LLM-facing
   entry point 不稳定，外部 executor native memory 可能绕过 AIWorker Brain。
3. Soul/schema/artifact/admission 的实现很容易继续膨胀成领域工作流引擎，违背
   AIWorker 轻量自托管 Project Brain + Worker/Fleet aggregation runtime 的定位。

本任务把架构决策写入权威文档：Brain 是 Governance Kernel，不是硬编码领域自动化
引擎；hard logic owns invariants, LLM owns semantics。目标是让后续开发者在新增
Brain 代码前能明确判断：该逻辑应该进 Brain Kernel、Soul guidance、LLM-facing
tool、executor overlay，还是应该根本不做。

## 验收标准

1. `docs/architecture.md` 明确 Brain Governance Kernel 决策，覆盖允许的 hard
   logic、不应进入 Brain 的语义逻辑、现有 Brain 组件的正确解释与禁止升级方向。
2. `docs/architecture.md` 补齐新增 Brain hard logic 前的自检规则，包含 invariant /
   mutation / executor-boundary / truthfulness 四类检查。
3. `docs/architecture.md` 诚实记录 0.8.x 的 decision layer 现实：heuristic /
   observe-only 不能被包装成 LLM-backed Brain decider。
4. `docs/architecture.md` 修正 admission state 仍写成 roadmap / 未落 DB 的过期表述，
   与 PLAN-101 / PLAN-103 的 worker.db MVP 现实一致。
5. `AGENTS.md` 添加短规则，提示未来开发者不要把 Brain Kernel 做成硬编码领域
   workflow engine。
6. PMA task / plan / changelog / index 同步完成；本轮不改 runtime 代码。
