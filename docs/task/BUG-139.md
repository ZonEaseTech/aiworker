# BUG-139 HR profile composer select dropdown visual split

- **status**: completed
- **priority**: P1
- **owner**: codex
- **createdAt**: 2026-05-19
- **claimedAt**: 2026-05-19
- **completedAt**: 2026-05-19
- **plan**: PLAN-374
- **relatesTo**: BUG-138, FEAT-100, PLAN-371

## Background

After `BUG-138`, the HR profile composer uses the shared Radix-backed
`Select`, but visual review shows the opened proposal type menu feels detached
from the select trigger. The menu also appears taller/heavier than the compact
composer action bar.

Live reproduction on the HR People Workbench showed the compact trigger keeps a
38px height when opened, while the Radix content opens above the trigger with
`data-side="top"`. The perceived height jump comes from the floating menu
overlay rather than the trigger layout itself.

## Scope

- Keep the HR composer on the shared `Select` primitive.
- Make top-opening dropdowns visually join the trigger instead of using the
  bottom-opening radius assumption.
- Let compact HR composer menu content receive matching compact/mono styling
  even though Radix renders the content through a portal.
- Update focused component and Worker Web tests.

## Non-goals

- Do not reintroduce a native `<select>`.
- Do not change HR session creation, template ordering, profile review, or
  promotion behavior.
- Do not change Host/Soul protocol or app-owned domain semantics.

## Acceptance

1. Opening the HR composer proposal type menu does not change the trigger
   height.
2. The menu and trigger read as one connected control when the menu opens above
   the action bar.
3. Menu option typography and density match the compact composer select.
4. Existing shared select users keep their current behavior.
5. Focused tests, UI component governance check, browser smoke, and
   code-review-graph review pass before closeout.

## Record

- 2026-05-19 17:32 CST: User reported the opened proposal type component feels
  taller and visually split between options and select. Investigation confirmed
  the trigger height stays 38px, but the portal dropdown opens on `data-side="top"`
  while the shared CSS assumes a bottom-opening menu and portal content misses
  compact HR styling.
- 2026-05-19 17:58 CST: Completed the fix:
  - shared `Select` now supports opt-in `side` and `contentClassName` props;
  - shared CSS gives portal content a radius fallback and side-aware connected
    edges;
  - HR profile composer pins the proposal type menu above the bottom action bar
    and styles the portal content with compact mono options;
  - browser smoke confirmed trigger height stays 38px, content opens with
    `data-side="top"`, option rows are 38px, and the menu/trigger radius now
    connects visually.
