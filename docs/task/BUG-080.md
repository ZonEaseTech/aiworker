# BUG-080 OTP-approved worker reconnects to /enroll-ws as a plain node and is rejected

- **status**: completed
- **priority**: P1
- **owner**: local
- **createdAt**: 2026-05-06
- **discoveredAt**: 2026-05-06 13:31
- **completedAt**: 2026-05-06 13:46
- **plan**: PLAN-137
- **relatesTo**: BUG-079, FEAT-026, PLAN-019, FEAT-055

## Observed Behavior

After the public Caddy `/w*` route was restored for `BUG-079`, the already
approved OTP worker `w_8jbcm249cxn4` did not come back online. Direct gateway
bridge access returned:

```json
{
  "error": {
    "code": "node_offline",
    "message": "worker w_8jbcm249cxn4 当前未连接到 gateway"
  }
}
```

Fleet audit shows repeated reconnect attempts rejected as:

```json
{
  "reason": "wrong_path:expected_enroll_otp",
  "role": "node",
  "agentId": "w_8jbcm249cxn4",
  "path": "/enroll-ws"
}
```

Caddy access logs show repeated `/enroll-ws` WebSocket upgrades after the
reload, but gateway closes them immediately after the plain node connect frame.

## Expected Behavior

An OTP-approved worker should reconnect after a transport drop without
requiring the deployer to hold operator Basic Auth credentials.

## Actual Behavior

The worker client keeps dialing the original `/enroll-ws` URL after approval
and correctly omits the `enroll` block on reconnect. Gateway path-aware auth
currently rejects every non-OTP connect frame on `/enroll-ws` before checking
whether the worker is already registered.

## Risk

P1 availability regression for OTP-enrolled workers behind a public Caddy setup
where `/ws` is protected by operator auth but `/enroll-ws` is intentionally
open for worker deployers.

## Reproducer

1. Start a worker with OTP enrollment through a public gateway URL.
2. Approve the OTP so the worker becomes registered.
3. Drop the WebSocket transport, for example by reloading Caddy.
4. Observe worker reconnect attempts to `/enroll-ws`.
5. Observe gateway audit `gateway.connect.rejected` with
   `wrong_path:expected_enroll_otp`.

## Validation

After fix:

1. OTP submit on `/enroll-ws` still requires `enroll.mode='otp'`.
2. Approved/registered node reconnect on `/enroll-ws` is accepted only when
   the presented worker token matches the encrypted token stored in
   `registered_workers`.
3. Unknown or wrong-token node reconnect on `/enroll-ws` is rejected.
4. `w_8jbcm249cxn4` can reconnect and the direct gateway bridge returns worker
   info again.
