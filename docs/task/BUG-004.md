## Description

After a `reloadRuntime` (triggered by `PUT /api/worker/config` or the
gateway `config.put` once BUG-003 lands), follow-up `aim chat` requests
hang and time out. Repro: T3 in PLAN-017 context — chat is `accepted: true`
by the dispatcher, but no `agent.thinking` / `agent.done` event ever
reaches the operator.

### Root cause analysis

- `GatewaySubscriber.start()`
  (`packages/core/src/worker/gateway-client/subscriber.ts:37-41`) calls
  `bus.on(...)` exactly once per WS connection, registering against
  whichever `WorkerEventBus` is current at handshake time. The closure
  captures **that bus instance**.
- `reloadRuntime` (`apps/api/src/modes/worker.ts:86-105`) builds a fresh
  runtime with a brand new `WorkerEventBus`, then disposes the previous
  runtime. The old bus stops receiving events; the subscriber's listener
  is still attached to it.
- `GatewayDispatcher` (`packages/core/src/worker/gateway-client/dispatcher.ts:186`)
  calls `this.deps.getRuntime().orchestrator.ingest(...)` — this **does**
  see the fresh runtime (hot path is correct on the inbound side). The
  orchestrator runs and emits events on the **new** bus; nothing is
  subscribed there, so nothing is forwarded to gateway → operator.

CLAUDE.md explicitly states the invariant:
> Hot-reload 写法 ... gateway 的 node subscriber 也是 `getBus()` 懒取，
> reload 后自动追新 bus。

The lazy `getBus` getter exists, but `start()` is only invoked on
`onConnected`. The fix is to re-call `subscriber.start()` (which is
idempotent — it stops first) whenever the runtime is reloaded.

### Acceptance criteria

- Sequence in T3 of PLAN-017 succeeds end-to-end:
  1. PUT `/api/worker/config` (or `aim config set` post-BUG-003) with
     correct `If-Match` returns 200.
  2. Subsequent `aim chat <workerId> '...'` returns `agent.thinking`
     stream and `done(stop)` within timeout.
- No leaked listeners on the old bus (`previous.dispose()` already
  unsubscribes per-bus listeners; subscriber.stop must remove its own
  listener regardless).
- Works for both reload triggers: HTTP `PUT /api/worker/config` and
  gateway `config.put`.

## Notes

Implementation sketch (subject to PLAN-017 review):
- `GatewayNode` interface gains a `notifyRuntimeReloaded()` (or similar)
  method that calls `subscriber.start()` when `connected === true` and
  is a no-op otherwise (next `onConnected` already covers the offline
  case).
- `bootstrapWorkerApp` accepts an `onRuntimeReloaded?: () => void` option
  (or returns the reload hook so `serve.ts` can wrap it). The CLI uses a
  mutable ref to forward to the not-yet-constructed `gatewayNode`.
- A regression test in `packages/core/src/worker/gateway-client/`
  exercises subscriber refresh after runtime swap with stub bus.
