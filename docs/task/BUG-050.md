## Observed Behavior

A real Codex-backed `aiworker run` successfully created and read back a marker
file in `/Users/ben/projects/aiben/tmp`, and the assistant reported it used
shell `printf` and `cat`.

The AIWorker event stream for that run emitted `orchestrator.text`,
`orchestrator.quality_gate`, and `orchestrator.finished`, but did not emit
`orchestrator.tool_call` for the actual shell/file activity.

## Expected Behavior

When current Codex app-server emits live tool activity, AIWorker should
normalize the relevant notifications into shared `AgentEvent.tool_use` /
`tool_result` events so the orchestrator can emit `orchestrator.tool_call`
and downstream UIs, logs, approvals, and QA tooling can observe executor
hands.

## Reproduction

```bash
cd /Users/ben/projects/aiben
bun /Users/ben/projects/aiworker/apps/cli/dist/aiworker-bun.js init --soul developer
bun /Users/ben/projects/aiworker/apps/cli/dist/aiworker-bun.js executor select --engine codex --apply
bun /Users/ben/projects/aiworker/apps/cli/dist/aiworker-bun.js run \
  --chat-id codex-real-developer-tool-hand \
  --timeout-ms 180000 \
  --message 'create and read back a marker file under tmp/, then return JSON'
```

Evidence:
`/Users/ben/projects/aiben/tmp/codex-tool-hand-probe-20260503-223228/developer/run-tool.log`.

## Acceptance Criteria

1. Capture the raw current Codex app-server notification shape for shell/file
   activity without logging secrets or system prompt content.
2. Extend Codex notification normalization at the narrowest compatible layer.
3. Preserve existing legacy `codex/event/tool_call` and `codex/event/tool_result`
   compatibility.
4. Add focused fixture coverage for current-protocol tool activity.
5. A local Codex-backed worker hand probe emits `orchestrator.tool_call` while
   still reaching `orchestrator.finished`.
