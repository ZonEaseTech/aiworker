## Observed Behavior

`@zonease/aiworker-cli@0.6.0` published 版本 + claude-code 2.1.126 executor，端到端调试发现：
worker 在 `aiworker run` 投递任务时，**SOUL.md / AGENT.md / USER.md / MEMORY.md / ROLLUP.md /
capability-packs.json / policy.json / toolsets.json / scope manifest / skills / memories**
全部没有进入 claude-code 子进程的 system prompt 或 user prompt。

复现路径：
1. 任意目录 `aiworker init --soul <preset>`（developer / hr-recruiting / finance-ops 都试过）
2. `aiworker executor select --engine claude-code --apply`
3. `aiworker run --message "..."`
4. 用 fake-claude shim（PATH 前置一个 wrapper 把 argv / stdin / env dump 到磁盘）抓真实 claude 子进程的输入

实测样本（两次独立 run）：

```text
=== ARGV ===  -p --verbose --output-format=stream-json --input-format=stream-json
              --include-partial-messages --replay-user-messages
              --dangerously-skip-permissions --model sonnet
              （第二轮起多 --resume <sessionId>）
=== STDIN ===
{"type":"user","message":{"role":"user","content":[{"type":"text","text":
  "Recent messages:\n- user: ...\n- assistant: ...\n
   New incoming message: <prompt>"}]}}
```

- 没有任何 system prompt 段
- chat history 被拼成单条 user text
- claude-code session jsonl（`~/.claude/projects/<dir>/<sessId>.jsonl`）里的 attachment 全是
  user-level claude-code 自身的 hook / mcp / skill_listing / deferred_tools，没有 .aiworker/
  任何文件

业务证据（决定性对照）：

| 配置 | LLM 自我介绍首句 |
|------|------------------|
| developer Soul + 全套 brain 文件 | "我是一个专注软件工程任务的 AI 助手，风格简洁直接、以代码和结果为导向…" |
| general-assistant Soul + SOUL/AGENT/MEMORY 全 mv 走 | "我是一个专注于软件工程任务的 AI 助手，风格简洁直接、以代码和事实说话…" |
| hr-recruiting Soul + 全套 brain 文件 | "我是一名务实的软件工程协作者，用简洁直接的中文沟通，专注于写出正确、安全、够用的代码…" |
| finance-ops Soul + 全套 brain 文件 | "我是一个专注于软件工程任务的 AI 助手，以简洁直接的方式与你协作写代码、排查问题…" |

四个不同 Soul / 一个删 brain 的回答几乎一致：都自称"软件工程助手"。这是 claude-code CLI 自带的
default system prompt，与 AIWorker 的 SOUL 调教完全无关。

`aiworker brain memories` 在 brain runtime 端能列出 admission MVP 落盘的 3 条 memory，但 LLM
回答 "你的长期记忆里关于 admission MVP 验证有什么记录" 时说"记忆文件不存在"；只有把
`memories/qa-fixture.md` 写进 prompt，LLM 才会自己 filesystem-read 探索（且第一次去
`~/.claude/projects/<dir>/memory/` 找空气，第二次才找到 .aiworker/memories/）。

## Expected Behavior

`aiworker run` 投递给 claude-code 子进程的输入应当包含：

- AGENT.md / SOUL.md / USER.md / MEMORY.md / ROLLUP.md 拼接出的 system prompt（已由
  ContextManager 拼好，见 `packages/core/src/worker/orchestrator/context-manager.ts` L42-75 +
  RunContextComposer L97-114）
- brain memories 索引（必出现）+ 按 task 相关性 hot-load 1~3 个 memory body
- 至少把 Soul identity（id / label / 沟通风格 / 边界）注入到 system prompt 顶端

LLM 自我介绍应当反映 SOUL.md 实际配置（developer Soul 自称 "developer worker 直接、证据优先" /
hr-recruiting 自称 "HR Soul，关注公平和可追溯" / finance-ops 自称 "Finance Ops，数字精确"）。

`aiworker brain memories` 列出的条目 LLM 必须能直接 cite，不需要 user 在 prompt 里手写路径。

## Source Code Root Cause

| 层 | 文件 | 行号 | 问题 |
|----|------|------|------|
| ContextManager | `packages/core/src/worker/orchestrator/context-manager.ts` | L42-75 | 正确拼 systemPrompt（无问题） |
| RunContextComposer | 同文件 | L97-114 | 正确把 system 段放进 messages[0]（无问题） |
| orchestrator | `packages/core/src/worker/orchestrator/service.ts` | L275-276 / L1027-1032 | 正确把含 system 的 ChatMessage[] 传给 executor.messages（无问题） |
| **claude-code adapter** | `packages/core/src/worker/executor/engines/claude-code/executor.ts` | `buildBaseArgs` L243-260 | **没拼 `--system-prompt` / `--append-system-prompt`** |
| **claude-code protocol** | `packages/core/src/worker/executor/engines/claude-code/protocol.ts` | `sendUserMessage` L98-107 | **envelope 只塞 user，丢弃整个 messages 数组中除最后 user 外的所有内容** |
| BrainBriefCompiler | `packages/core/src/worker/brain/brief/compiler.ts` | 头部注释 | 明示 "preview-only"，未接入 orchestrator system prompt 路径 |

## Scope of Fix（建议）

### P0（必修）

1. claude-code adapter 在 `spawnClaudeProcess` / `buildBaseArgs` 加：
   - 把 `AgentRunInput.messages` 中 role=system 的内容 join 后通过 `--append-system-prompt
     "<brain ctx>"` 注入 claude-code 子进程
   - 或在 stdin 投递前先发一条 `{"type":"system","message":{"role":"system","content":[
     {"type":"text","text":"..."}]}}` envelope（取决于 claude-code 2.x 协议支持）
2. 第二轮起的 `--resume <sessId>` 仍要 re-inject system —— 因为 SOUL.md 可能在两轮间被
   `aiworker config set` / brain hot reload 改变；不能假设 claude-code session 持有的 system
   还合法。可以选择：
   - 显式禁用 `--resume`，让 AIWorker 独立持有 session 历史（每轮 stateless 投递）
   - 或每轮 re-send `--append-system-prompt` 覆盖
3. brain memories 注入策略：MEMORY.md 索引（条目数有限，全量注入）+ 按 task 相关性 hot-load
   1~3 个 memory body。LLM 应当被显式告知 `[memory:<topic>]` cite 语法，不让它自己
   filesystem-read 探索。

### P1（重要）

4. PLAN-102 BrainBriefCompiler 接入 orchestrator —— 替换 ContextManager 当前的全量拼接，
   按 task / token-budget / artifact ref 给 LLM 真正的 task-specific brain。当前 brief
   compiler 只在 CLI 子命令 preview，浪费功能。
5. capability_decision 的 selectedBuiltins / selectedSkills / selectedMcpTools 真的转换成
   claude-code `--allowedTools` / project-level MCP overlay，而不是停留在 observe_only 元数据。

### P2（落地完善）

6. 把 SOUL/AGENT/MEMORY 注入的实际内容回写到 worker.db conversations / messages 表（system
   role），方便 audit / replay / Worker Admin UI 显示真实 brain 注入快照。
7. 同步检查 codex / acp / cursor / mcp 等其它 executor adapter 是否同样断（架构上推断同样有
   问题，因为 BUG-056 暴露的是 adapter 层 system prompt 注入缺失）。
