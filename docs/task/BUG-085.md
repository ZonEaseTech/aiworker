# BUG-085 Pre-compaction memory flush bypasses Brain admission

- **priority**: P1
- **owner**: local

## 描述

`orchestrator.compaction.memoryFlush.enabled=true` 时，
`runPreCompactionMemoryFlush` 会通过 `BrainProvider.writeMemory()` 直接写入
canonical Project Brain memory。

这条路径来自 FEAT-037/PLAN-028 的 session compaction 设计，但现在已经和
Brain Governance Kernel 决策冲突：durable generated Brain mutation 必须回到
AIWorker admission，而不是由 suppressed executor output 直接落盘。

## ActiveForm

将 pre-compaction memory flush 从直接写 memory 改为创建 pending admission
proposal

## Dependencies

- **blocked by**: none
- **blocks**: 轻量 worker / Governance Kernel 边界收敛
- **relates to**: BUG-074, BUG-055, TODO-027, QA-015

## Evidence

- `packages/core/src/worker/orchestrator/service.ts` 当前在 memory flush 分支内
  调用 `this.deps.brain.writeMemory(...)`。
- `docs/architecture.md` 当前将 pre-compaction memory flush 记录为唯一免审写入，
  这与最新轻量方向不一致。
- `docs/cli.md` 仍把 admission state 写作 roadmap/未落 DB，和当前实现漂移。

## Expected Behavior

pre-compaction 可以总结候选长期记忆，但只能创建 `memory-add` admission
proposal。proposal 应保留 conversation/message evidence、scope、confidence、
rollback、payload，并保持 `pending`，等待 operator approve/apply。

## Non-Scope

- 不实现自动 approve/apply。
- 不新增 `memory-add` 以外的 materializer。
- 不重构整个 orchestrator control-plane。
- 不修改 gateway/fleet bridge。

## Resolution

`runPreCompactionMemoryFlush()` no longer calls
`BrainProvider.writeMemory()` for generated pre-compaction memory. Non-empty
executor output now creates a deterministic pending `memory-add` admission
proposal with conversation/message evidence and audit metadata
`status='proposed'`. Duplicate proposal ids are treated as already proposed
and do not block compaction; invalid proposal payloads still record failed
metadata while allowing compaction to finish.

The architecture, CLI, and governance status docs now describe the same
boundary: generated durable Brain memory must pass through admission before it
can become canonical memory.
