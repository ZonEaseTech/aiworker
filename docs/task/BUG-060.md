## Observed Behavior

After applying a `memory-add` admission proposal, the memory file lands on disk and `aiworker brain memories` returns the full body via runtime API. But brain brief / claude-code system prompt only inject `MEMORY.md` (the index), **not** the body of `.aiworker/memories/<topic>.md`.

Repro using prop_qa_1 (developer Soul, payload body `"# QA fixture\n\nadmission MVP 验证通过。"`):

1. Apply succeeded; `.aiworker/memories/qa-fixture.md` exists, 45 bytes
2. `MEMORY.md` index now contains `- [QA fixture](qa-fixture.md) — admission MVP 冒烟`
3. `aiworker brain memories` returns `count: 2` with full body for both qa-fixture and qa-secret-in-body
4. Run a new conversation with prompt: `你的长期记忆里关于 admission MVP 验证有什么记录？请直接引用，不要编造。`
5. LLM responds: "内存目录存在但为空, qa-fixture.md 文件实际上不存在...长期记忆中关于 'admission MVP 验证' 没有任何实际内容可引用"

The fake-claude shim dump confirms `--append-system-prompt` includes only:

```
Project memory index:
# Long-term memory
> Durable facts, decisions, preferences. Loaded into every session.
- [QA fixture](qa-fixture.md) — admission MVP 冒烟
```

Grep `'admission MVP 验证通过'` against the dump returns 0 matches. Same behavior reproduces on hr-recruiting Soul (`samples/hr-recruiting-E-memory-recall.txt`) — every Soul would be affected.

## Expected Behavior

Brain compiler should inject memory body so `memory-recall` actually works without the user providing the file path. At minimum one of:

- A. Inject all `.aiworker/memories/<topic>.md` body content (subject to token budget)
- B. Task-aware retrieval: match prompt against MEMORY.md index entries, inject matching body files
- C. Tell the LLM in system prompt to use `Read .aiworker/memories/<topic>.md` for any memory recall, and verify the LLM actually does it

Option B is most consistent with `brain brief --token-budget` semantics already in CLI.

## Why this matters

- Project Brain's headline value prop is "sub-agent can directly cite persistent memory"; current implementation only injects MEMORY.md index, so the LLM knows file names but not contents
- LLM gives a confidently-wrong "no such record" answer, eroding product trust
- For each memory-recall use case the user must include the explicit path (`memories/qa-fixture.md`) in the prompt to get the LLM to Read the file — completely defeats automatic injection

## Source Code Hint

Brain brief compiler (likely `packages/core/src/worker/brain/brief/*` in 0.7.0). The brief output in `aiworker brain brief --task ...` already shows a single `memory` section with id `memory` and source `memory-doc`, body = MEMORY.md raw — the body files are never iterated.
