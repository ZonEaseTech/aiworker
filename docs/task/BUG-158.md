## Completion Notes

- Core sessions now freeze `engineId`, `engineCommand` and `executionMode` into session metadata at creation time. Follow-up turns resolve from the frozen session engine first, then from legacy latest invocation metadata/inference, and only use the current request for brand-new sessions.
- CLI `engine select` and `session start --engine <id>` now affect only new sessions. `turn send` can pass the current selected engine request, but runtime keeps the existing session engine immutable.
- API session creation enriches session metadata with current local execution settings before runtime creates the session, so Web-created sessions freeze the same engine the first turn uses.
- Mounted universal workbench session detail refreshes and pollers are guarded by a `routePrefix + workerId + workspaceId + sessionId` context key so stale locator responses cannot overwrite the current mounted context.
- Mounted theme coverage verifies Host dark appearance reaches mounted surface URL, micro-app data, universal workbench HTML chrome, and the mounted child document after Host appearance changes without a reload.
