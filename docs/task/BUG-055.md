# BUG-055 Admission `apply --commit` writes plaintext secrets in payload.body to brain memory

- **status**: completed
- **priority**: P0
- **owner**: aiworker-maintainer
- **createdAt**: 2026-05-04 22:10
- **discoveredAt**: 2026-05-04 22:10
- **completedAt**: 2026-05-05 01:30
- **plan**: PLAN-106
- **relatesTo**: PLAN-101, FEAT-054

## Observed Behavior

`brain admission apply --commit` 把 `payload.body` 原样写到 filesystem，没有任何 secret-like
模式扫描或拦截。

复现：

1. 直接向 worker.db `brain_admission_proposals` 插入一条 memory-add proposal，
   `payload.body` 含明文 `apiKey=sk-LIVE-shouldnotpersist` `bearer=eyJabc`
2. `aiworker brain admission approve <id> --decided-by qa-bot`
3. `aiworker brain admission apply <id> --decided-by qa-bot --commit`
4. `cat .aiworker/memories/<topic>.md` → 文件内容包含明文 secret

```text
# leak test

apiKey=sk-LIVE-shouldnotpersist
bearer=eyJabc
```

默认 redact 仅对 `payload` 顶层字段名（`apiKey` / `token` / `password` / `secret` / `bearer` /
`auth` / `credential`）生效；`payload.body` 内字符串既不被 redact，也不阻止 apply。
PLAN-101 的 `redactBrainAdmissionProposal` zod helper 是 field-name based，不扫 body 内容。

## Expected Behavior

任一选项：

1. **强校验**：materializer 在 dry-run / commit 前对 `payload.body` 做 secret-like pattern
   扫描（`sk-[A-Za-z0-9_-]{20,}` / `eyJ[A-Za-z0-9_=.-]{20,}` / 高熵字符串等），命中则拒绝并
   提示 operator 用 `--allow-secret-body` 显式覆盖
2. **强替换**：默认对 body 做 secret pattern → `[REDACTED]` 替换，dry-run diff 必须明示
   扫描 / 替换结果
3. dry-run preview 输出必须包含扫描结论 `secret_pattern_hits: 0` 或 `secret_pattern_hits:
   ["sk-..."]`，让 operator 知情

## Why this matters

- AIWorker 的核心承诺是 "Project Brain 不长存 secret"（CLAUDE.md "secret 放 .env 或 vault，
  永不硬编码"）
- admission MVP 是 brain 唯一的"durable change gate"；如果它不挡 body 内 secret，Soul
  生成 proposal 时一旦把 secret 拼进 body，就形成长期 brain 内泄露面，后续 brain projection /
  brief / artifact summary / fleet brainSummary（虽然只 aggregate 不含 payload）相关链路都会
  不同程度复制
- BUG-056 修通后，brain memories 会被注入 LLM system prompt → secret 暴露面进一步扩大

## Scope of Fix（建议）

1. 在 `packages/core/src/worker/brain/admission/service.ts` 的 materializer 加一道
   `scanBodyForSecrets(body: string): SecretHit[]` 函数；MVP `memory-add` 路径上 dry-run /
   commit 都执行
2. 默认拒绝命中；`--allow-secret-body` flag（CLI + REST `?allowSecretBody=true`）显式覆盖
   且写决策 row（`reason='operator-overrode-secret-scan'`）
3. dry-run JSON 输出 `outcome.secretScan: { hits: [...], action: 'block'|'redact'|'allow' }`
4. shared `scanBodyForSecrets` 复用到 PLAN-102 brain brief compiler 与 fleet brainSummary
   pointer，保证多入口防护一致
