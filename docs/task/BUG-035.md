# BUG-035 `aiworker serve` exits after starting worker server

- **status**: completed
- **priority**: P0
- **owner**: Codex
- **createdAt**: 2026-04-29 08:45
- **discoveredAt**: 2026-04-29 08:43
- **releaseTarget**: `@zonease/aiworker-cli@0.4.5`

## Description

During the `0.4.5` test-fleet validation, a local worker configured with
`executor=codex/default` was started through the documented CLI path:

```bash
aiworker serve --port <port> --host 127.0.0.1 --no-serve-web
```

The worker booted, built runtime, started the HTTP server, and began dialing
the fleet OTP enrollment endpoint. The CLI process then exited before the
gateway could return an OTP, so the worker never stayed online long enough to
enroll.

Sanitized observed log shape:

```text
[worker <worker-id>] worker.db ready at <tmp>/worker.db
[worker <worker-id>] runtime built - brains=0 executor=codex/default channels=0
[aiw serve] worker <worker-id> listening on 127.0.0.1:<port> (config v2)
[aiw serve] OTP enrolling to <gateway-url>/enroll-ws; awaiting operator approval
[gateway-client <worker-id>] connecting to <gateway-url>/enroll-ws
[aiw serve] gateway-client dialing <gateway-url>/enroll-ws
```

No `OTP:` line was emitted before process exit.

## Expected Behavior

`aiworker serve` should remain a foreground long-running process until it
receives SIGTERM/SIGINT, matching `aiworker gateway start` foreground behavior.
The worker should keep its HTTP server and gateway-client alive long enough for
OTP approval and fleet chat traffic.

## Root-Cause Candidate

`apps/cli/src/commands/serve.ts::runServe()` starts `Bun.serve()` and registers
signal handlers, but then returns. The CLI entrypoint exits with the returned
status after `runCli()` completes. `runGatewayStartForeground()` avoids this by
awaiting an unresolved promise after installing signal handlers; `runServe()`
does not currently do the same.

## Reproduction Steps

1. Create an isolated `AIWORKER_HOME` with a preseeded `.env`.
2. Bootstrap local worker config and set `executor` to `{ "engine": "codex",
   "variant": "default" }`.
3. Export `AIWORKER_GATEWAY_URL=<gateway-url>` and
   `AIWORKER_ENROLL_MODE=otp`.
4. Run `aiworker serve --port <port> --host 127.0.0.1 --no-serve-web`.
5. Observe the process exits after startup logs and before OTP enrollment
   completes.

## Acceptance Criteria

1. `aiworker serve` blocks in foreground until SIGTERM/SIGINT.
2. SIGTERM/SIGINT still stop both the HTTP server and gateway-client cleanly.
3. Add a regression test that proves `runServe()` does not resolve immediately
   after successful startup.
4. Re-run the 0.4.5 fleet validation path: local Codex worker OTP enrollment,
   explicit conversation continuity, default accepted-id continuity, reset
   rotation, and `sessions` metadata checks.
