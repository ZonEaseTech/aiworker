# BUG-020 gateway WebSocket maxPayloadLength + idleTimeout + connect 限频

- **status**: implemented
- **priority**: P1
- **owner**: BenDaye
- **createdAt**: 2026-04-27
- **discovered**: 代码审查（root issue: `nnid9urk`）发现 `Bun.serve` 的 websocket 防御层缺失 + 无 IP 级 brute-force 阻断。

## 现象

`packages/gateway/src/server.ts:42-92` `Bun.serve` 没有显式设置：
- `maxPayloadLength`（每消息大小上限，默认 16 MB）
- `idleTimeout`（空闲连接回收）

同时 `authorizeConnection` 失败后立即 `ws.close(4401, ...)`，但没基于 IP 累计计数。

## 风险

- **OOM**：攻击者发送 GB 级单消息让 `parseFrame` 的 `JSON.parse` 撑爆内存
- **brute-force**：盲扫 `joinToken` / `internalSharedSecret`。`timingSafeEqual` 防的是侧信道，扛不住高并发穷举（32 字节随机 token 无窗口约束时仍是问题）
- **死连接累计**：连上不发数据的连接吃掉 ws fd / 内存

## 修复

### 1. `Bun.serve` websocket 配置（`packages/gateway/src/server.ts`）

```ts
websocket: {
  maxPayloadLength: 1024 * 1024, // 1 MiB 单消息上限
  idleTimeout: 120,              // 120s 空闲超时
  open / message / close ...
}
```

`maxPayloadLength=1 MiB` 给的是控制面消息的现实上限：

- `chat.send` 的 `content` 没有 schema 上限，operator 可能贴长段（log / 文件内容），64 KB 太紧；
- `workers.list` / `approval.list` 等列表型 result 在 maxWorkers 几百量级下仍远低于 1 MB；
- 1 MB 远低于默认 16 MB，足以挡住"GB 帧 OOM"。

`idleTimeout=120s` 与 Bun 默认值一致；显式声明便于 ops 审阅与未来回归测试。

### 2. ConnectRateLimiter（`packages/gateway/src/registry/connect-rate-limiter.ts`）

`Map<remoteAddress, { fails, firstFailAt, blockUntil }>`：

- 默认参数：60s 窗口内累计 ≥ 5 次握手失败 → block 10 分钟
- `recordFailure` 返回 `blockedNow`：调用方据此写 `gateway.connect.brute_force_blocked` audit
- `recordSuccess` 清计数（合法 token 轮换 + 暂时误用不会留下永久痕迹）
- `prune()` 回收过期条目（窗口结束 + block 已结束）

### 3. 接入点

- `fetch` handler（`packages/gateway/src/server.ts`）：upgrade 前 `connectRateLimiter.isBlocked(remoteAddress)`，blocked → 直接 `429 + Retry-After`，不浪费 ws 升级。`loopback` 短路（127.0.0.0/8 / ::1 视为信任域，避免 aim CLI 本机调用被误伤）。
- `handleMessage` connect 帧：
  - `authResult.ok=false` 且非 `wrong_path:*`（协议错配 ≠ 穷举尝试）→ `recordFailure`；触发 block 时写 `gateway.connect.brute_force_blocked` audit。
  - `authResult.ok=true` → `recordSuccess` 清计数。
- `GatewayContext.connectRateLimiter`：在 `index.ts::createGatewayContext` 注入；测试 ctx 可缺省，server.ts 路径条件性使用。

## 不在范围

- **bad-frame**（`parseFrame` 失败）：版本错配信号，与穷举无关，不计入 brute-force（避免 worker 升级期误伤）。
- **多副本部署**：当前 ConnectRateLimiter 是进程内存。要在多 gateway 副本间共享计数需要外部协调（Redis / Caddy 反代叠 fail2ban），后续如果起多副本再讨论；自托管单进程足够。
- **perMessageDeflate**：Bun 默认未开启压缩，不存在 zip-bomb 风险，不需要显式关闭。

## 验证

- 单测：`packages/gateway/test/connect-rate-limiter.test.ts`（9 case）覆盖阈值 / 窗口外 / block 解除 / 多 IP / undefined IP / prune
- 集成：`packages/gateway/test/brute-force.test.ts`（5 case）覆盖 connect 失败累计 → block + audit 写入、握手成功清计数、loopback 不限频、wrong_path 不计入、多 IP 互不干扰
- 全量 `bun test` 通过（packages/gateway）
