# BUG-133 Official Soul App defaultTemplates contain duplicates

- **status**: completed
- **priority**: P1
- **owner**: codex

- **claimedAt**: 2026-05-17
- **completedAt**: 2026-05-17

## Description

Fresh `soul list` output for bootstrapped official Soul Apps projected
duplicate `defaultTemplates` when multiple workspace types declared the same
default capability. HR listed `aiworker-hr.candidate-screen` twice, and QA
listed `aiworker-qa.regression-matrix` twice. This makes CLI/Web worker
defaults look unstable and hides whether the app's default capability surface
is complete.

## ActiveForm

Deduplicating official Soul App default template projection.

## Acceptance Criteria

- `projectSoulAppSoul` preserves workspace declaration order while removing
  duplicate namespaced default capability ids.
- Tests cover HR and QA official manifest projection.
- A real disposable CLI debug run shows unique default templates after
  bootstrap.

## Notes

- 2026-05-17 17:38: Reproduced with `soul list` in
  `/private/tmp/aiworker-hr-prod-20260517173556`.

## Results

- Added `projectSoulAppDefaultTemplates` and reused it for Host projection and
  standalone Soul App runtime worker metadata.
- HR now projects defaults in order:
  `aiworker-hr.person-profile`, `aiworker-hr.profile-update-proposal`,
  `aiworker-hr.candidate-screen`.
- QA now projects defaults in order:
  `aiworker-qa.regression-matrix`, `aiworker-qa.release-gate`.
- Covered the official HR/QA projection with registry and runtime tests, then
  verified the new values through a disposable `soul list` run.
