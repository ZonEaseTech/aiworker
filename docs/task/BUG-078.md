# BUG-078 Worker OpenAPI advertises stale orchestrator chat route and omits working task/conversation routes

- **status**: completed
- **priority**: P3
- **owner**: local
- **createdAt**: 2026-05-05
- **discoveredAt**: 2026-05-05 20:44
- **completedAt**: 2026-05-06
- **plan**: PLAN-123
- **relatesTo**: QA-007, PLAN-122

## Observed Behavior

Across all ten local worker scopes in the 0.9.0 matrix, `/openapi.json`
advertised `/api/worker/orchestrator/chat`, but the working endpoints used by
Worker Admin/runtime routes are:

- `POST /api/worker/orchestrator/tasks`
- `GET /api/worker/orchestrator/tasks`
- `GET /api/worker/orchestrator/conversations`
- `POST /api/worker/orchestrator/conversations/:id/messages`

The REST/SSE probe succeeded by using the task/conversation routes, while the
OpenAPI document omitted them in 10/10 scopes.

Evidence:

- `/home/ben/projects/debug-aiworker-cx/release-0.9.0-governance/reports/summary.json`
- `raw/*/rest.openapi.http`
- `raw/*/rest.task01.http`
- `raw/*/rest.task02.http`
- `raw/*/rest.sse.txt`

## Expected Behavior

The worker OpenAPI document should be the source of truth for callable worker
REST routes. It should document the routes that actually accept orchestrator
tasks and conversation continuations, and should not advertise stale or
unmounted paths.

## Actual Behavior

The OpenAPI route list is stale/incomplete for orchestrator operations. This
creates operator and client confusion when validating local worker REST without
source-code knowledge.

## Risk

P3 UX / API documentation risk. REST itself works, bearer auth works, and SSE
works, but the documented contract is misleading.

## Reproducer

```sh
RUN=/home/ben/projects/debug-aiworker-cx/release-0.9.0-governance
AIW=$RUN/bin/node_modules/.bin/aiworker
SCOPE=$RUN/matrix/general-assistant-codex
PORT=9440

cd "$SCOPE"

  > "$RUN/tmp/bug-078-serve.log" 2>&1 &
PID=$!
sleep 2
curl -sS -H "Authorization: Bearer $TOKEN" "http://127.0.0.1:$PORT/openapi.json"
kill -TERM "$PID"
```

Compare with the successful task calls in:

```text
$RUN/raw/general-assistant-codex/rest.task01.http
$RUN/raw/general-assistant-codex/rest.task02.http
```

## Validation

After fix:

1. `/openapi.json` includes the working task and conversation routes.
2. Any stale `/api/worker/orchestrator/chat` entry is either implemented or
   removed.
3. Worker REST smoke can be generated from the OpenAPI document without
   source-code route knowledge.

## Completion Evidence

- Worker OpenAPI registration now includes task and conversation routes and
