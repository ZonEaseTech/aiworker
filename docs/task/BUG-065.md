# BUG-065 `/openapi.json` returns empty `paths`, all worker REST endpoints missing from API doc

- **status**: pending
- **priority**: P2
- **owner**: unassigned
- **createdAt**: 2026-05-04 22:10
- **discoveredAt**: 2026-05-04 22:08
- **plan**: TBD
- **relatesTo**: AGENTS.md "API 文档以代码为准" rule

## Observed Behavior

Start `aiworker serve` against a project, then fetch the OpenAPI doc:

```bash
curl -s http://127.0.0.1:19311/openapi.json
```

Returns:

```json
{
  "openapi": "3.1.0",
  "info": {
    "title": "AIWorker Worker API",
    "version": "0.7.0",
    "description": "Per-worker surface: channels, orchestrator, memory, skills, execution, evolution. Worker id: w_0rmz3bz0fwy7"
  },
  "components": {"schemas": {}, "parameters": {}},
  "paths": {}
}
```

`paths` is empty, but the server is actually serving ≥10 endpoints (all return 200 with valid bearer): `/health`, `/api/worker/info`, `/api/worker/brain/summary`, `/api/worker/brain/admission`, `/api/worker/brain/admission/<id>`, `/api/worker/sessions`, `/api/worker/schedule`, `/api/worker/approvals`, `/admin/`, `/docs`.

The `/docs` Scalar UI loads but renders 0 endpoints (it consumes `/openapi.json`).

## Why this matters

- AGENTS.md mandates: "API 文档以代码为准：OpenAPIHono `app.doc('/openapi.json')` + `/docs`. 新增或修改 API 时同步 zod schema、OpenAPI metadata、typed client/proto 和相关测试." — 0.7.0 violates this
- Any third-party client generating types from `/openapi.json` produces 0 endpoints; the typed worker client is unusable
- Internal tooling that depends on OpenAPI for SDK regeneration breaks silently

## Root Cause Hint

OpenAPIHono only adds endpoints to `app.doc('/openapi.json')` output if registered via `app.openapi(routeDefinition, handler)`. If 0.7.0 transitions the worker API code to plain `app.get('/path', handler)` for any reason (maybe to drop schema validation cost?), the routes work but never appear in the doc.

A second possibility: the OpenAPI metadata is registered under a different `Hono` instance than the one mounted at `/openapi.json`.

## Reproducer

```bash
DEBUG_ROOT=/home/ben/projects/debug-aiworker/qa-2026-05-04-v0.7.0
cd $DEBUG_ROOT/proj-developer
TOK=$(aiworker token rotate 2>&1 | grep -oE 'wtk_[A-Za-z0-9_-]+' | head -1)
setsid aiworker serve --port 19311 --no-open > /tmp/serve.log 2>&1 &
sleep 3

# 1. doc is empty
curl -s http://127.0.0.1:19311/openapi.json | python3 -c '
import json, sys
o = json.load(sys.stdin)
print("paths:", len(o.get("paths", {})))
print("schemas:", len(o.get("components", {}).get("schemas", {})))
'
# Expected: paths >= 10, schemas >= 5
# Actual:   paths = 0, schemas = 0

# 2. but real endpoints work
curl -s -H "Authorization: Bearer $TOK" http://127.0.0.1:19311/api/worker/brain/summary | head -c 100
# returns valid JSON ✓
```

## Validation

After fix, `curl /openapi.json | jq '.paths | keys | length'` ≥ 10 and `/docs` Scalar UI shows the full endpoint list with parameter / response schemas.
