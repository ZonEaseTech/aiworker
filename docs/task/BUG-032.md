# BUG-032 Stabilize workspace-wide test gate under concurrent package execution

## Description

The workspace-wide test gate is flaky when packages run concurrently, even
though the same focused tests pass in isolated or sequential package runs.

Observed behavior from `QA-001` reliability validation:

1. `bun run --filter '*' test` failed twice under concurrent workspace
   execution.
2. Run 1 failed with timeouts in the core `CronService` tick hook and the web
   `boundary-lint > rejects fleet imports from the worker view` case.
3. Run 2 failed with a CLI init integration timeout.
4. Isolated reruns passed:
   - core package: 479/479 pass
   - cli package: 42/42 pass
   - gateway package: 128/128 pass
   - storage-sqlite package: 15/15 pass
   - focused repeat set: 99/99 pass twice
   - web boundary-lint and core cron single-file reruns passed

## Acceptance Criteria

1. `bun run --filter '*' test` passes repeatedly under normal CI-like
   concurrency.
2. Tests that need exclusive ports, temp directories, DB files, timers, or
   global process env are isolated enough to run beside other package tests.
3. Add a short stress/repeat command or CI note that can reproduce the fixed
   workspace-wide gate without relying on unbounded loops.
4. If concurrency is intentionally unsupported for a subset, encode that in the
   package scripts rather than leaving flakes in the root gate.
