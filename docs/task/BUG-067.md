# BUG-067 `conversation.classifier` silently falls back to heuristic on `non-json-classifier-output` without preserving the raw LLM output

- **status**: pending
- **priority**: P1
- **owner**:
- **createdAt**: 2026-05-05 14:10
- **discoveredAt**: 2026-05-05 13:57
- **relatesTo**: BUG-066

## DOC-006 framing

This remains the diagnostic half of the post-DOC-005 truthfulness layer. The
goal is not to make classifier output authoritative; it is to preserve enough
evidence for operators and tests to know when the LLM classifier failed and
why the system fell back to heuristic behavior.

## Observed Behavior

During 0.8.0 release validation, every continuation turn of `aiworker run`
emits the same `conversation.classifier` event:

```json
{
  "type": "conversation.classifier",
  "payload": {
    "conversationId": "...",
    "decision": { "continue": true, "reason": "non-json-classifier-output" }
  }
}
```

This implies a real LLM classifier is invoked but its output is rejected for
not being valid JSON, after which the system falls back to heuristic intent
selection (`intent-heuristic`, see BUG-066).

The event keeps `reason: "non-json-classifier-output"` but does not include:

- the raw LLM output that failed validation
- which prompt/template was used
- the engine and model that produced the output
- the parse error message
- whether this is the first such failure in the session

A user trying to debug "why is brain decision always heuristic" gets only a
boolean `continue=true` with no actionable evidence.

## Why this matters

- Without the failed LLM output, neither a human reviewer nor a downstream
  test can tell if the classifier prompt is wrong, the model is non-compliant,
  or the JSON schema is too strict.
- Repeated silent fallback masks a regression — if the classifier prompt ever
  starts producing valid JSON in a future model version, no one notices, and
  if it stops, no one notices either.
- 60 turns × 5 Souls × 2 engines all hit `non-json-classifier-output`
  without exception → either the classifier is misconfigured for both engines
  or the JSON contract is wrong, but the event surface is too thin to
  distinguish.

## Reproduction

Same environment as BUG-066. Any second-or-later turn under the same
chat-id will emit the event:

```bash
$AIW run --chat-id smoke --message 'Hello'
$AIW run --chat-id smoke --message 'Continue'
grep '"type":"conversation.classifier"' logs/*.log
```

Across the 60-turn 0.8.0 validation matrix, the count of events with
`reason: "non-json-classifier-output"` matches the number of continuation
turns (no turn produced a JSON-validating classifier output).

## Expected Behavior

The event should include enough diagnostic context to distinguish:

1. Classifier was not invoked (heuristic-only mode).
2. Classifier was invoked but the model returned non-JSON — payload must
   carry the raw output (truncated to a documented bound), the engine/model,
   the prompt template id, and the parse error.
3. Classifier was invoked and returned JSON that failed schema validation —
   payload must carry the JSON and the validation errors.

Additionally:

- `aiworker brain status` should expose recent classifier success rate and
  the last failure sample, so operators can spot a regression without
  scraping event logs.
- A focused regression test should run a real classifier against a known
  prompt and assert `reason !== "non-json-classifier-output"`. If the
  contract is intentionally optional, the documentation should say so.

## Acceptance Criteria

1. `conversation.classifier` event payload extended with raw output, model
   identifier, and parse/schema error fields when the fallback path triggers.
2. Add a CLI/REST surface (or extend `brain status`) that summarises recent
   classifier outcomes.
3. If the JSON contract is the actual root cause, fix the contract or the
   classifier prompt and remove the silent-fallback path.
4. Tests assert that with the default classifier configuration the
   `non-json-classifier-output` reason is not the dominant outcome on either
   `claude-code` or `codex` engines.

## Notes

- See BUG-066 for the umbrella context (brain decision layer is heuristic).
- This bug specifically targets the diagnostic surface, even if the
  underlying decision stays heuristic-by-default.
