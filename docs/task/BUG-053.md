# BUG-053 Codex executor may replay final text after streamed deltas

- **status**: completed
- **priority**: P2
- **owner**: Codex
- **createdAt**: 2026-05-04 10:04
- **discoveredAt**: 2026-05-04 10:04
- **completedAt**: 2026-05-04 10:34

## Observed Behavior

The operator reported seeing the same class of duplicate streamed text problem
under the Codex executor: append-only text deltas are rendered, and a later
event appears to replay the final assistant text, causing downstream consumers
to show duplicated output.

This is related to, but distinct from, `BUG-052`. `BUG-052` confirmed and fixed
the Claude Code path where partial `stream_event` text was followed by a final
assistant text block. This task tracks whether the Codex executor has an
equivalent replay path and, if confirmed, where it should be fixed.

Current code observations:

- `packages/core/src/worker/executor/engines/codex/normalize.ts` maps legacy
  `codex/event/assistant_message` by preferring `delta` and falling back to
  full `text`.
- Current protocol `item/agentMessage/delta` is mapped as a text delta.
- Existing Codex normalizer tests cover delta and full-text fallback
  separately, but do not cover a streamed-delta-then-final-text sequence.

## Expected Behavior

`orchestrator.text.payload.delta` is append-only text for all executor engines.
Codex-backed runs should not emit a final full-text snapshot through the same
`delta` field after prior assistant text deltas have already been emitted.

If Codex exposes both incremental deltas and final snapshots, AIWorker should
either suppress the replay at the narrowest executor adapter layer or expose the
snapshot through a distinct field/event type.

## Reproduction / Evidence

Sanitized local reproduction ruled out a replay on the current Codex path.
The probe used a temporary project-scope worker, real `HOME` for Codex auth,
and captured only event types plus text delta values/lengths.

Command shape:

```bash
cd /Users/ben/projects/aiworker/tmp/bug-053-repro
bun /Users/ben/projects/aiworker/apps/cli/src/aiworker.ts init --soul developer --force
bun /Users/ben/projects/aiworker/apps/cli/src/aiworker.ts executor select --engine codex --apply
bun /Users/ben/projects/aiworker/apps/cli/src/aiworker.ts run \
  --chat-id codex-text-replay-check \
  --timeout-ms 180000 \
  --message 'Reply with exactly "BUG053_MARKER_20260504" and nothing else.'
```

Observed `orchestrator.text` deltas:

```text
BUG
053
_MARK
ER
_
202
605
04
```

The sequence was followed by `orchestrator.finished`; no full final text replay
was observed.

Direct `codex app-server` probe on `codex-cli 0.128.0` observed current
`item/agentMessage/delta` notifications with params keys
`delta`, `itemId`, `threadId`, `turnId`, then `thread/tokenUsage/updated` and
`turn/completed`. No `codex/event/assistant_message` or full-text snapshot was
observed. Fallback pin `@openai/codex@0.121.0` also used the current protocol,
not legacy `thread_start`.

   current `item/agentMessage/delta`, another current notification, or a

3. Preserve the global contract that `orchestrator.text.payload.delta` is
   append-only.
4. If replay is confirmed, fix the narrowest Codex executor layer without
   changing Worker Admin, CLI, or gateway append behavior.
5. Add focused Codex fixture coverage for the confirmed event shape.
6. Preserve Codex session continuation and existing tool/event normalization
   behavior.
