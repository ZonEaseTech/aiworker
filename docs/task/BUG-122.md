# BUG-122 Restore GitHub-hosted release workflows after self-hosted fallback

## Background

During the `@zonease/aiworker-cli@0.15.2` emergency release, the original
`ubuntu-latest` runs stayed queued with no runner and no steps. The release was
unblocked by temporarily switching `lint.yml` and `release.yml` to the
organization's `ttpos-uat-linux` self-hosted runner label.

That fallback made the release succeed, but leaving public repository workflows
on self-hosted runners is the wrong long-term CI posture. The default path for a
queued GitHub-hosted run should be cancel and re-run first, then investigate
GitHub-hosted runner availability or repository/org Actions policy. Self-hosted
fallbacks should require explicit acceptance and must be reverted immediately.

## Scope

- Restore `.github/workflows/lint.yml` and `.github/workflows/release.yml` to
  `ubuntu-latest`.
- Keep the Node 24 setup and explicit Node heap setting that stabilized the
  release path.
- Record the correction in PMA docs and changelog.
- Add an operator memory note so future release work does not repeat the
  self-hosted fallback as the first remediation step.

## Acceptance Criteria

1. `lint.yml` uses `runs-on: ubuntu-latest`.
2. `release.yml` uses `runs-on: ubuntu-latest`.
3. The workflows retain `actions/setup-node@v4` with Node 24 and
   `NODE_OPTIONS=--max-old-space-size=1024`.
4. PMA docs and changelog record why the self-hosted fallback was reverted.
5. A memory update note exists under `.codex/memories/extensions/ad_hoc/notes`.

## Record

- 2026-05-15 21:00: Restored both workflows to `ubuntu-latest` while preserving
  Node 24 and heap settings. Documented the incident as a CI fallback correction
  rather than a release behavior change. The already published `v0.15.2` tag and
  release evidence were not modified.
