dogfood，验证 Journal、Gate、Brain Engine review、repair/rerun/hold、Brain Inbox

proof-loop MVP 已具备继续 readiness closeout 的证据。

## Results

- Pass path: covered by Journal trace tests and Gate pass normalization.
- Repair/rerun/hold path: covered by orchestrator history tests:
  - single repair attempt in retry mode;
  - `task.held` in block mode;
  - parent → child rerun lineage;
  - rerun cap rejection after 3 child attempts.
- Brain Inbox path: covered by core/API/CLI tests:
  - pending proposal creation from Brain Engine `lessonCandidates`;
  - explicit rejection stays in `brain_admission_proposals.status='rejected'`;
  - no canonical filesystem write happens without the existing admission apply path.
- Authority path: covered by authority service and orchestrator tests:
  - production database deletion prompt is high risk under ambient authority;
  - `enforceable=false` is preserved;
  - Gate verdict cites `authority-preflight` as observe-only warning.

## Product Judgment

The proof loop reduced review ambiguity: a task now has one Journal trace carrying
executor authority, preflight warnings, task lifecycle, Gate verdict, Brain Engine
review, repair/rerun lineage, and Inbox proposal ids.

The proof loop reduced memory drift: lessons are not silently written. They become
pending admission proposals with evidence, risk, confidence, target, payload, and
rollback, and the existing approve/reject/apply state machine remains the only
canonical Brain mutation path.

The proof loop does not yet prove a 1.0 release claim. It is source-backed and
developer-repo scoped; published-package validation and release packaging belong
to PLAN-181 or a dedicated REL task.
