# BUG-118 Worker Web blanks with orphan legacy workers

## Description

After publishing `@zonease/aiworker-cli@0.13.0`, a user with an existing
`AIWORKER_HOME` can start the daemon successfully but see a blank Worker Web
page. The daemon serves Web assets and local API responses, but Worker Web
selects a persisted legacy worker whose `soulId` is no longer projected by the
current official Soul App catalog.

Acceptance criteria:

- Worker Web does not render a blank page when persisted workers reference
  unavailable legacy Soul ids.
- Worker Web selects the first worker that has both a projected Soul and a
  capability template.
- If no selectable workers exist, Worker Web falls back to the Soul App
  first-run surface.
- Existing valid HR/QA worker routes, creation flow and specialized HR
  workbench behavior remain passing.
- The published patch package can start the daemon and render Web in both clean
  and legacy-home smoke scenarios.

## ActiveForm

Fixing Worker Web's selected worker resolution so stale local metadata cannot
blank the Host shell after the 0.13.0 preview release.
