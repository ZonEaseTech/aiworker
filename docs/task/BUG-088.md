# BUG-088 Worker Web session turn disappears until refresh and Codex plugin warning noise

- **status**: done
- **priority**: P0
- **owner**: local
- **createdAt**: 2026-05-10 20:50
- **claimedAt**: 2026-05-10 20:50
- **plan**: PLAN-226
- **relatesTo**: apps/web, apps/api, packages/core

## Problem

Two production UX issues were reported in the session route:

1. When the operator sends a follow-up message, the composer clears
   immediately, but the new user turn is not visible until browser refresh.
2. Codex CLI writes a non-fatal `403 Forbidden` warning while warming
   `chatgpt.com/backend-api/plugins/featured`; AIWorker shows the raw stderr
   warning and Cloudflare HTML as if it were the session response.

## Investigation

- `submitTurn()` clears `turnInput` before the streamed turn result is loaded.
- The SSE route only forwards persisted `session_event` rows. It ignores the
  runtime bus `turn` event, so Web receives events for a real `turnId` before
  it has the corresponding `LocalTurn` row.
- `WorkerSessionChat` renders events by matching `event.turnId` against
  `turn.id`; without the new turn row, incoming stream events have no visible
  parent message.
- The latest local invocation succeeded and produced an artifact. The 403 is a
  Codex CLI warning from featured plugin cache warming, not the model request
  or AIWorker local API failing.

## Acceptance Criteria

- Sending a follow-up turn immediately shows the user message and assistant
  pending state without waiting for refresh.
- When the daemon creates the real turn row, Web replaces the optimistic state
  with the streamed turn and events.
- Non-fatal Codex plugin warm/cache warnings do not dominate the session
  timeline.
- API/Web tests cover the new streamed turn event and optimistic UI behavior.
- Focused gates and code-review-graph pass before completion.

## Resolution

- Runtime turn bus events now carry the persisted `LocalTurn` row for running,
  succeeded, and failed states.
- The SSE route forwards those rows as `turn` frames alongside
  `session_event` frames.
- Worker Web merges persisted turns, streamed turns, and an immediate
  optimistic pending turn so the operator message is visible as soon as it is
  submitted.
- Codex's known non-fatal featured plugin cache 403 warning is filtered from
  visible session logs and final tool output while the raw `stderr.log` remains
  on disk for diagnosis.
