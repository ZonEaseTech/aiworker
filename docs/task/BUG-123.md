# BUG-123 Published official Soul App mounted entrypoints are wrong

## Background

Clicking the HR header primary action in the published `@zonease/aiworker-cli@0.16.0`
daemon returns `Local API 502: /api/local/apps/aiworker-hr/actions/create-people-profile`.
The daemon error body shows that Host cannot start the mounted HR service:

```text
Mounted Soul App service exited before readiness: 1. error: Module not found "dist/host-mounted.js"
```

The published official app manifest points `api.localService.command` at
`dist/host-mounted.js`, but a clean Bun build emits mounted entrypoints at
`dist/mounted/host-mounted.js`. QA has the same published-package failure for
`create-release-gate`.

## Goal

- Patch published official app manifests to the real bundled entrypoint paths.
- Make the publish-manifest test assert the copied files exist at those paths.
- Extend the dist release smoke to invoke mounted HR and QA shell actions, not
  only bootstrap/list catalog metadata.

## Non-Goals

- Do not change Host/Soul protocol semantics.
- Do not make Host interpret HR profile or QA release gate domain data.
- Do not repair the already-published `0.16.0` package in place; prepare a
  source fix that can ship in the next patch release.

## Acceptance Criteria

1. `apps/cli/scripts/build-publish-manifest.ts` patches official app manifests
   to `dist/mounted/host-mounted.js` and `dist/standalone/standalone.js`.
2. Publish-manifest tests fail if copied official app runtime entrypoint files
   do not exist.
3. `smoke:dist-release` invokes HR and QA mounted primary actions successfully.
4. Focused tests and dist release smoke pass.
5. code-review-graph runs for the code changes before closeout.

## Record

- 2026-05-16 23:04: Claimed after reproducing the published-package 502 against
  local daemon port `9217` for both HR and QA actions. Root cause is manifest
  patching to stale flat `dist/*.js` entrypoints while clean Bun output is nested
  under `dist/mounted/` and `dist/standalone/`.
- 2026-05-16 23:07: Fixed the publish-manifest patch to use nested runtime
  entrypoints and added physical runtime-file assertions. Extended the dist
  release smoke to invoke HR and QA mounted primary actions; the smoke now proves
  broker storage/search writes and generic action endpoints both return 200.
- 2026-05-16 23:14: During `0.16.1` release prep, `npm pack --dry-run`
  exposed ignored local legacy flat `dist/host-mounted.js` and
  `dist/standalone.js` files leaking into local official app resources. Added a
  regression test and filtered those stale flat entries while preserving the
  nested release entrypoints.
