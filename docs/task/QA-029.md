## Background

After the destructive session/workspace refactor, validation must prove the
operator path works from an empty `~/.aiworker`: daemon boot, Web entry, Soul
worker selection, workspace/session/turn creation, artifact visibility, settings
persistence, CRG review, and commits.

## Goal

Run focused gates, feasible root gates, code-review-graph review, and browser
verification. Provide a local preview URL.

## Acceptance Criteria

- Empty host home initializes without old project-scope files.
- Web first screen selects a Soul worker and capability template.
- Creating a workspace/session turn produces a visible artifact or a clear
  engine configuration failure if no engine is available.
- Settings changes persist across refresh.
- Focused gates and feasible root gates are recorded.
- code-review-graph review is recorded for code changes.
- Conventional commits exist for the implemented slices.
