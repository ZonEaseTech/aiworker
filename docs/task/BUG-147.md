## Background

FEAT-106 correctly removed the Host-owned `apps/web/src/worker/souls/hr`
boundary, but the deleted path contained the already migrated HR people
workbench product model and profile/review semantics. The current
`apps/aiworker-hr` product web surface is still proof-level, so the working
product UI was removed from Host before it was ported into the app that owns
it.

## Acceptance Criteria

1. Do not restore `apps/web/src/worker/souls/hr`.
2. Move the HR people workbench domain model, profile README parsing and
   revision-review behavior into `apps/aiworker-hr/product/web`.
3. Render the HR route and standalone HTML through app-owned shadcn-first
   workbench components from `@zonease/aiworker-ui`.
4. Host mounted `/micro-app/routes/hr-home` serves the real HR people workbench
   instead of proof cards.
5. The HR app introduces no Host-private imports or legacy
   `@zonease/aiworker-component` dependency.
6. Focused HR tests, validate/smoke, mounted-surface smoke, boundary audit,
   UI audit, diff check and code-review-graph run before completion.

## Completion Notes

- Ported the HR people workbench domain model, profile README parser and
  revision-review logic into `apps/aiworker-hr/product/web/people-workbench`.
- Rebuilt the visible HR route as an app-owned shadcn workbench surface using
  `@zonease/aiworker-ui` Card, Item, Badge and Button primitives.
- Updated standalone and Host mounted HR entrypoints to render the real
  people workbench instead of proof cards.
- Kept `apps/web/src/worker/souls/hr` deleted and added tests/audits proving
  the HR app does not import Host Web source, `@zonease/aiworker-shared`, or
  `@zonease/aiworker-component`.
