## Scope

Run the extended Governance Kernel harness after PLAN-133 lands to prove
the long-running `aiworker serve` REST multi-turn regression invariants:

- `POST /api/worker/orchestrator/tasks` returns 401 without bearer and
  enqueues nothing.
- `POST /api/worker/orchestrator/tasks` with bearer enqueues a task that
  the long-lived orchestrator drives to `agent_tasks.status='succeeded'`,
  with a conversation row appearing in worker.db.
- `POST /api/worker/orchestrator/conversations/:id/messages` continues the
  same conversation, the orchestrator drives the second task to
  `succeeded`, and the conversation messages array grows by 2 (user +
  assistant).
- `GET /api/worker/orchestrator/conversations/:id/messages` returns ≥ 4
  messages.

## Multi-Turn REST Evidence Highlights

For each pair, all four new REST orchestrator checks PASS:

| Check | developer-codex | general-assistant-claude-code |
|---|---|---|
| REST orchestrator unauth boundary | PASS (POST /tasks without bearer → 401) | PASS (POST /tasks without bearer → 401) |
| REST orchestrator submit | PASS (POST /tasks → 201, task succeeded, conversation row written) | PASS (POST /tasks → 201, task succeeded, conversation row written) |
| REST orchestrator continue | PASS (POST /conversations/:id/messages → 201, same conversation id, second task succeeded) | PASS (same) |
| REST orchestrator messages | PASS (GET /conversations/:id/messages → 200, 4 messages) | PASS (same) |

Together these checks prove the long-running `aiworker serve` orchestrator
preserves the same admission / conversation / chat-id continuity invariants
as the per-turn `aiworker run` CLI surface:

- Two consecutive REST submissions on the same conversation id terminate at
  `agent_tasks.status='succeeded'` against the same long-lived orchestrator
  process.
- The conversation messages array grows monotonically across turns; both
  user prompts and assistant replies are persisted to `worker.db`.
- Bearer auth is required to enqueue (BUG-015 / BUG-035 / BUG-043 / BUG-044
  regression line).

The existing 30 pre-PLAN-133 source-backed checks per pair continue to PASS
under the same harness invocation.
