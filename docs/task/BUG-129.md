# BUG-129 Failed Codex turn can leave durable artifact files unregistered

- **status**: pending
- **priority**: P1
- **owner**: unassigned
- **createdAt**: 2026-05-17
- **plan**: PLAN-344
- **relatesTo**: packages/core/src/worker/executor.ts, packages/core/src/worker/runtime.ts

## Background

In the first real Codex sample, turn 2 wrote a markdown file under
`artifacts/<sessionId>/`, then Codex exited with `Selected model is at
capacity`. AIWorker marked the turn failed and returned `artifacts: []` even
though the durable file existed on disk.

## Root Cause Candidate

`runLocalCliExecutor` throws immediately when the external engine exits
non-zero, before `discoverInvocationArtifacts` can salvage files produced before
the failure.

## Acceptance Criteria

- Failed turns that wrote files under the current session artifact directory
  surface those files in a recoverable/failed-artifact state, or the runtime
  records an explicit diagnostic event pointing to the unregistered file.
- The behavior is covered by executor/runtime tests using a scripted engine
  that writes an artifact and exits non-zero.
- The session timeline makes clear that human review is still required before
  any promotion.
