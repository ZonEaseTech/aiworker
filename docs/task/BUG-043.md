# BUG-043 Worker Admin chat event stream times out before slow replies

- **status**: completed
- **priority**: P1
- **owner**: Codex
- **createdAt**: 2026-05-02 20:39
- **discoveredAt**: 2026-05-02 20:25
- **completedAt**: 2026-05-02 21:02
- **plan**: PLAN-065

## Observed Behavior

During local Worker Admin Chat validation with the real Codex executor, the
assistant reply was persisted in `worker.db`, but the browser did not live
update until the page was reloaded. The worker server logged a Bun request
timeout for `GET /api/worker/events/stream` after about 10 seconds.

Relevant code pointers:

- `apps/cli/src/commands/worker/serve.ts` starts `Bun.serve` without an
  explicit `idleTimeout`.
- `apps/api/src/worker/events/routes.ts` keeps the SSE stream open only by
  writing bus events; it does not send heartbeat frames while a slow executor
  is still running.

## Expected Behavior

Worker Admin Chat should keep the event stream alive for slow but healthy
executor replies and render the assistant response without requiring a reload.

## Reproduction

1. Start a local worker with the Codex executor and Worker Admin enabled.
2. Open `/admin/chat` with a valid worker bearer token.
3. Send a prompt that takes longer than 10 seconds to complete.
4. Observe the server timeout on `/api/worker/events/stream` and the missing
   live UI update, even though the assistant message is later persisted.

## Acceptance Criteria

1. Slow executor replies beyond 10 seconds still stream or otherwise update the
   Chat UI without a page reload.
2. The worker event stream has a tested keepalive/timeout strategy compatible
   with Bun's server idle timeout.
3. Focused API/Web tests cover a long-running task with no intermediate text
   events.
4. A real local Worker Admin smoke verifies that a slow Codex-backed reply
   appears live in the UI.

## Plan

- **PLAN-065**: Worker Admin SSE keepalive for slow replies.

## Notes

  the direct worker event stream staying byte-idle while slow executors run.
- 2026-05-02 21:02 Fixed by adding direct worker SSE `: connected` and
  `: keepalive` comment frames below Bun's default HTTP idle timeout, with
  cleanup on request/stream abort.
