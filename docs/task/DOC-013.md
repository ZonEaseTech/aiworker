## Context

The active documentation now routes Host and Soul App development through
separate skills, but architectural constraints are still repeated across active
entrypoints, skills and authoring docs. That shape is understandable to humans,
yet fragile for agents: future edits can drift because there is no explicit
registry that says which file owns a rule and which checks enforce it.

`README.zh-CN.md` is also stale and still describes an older turn/memory/runtime
shape. It should not remain as a second product entrypoint.

## Goals

- Make `docs/architecture.md` the explicit normative source for hard
  Host/Soul/protocol/data/import/documentation constraints.
- Keep `AGENTS.md`, README files and skills as thin operational routers.
- Remove stale active-entrypoint language from `README.zh-CN.md`.
- Add a machine check that protects the documentation contract from drifting.

## Non-Goals

- No runtime behavior changes.
- No database, API, manifest or UI changes.
- No rewrite of historical PMA, changelog or Superpowers records.
- No large onboarding portal.

## Acceptance Criteria

- `docs/architecture.md` contains a stable Constraint Registry with IDs, owners,
  source-of-truth status and enforcement references.
- Active thin layers point agents to the registry instead of independently
  redefining the same constraints.
- `README.zh-CN.md` no longer carries stale product architecture.
- `scripts/check-doc-contract.ts` verifies the active documentation contract.
- `bun run docs:check` exists and runs the contract check.
- `bun run lint` includes the documentation contract check.
