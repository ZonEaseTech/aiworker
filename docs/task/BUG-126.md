# BUG-126 Profile ledger follows parent repository when workspace is under ignored path

## Background

During the HR native skill debug campaign, a pilot `AIWORKER_HOME` under the
repo ignored `tmp/` path produced profile ledger metadata:

```text
profileLedger.git.status = failed
message = The following paths are ignored by one of your .gitignore files: tmp
```

The workspace also lacked its own `.git` repository and `git status` resolved
against the parent project repository.

## Root Cause

`profile-ledger` used `git rev-parse --is-inside-work-tree`, which returns true
inside a parent repository. Running `git init` from inside that parent worktree
can reinitialize the parent repo instead of creating a nested workspace ledger.

## Fix

- Treat a workspace as a profile ledger repository only when
  `git rev-parse --show-toplevel` resolves to the workspace root.
- Run profile-ledger git commands with `GIT_CEILING_DIRECTORIES` set to the
  workspace parent so parent repository discovery cannot leak in.
- Canonicalize `/var` and `/private/var` paths before comparison.

## Verification

- `bun run --filter '@zonease/aiworker-core' test src/worker/runtime.test.ts src/worker/executor.test.ts`
- Matrix setup under `/private/tmp/...-matrix` created three profile workspaces
  with `profileLedger.git.status = created`.
