# BUG-044 Worker Admin chat does not continue the selected conversation

- **status**: completed
- **priority**: P1
- **owner**: Codex
- **createdAt**: 2026-05-02 20:39
- **discoveredAt**: 2026-05-02 20:26
- **completedAt**: 2026-05-02 21:29
- **plan**: PLAN-066

## Observed Behavior

Worker Admin Chat lists prior conversations and lets the operator select one,
but sending a message always calls the task submission path. The backend creates
a new task with `chatId = task:<task-id>`, so each Web UI send becomes a new
conversation instead of continuing the selected conversation/session.

Real local validation showed separate `web:task:<uuid>` conversations for
successive Worker Admin sends, while CLI `worker run --chat-id
real-codex-session-1` preserved continuity correctly across turns.

Relevant code pointers:

- `apps/web/src/worker/features/chat/chat-panel.tsx` calls `submitTask(text)`
  without passing the active conversation.
- `packages/core/src/worker/orchestrator/service.ts` `submitTask()` always
  creates a fresh task envelope with `chatId: task:<id>`.

## Expected Behavior

When an operator selects an existing conversation and sends a message, Worker
Admin Chat should continue that conversation and reuse the executor-native
session binding where applicable. Creating a new conversation should be an
explicit action.

## Reproduction

1. Start a local Codex-backed worker and open authenticated Worker Admin Chat.
2. Send a message and wait for the assistant reply to persist.
3. Select that conversation and send a second message intended to reference the
   prior turn.
4. Observe a new `web:task:<uuid>` conversation row instead of a continuation
   of the selected conversation.

## Acceptance Criteria

1. Worker Admin Chat has separate "new task/new conversation" and "continue
   selected conversation" flows.
2. Continuing a selected conversation appends user/assistant messages to the
   same conversation row.
3. The executor-native session binding is reused for engines that support
   continuity.
4. Web and orchestrator tests cover both new conversation and continuation
   behavior.
