# BUG-010 Runtime log strings still reference `aiw` / `aim` / `aim.json` after PLAN-020 rename

- **status**: pending
- **priority**: P3
- **owner**: (unassigned)
- **createdAt**: 2026-04-27 09:10

## Description

PLAN-020 S3 docs sweep (commit `4d0fd24`) caught README / docs / CLAUDE.md
forward-looking references but **missed runtime log strings** in TS source
that print to operator / worker stdout. Result: even after the binary
itself renamed to `aiworker`, the live console output still says
"`[aiw serve]`", "请用 `aim enroll approve` …", etc.

Discovered live during PLAN-020 e2e (2026-04-27 08:55) — fresh OTP
worker `w_0fdb13wpattb` printed:

```
i [aiw serve] worker w_0fdb13wpattb listening on :3001 (config v2)
i [aiw serve] OTP enrolling to wss://gateway.example.test/enroll-ws; awaiting operator approval
i [aiw serve] OTP 6TX3-ERJV 已签发，请用 aim enroll approve 6TX3-ERJV 准入；expires in 300s
```

These don't break anything — the binary IS named `aiworker` and
`aim enroll approve` did get accepted because S2 also registered
`aiworker enroll approve` while not removing the legacy aliases (or
because the prompt string is hard-coded). They just confuse new users
who only know `aiworker`.

### Acceptance criteria

1. `git grep -E '\b(aiw|aim)\b' --` over **source code** (`apps/`,
   `packages/`) returns either:
   - empty, OR
   - only matches inside string-literal comments / historical PLAN/FEAT
     references that we explicitly want to keep.
2. Every `consola.info` / `consola.success` / `consola.warn` /
   `console.log` that contains an old name string is updated to
   `aiworker`.
3. Any `Use \`aim ...\`` instructional string changed to `Use
   \`aiworker ...\``.
4. `apps/cli/src/aim/commands/install.ts` location is OK (subdir name
   "aim" is internal — bin entry is what matters); but if the file's
   `consola.success(\`aim install systemd …\`)` style strings reference
   the old name, change them.
5. `~/.aiworker/aim.json` state file: **either rename to
   `~/.aiworker/aiworker.json` (clean break, since never published)
   OR document that the legacy name is retained for state-file
   stability** — pick one and apply consistently across:
   - `apps/cli/src/aim/state.ts`
   - all docs that mention the file
   - migration note in CHANGELOG (if rename)

### Out of scope

- Existing `apps/cli/src/aim/` directory layout — that's internal
  source organisation, not user-facing
- PLAN/FEAT/BUG/changelog historical entries (they reference `aim` /
  `aiw` and stay frozen)
