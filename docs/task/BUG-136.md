# BUG-136 Profile ledger writes repository-local Git identity

## Background

`BUG-126` fixed parent repository discovery for profile workspaces created under
an ignored source checkout path. The incident still exposed a broader provenance
hazard: profile ledger commits configured `user.name` and `user.email` with
`git config`, which writes persistent repository-local identity.

The source checkout was previously left with:

```text
user.name = AIWorker Profile Ledger
user.email = aiworker@local
```

and multiple real development/release commits were authored with that identity.

## Root Cause

`profile-ledger` used persistent `git config user.name/user.email` before each
profile commit. When git repository discovery reached the wrong repository, the
wrong repository's local config was mutated. Even for the correct profile ledger
repository, this creates durable config state where a per-command identity is
sufficient.

## Fix Plan

- Stop writing `user.name` and `user.email` into repository-local Git config.
- Inject the ledger author/committer identity only through Git process
  environment for profile commit/tag commands.
- Add regression coverage that proves parent repository config and workspace
  local config are not mutated while profile commits still carry the ledger
  author identity.
- Confirm the current source checkout no longer has local `user.*` overrides.
- Record the already-polluted commit range without rewriting shared history
  unless explicitly requested later.

## Outcome

Profile ledger Git identity is now process-scoped rather than repository
stateful. Profile commits and annotated tags receive
`AIWorker Profile Ledger <aiworker@local>` through Git environment variables,
while neither the parent repository nor the workspace ledger repository receives
persistent local `user.name` / `user.email` config.

The current source checkout has no local `user.name` / `user.email` overrides.
Historical commits already authored with the ledger identity were measured as 27
commits, from `285e5f22` through `b31ff94a`. They were not rewritten in this
fix because those commits are already part of shared release history.
