# BUG-057 Brain decision-layer LLM evaluator never produces valid JSON

## Observed Behavior

orchestrator 的三层决策（intent classifier / capability decision / quality gate）在 0.6.0
published 版本下默认全部走 heuristic：

```
orchestrator.intent_decision    mode=observe_only  source=intent-heuristic
orchestrator.capability_decision mode=observe_only  source=capability-registry
orchestrator.quality_gate       mode=observe_only  evaluator=heuristic
```

显式开启 LLM evaluator：

```bash
aiworker config set '{
  ...,
  "orchestrator":{"decisionPipeline":{
    "intentClassifier":{"evaluator":"llm"},
    "qualityGate":{"evaluator":"llm","gateMode":"warn"}
  }}
}'
```

后实测 100% 仍 fallback heuristic，事件 reason 字段：

```
"llm-intent-classifier-error: SyntaxError: JSON Parse error: Unexpected identifier \"React\""
```

fake-claude shim 抓到的 intent classifier LLM 调用 stdin：

```text
=== ARGV ===  -p --output-format=stream-json --input-format=stream-json --model sonnet
=== STDIN ===
{"type":"user","message":{"role":"user","content":[{"type":"text","text":
  "Recent messages:\n- user: ...\n- assistant: ...\n
   New incoming message: 我想知道 React 19 里面 useTransition 的新行为..."}]}}
```

quality gate LLM 调用 stdin：

```text
"Quality profile: default\nRisk: low\nMode: observe\nThreshold: 5\n
 User request:...\nAssistant answer:..."
```

两者：

- 没有任何 system prompt（与 BUG-056 同因，adapter 层不发 system）
- 没有任何 schema 指令（没说 "你是 classifier，请按 JSON 形式输出 `{intent, sessionAction, risk, confidence, reason}`"）
- LLM 把它当普通 Q&A 回答，第一个字符是 "React"，`JSON.parse` 立刻炸 → fallback heuristic

启用 LLM evaluator 时单轮 user 对话实际触发 4 次 claude-code 子进程调用（intent / main /
quality / 偶尔 capability），3 次输出被 schema 拒绝丢弃，token 浪费 + 延时显著上升 + 用户体验
与 default heuristic 完全一样。

## Expected Behavior

- 启用 `evaluator: 'llm'` 后，intent classifier / quality gate 应当产出可解析 JSON
- 即便 LLM 偶尔输出非 JSON，应有 1 次 retry-with-stricter-prompt 兜底
- 事件 mode 在配置允许时应能切到 `enforce`（影响 sessionAction / quality threshold），不只
  observe_only
- capability registry 当前是纯 heuristic（无 LLM 入口），如果产品定位是"brain 也用 LLM"，
  需要补 LLM 路径

## Source Code Root Cause（待修）

- `packages/core/src/worker/orchestrator/intent-classifier.ts` L46-81：`buildIntentPrompt`
  没构造 system / instruction 段；通过主 executor 投递时只发普通 user message
- `packages/core/src/worker/orchestrator/quality-gate.ts` L23-34：`evaluateWithExecutor` 同
  样问题
- `packages/core/src/worker/orchestrator/capabilities.ts` L99：硬编码 `reason: 'S2 observe-only
  capability registry; selections are recorded but not enforced.'`，没有 LLM 入口

## Scope of Fix（建议）

### P0

1. `buildIntentPrompt` / `buildQualityGatePrompt` 必须在送 LLM 前先构造 system message：

   ```text
   You are an internal classifier. Output ONLY a JSON object matching:
   {"intent": "answer"|"planning"|"...", "sessionAction": "...",
    "risk": "low"|"med"|"high", "confidence": 0..1, "reason": "<short>"}
   No markdown. No prose. No code fence.
   ```

2. 依赖 BUG-056 的 adapter 修复：claude-code adapter 必须支持 system prompt 注入（无论
   `--append-system-prompt` 还是 stdin system envelope），否则 system 指令永远到不了 LLM
3. 加 1 次 retry-with-stricter-prompt：第一次 `JSON.parse` 失败后追加 "Previous output was not
   valid JSON. Output JSON only:" 重发

### P1

4. 决策层 LLM 走轻量 LLM provider（直 Anthropic / OpenAI API），不要每个决策启 claude-code
   子进程 —— cold start ~1.5s + claude-code default system 3000+ token 浪费严重；
   `controlExecutor` 配置已经支持解耦，文档里应当推荐独立配置
5. capability registry 补 LLM 入口（如果产品方向是"brain 也用 LLM"），或显式在事件 reason 里
   声明"capability registry by design 走 deterministic"
