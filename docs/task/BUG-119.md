## Background

AIWorker will not publish standalone SDK/runtime npm packages in this slice.
Before any future publication, the current monorepo-only authoring boundary
still needs cleanup:

1. Mounted Soul Apps can call Host broker routes through the SDK client, but the
   callback path does not carry Host bearer auth when `AIWORKER_LOCAL_TOKEN` is
   enabled.
2. `aiworker app create` scaffolds `@zonease/aiworker-soul-app-sdk:
   workspace:*`, which is accurate for source-checkout development but
   misleading for external npm users while the SDK package is unpublished.
3. The SDK README still lists runtime harness helpers after they moved to
   `@zonease/aiworker-soul-app-runtime`.
4. The runtime harness exposes Host storage row types and runtime internals more
   broadly than needed for app tests.

## Goal

Keep SDK/runtime unpublished, but make the current boundaries honest and safer:

- mounted app broker callbacks work through Host-owned mount-token auth without
  leaking caller bearer credentials;
- source-checkout scaffold output is clear about its monorepo preview
  dependency shape;
- SDK docs match the current SDK/runtime split;
- runtime harness return types avoid publishing Host storage rows as app-facing
  types.

## Non-Goals

- No npm publish.
- No CLI release or version bump.
- No public 1.0 SDK compatibility promise.
- No large rewrite of Host runtime, storage schema, or Soul App protocol.

## Acceptance

- A failing test first proves mounted broker callbacks are denied under local
  bearer auth before the fix and pass through mount-token auth after the fix.
- SDK client tests cover mount-token header injection.
- CLI scaffold tests cover the monorepo preview dependency note.
- Runtime harness tests still prove standalone and Host-mounted app behavior
  without exposing `WorkerRow` as the app-facing harness worker type.
- Focused tests, typechecks, app validate/smoke, `git diff --check`, and
  code-review-graph complete before closing the task.
