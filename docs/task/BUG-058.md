# BUG-058 `aiworker brain admission list/show` aborts entirely when a single proposal row has schema drift

- **status**: completed
- **priority**: P2
- **owner**: aiworker-maintainer
- **createdAt**: 2026-05-04 22:20
- **discoveredAt**: 2026-05-04 22:20
- **completedAt**: 2026-05-05 01:30
- **plan**: PLAN-106
- **relatesTo**: PLAN-101, PLAN-103

## Observed Behavior

当 worker.db `brain_admission_proposals` 表里某条 row 的 `evidence` JSON 缺字段（例如 `at` /
`kind` / `ref`）时，CLI / REST 整个 list / show 返回都崩溃：

```text
$ aiworker brain admission list --status pending

 ERROR  [aiworker brain admission list] failed: [
  {"code":"invalid_type","expected":"string","received":"undefined","path":["evidence",0,"at"],"message":"Required"},
  {"code":"invalid_type","expected":"...","received":"undefined","path":["evidence",0,"kind"],"message":"Required"},
  {"code":"invalid_type","expected":"string","received":"undefined","path":["evidence",0,"ref"],"message":"Required"}
]
```

正常 row 一并被拒，operator 看不到任何其它 proposal。`/api/worker/brain/admission` 应同样
表现（PLAN-103 read 端走同一 zod schema）。

## Expected Behavior

单条 schema 不合规：

- list / show 跳过该 row
- 返回值末尾添加 `{ skipped: <count>, skippedIds: [...], skipReasons: ['schema-drift'|...] }`
- 写一条 worker.db audit / log 行，方便后续手工修复

## Why this matters

- 0.6.0 admission service 与 worker.db migration 之间的 schema drift（任何字段 rename / 必填
  增加）会让整个 admission 视图变黑屏
- 外部脚本误改单条 proposal、partial migration 失败、brain admission decision 失败回滚到中间
  状态，都会导致一条坏行污染整张表
- Worker Admin UI / Fleet UI 的 brain 视图直接绑这两个 endpoint，UI 层会出现"所有 proposal
  都消失"的灾难性表现

## Scope of Fix（建议）

1. `packages/core/src/worker/brain/admission/service.ts` 的 `list` / `get` 路径用 per-row
   `safeParse` 替代整体 `parse`，单条失败时 skip 并记 reason
2. CLI / REST 输出统一加 `skipped` 字段，UI 用此字段渲染 toast 警告
3. 失败 row 推送到 audit log（`audit_events` 已有 fleet 侧；worker 侧可走 worker.db）
