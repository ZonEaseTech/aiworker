# BUG-033 CLI/gateway integration tests can leak gateway processes on timeout

- **status**: completed
- **priority**: P1
- **owner**: Unassigned
- **createdAt**: 2026-04-28 20:24
- **discoveredAt**: 2026-04-28 20:24
- **releaseTarget**: `@zonease/aiworker-cli@0.4.4`
- **bkd**: x6936h4q

## Description

The reliability subtask observed a local gateway process and temporary
directory left behind after a timed-out workspace test path.

Observed behavior:

1. After a flaky workspace test rerun, an orphaned
   `bun ... apps/cli/dist/aiworker.js gateway start --port <random>` process
   remained.
2. The process cwd was a temporary gateway directory matching
   `/tmp/aiworker-gateway-default-*`.
3. The subtask stopped the process and removed the temp directory during
   cleanup.
4. The leak was observed once after the timed-out workspace path and was not
   seen after focused tests or smoke scripts.

## Acceptance Criteria

1. CLI/gateway integration tests register cleanup handlers that terminate
   spawned gateway and worker processes on success, failure, and timeout.
2. Test temp directories containing credentials, DBs, or logs are removed after
   timeout paths.
3. Add a regression check that intentionally aborts or times out the relevant
   helper and verifies no listener/process remains.
4. Document any intentionally retained artifact directory and ensure it never
   contains secrets.

Ensuring gateway integration tests clean up spawned processes on timeout
