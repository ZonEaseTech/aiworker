## Context

Before REL-024, `main` was synchronized with `origin/main` and contained five
commits after the 0.9.7 release:

- Markdown Soul Pack migration.
- Cohere Web UI redesign.
- File-first Brain Skill runtime loading and memory search context loading.
- `brain-skill-add` admission materializer.
- Governance harness coverage for Brain Skill admission roundtrip.

At the start of the release, npm latest was `0.9.7`, and no `v0.10.0` tag
existed. Because this is user-visible worker behavior and product-surface
change under `0.x`, the next release was `0.10.0`.

## Scope

- Bump `apps/cli/package.json` and README latest to `0.10.0`.
- Run local release gates.
- Build and inspect CLI dist artifacts.
- Run publish dry-run up to the local npm authentication boundary.
- Commit the release bump.
- Create and push annotated tag `v0.10.0`.
- Monitor the tag-triggered release workflow.
- Verify npm latest, package version smoke, GitHub Release assets.
- Run published-package `cli-release-local` compact Governance Kernel harness.

## Out of Scope

- No feature code changes.
- No release workflow changes.
- No remote fleet upgrade unless the published-package validation passes first.
- No `policy-update` materializer.

## Acceptance Criteria

1. Local release gates pass.
2. `main` and `v0.10.0` are pushed.
3. GitHub Actions release workflow succeeds.
4. npm latest resolves to `0.10.0`.
5. `bunx @zonease/aiworker-cli@0.10.0 --version` reports `aiworker/0.10.0`.
6. GitHub Release `v0.10.0` exists with four binary assets.
7. Published-package compact governance harness passes and is recorded in QA.
