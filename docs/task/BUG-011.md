## Description

FEAT-030 acceptance criteria #9 与 README Quickstart 承诺：OTP 路径
worker 部署只需 `AIWORKER_GATEWAY_URL`（必）+ 可选 `AIWORKER_DISPLAY_NAME`，
其余 secret 由首次启动自动 mint 写 `~/.aiworker/.env`。

但 2026-04-27 10:35 在本机用 `bun apps/cli/dist/aiworker.js serve` 跑端到端验证时
（仅 export 上述 2 个 env + `AIWORKER_HOME=/tmp/...` 隔离目录），实测立刻报：

```
ERROR  unable to open database file
   at new Database (bun:sqlite:260:28)
```

因为 `packages/core/src/config/worker.ts:33`：

```ts
WORKER_DB_PATH: z.string().default('/var/lib/aiworker/worker.db'),
```

dev / 非 root 用户写不了 `/var/lib/aiworker`。补 `WORKER_DB_PATH=/tmp/.../worker.db`
后第二个错误冒出：

```
ERROR  Can't find meta/_journal.json file
```

因为 `WORKER_MIGRATIONS_FOLDER` 默认走 `defaultWorkerMigrationsFolder`，
后者通过 `import.meta.url` 解析 `@zonease/aiworker-storage-sqlite/drizzle/worker`，
**bundle 后**（`bun build --target=bun --minify`）`import.meta.url` 指向 dist 路径，
解析不到 drizzle 目录。npm-installed 场景同样有这个问题（drizzle 目录是否打到包里
未验证；即便打了，也要 `import.meta.url` 走 npm 的 node_modules 实路径才行）。

最终能跑通的命令实际是：

```bash
AIWORKER_HOME=/tmp/aiw-x \
WORKER_DB_PATH=/tmp/aiw-x/worker.db \
WORKER_MIGRATIONS_FOLDER=/path/to/source/packages/storage-sqlite/drizzle/worker \
AIWORKER_GATEWAY_URL=wss://gateway.example.test/ws \
bun apps/cli/dist/aiworker.js serve --port 19217
```

—— 仍是 4 个 env，不是 README 承诺的 2 个。

### Acceptance criteria

1. **`WORKER_DB_PATH` 加 lazy default**：当 env 未设时 fallback 到
   `<AIWORKER_HOME>/worker.db`（与 BUG-001 给 `WORKER_DATA_ROOT` 加
   `<AIWORKER_HOME>/data-root` lazy default 同思路）。容器 / systemd 仍可
   显式覆盖到 `/var/lib/aiworker/worker.db`。
2. **`WORKER_MIGRATIONS_FOLDER` bundle / npm 场景修复**：
   - 验证 `bun publish` 的 `dist/package.json` `files` 字段是否含 drizzle 目录
   - 若否，把 drizzle/worker + drizzle/fleet 拷进 `apps/cli/dist/drizzle/`
     （在 `apps/cli/scripts/build-publish-manifest.ts` 里加），`defaultWorkerMigrationsFolder`
     改成相对 `import.meta.url` 找 `./drizzle/worker`，bundle 后能命中
   - 或者：把 migrations 内嵌为 string array（drizzle migrator 支持
     `migrationsTable + migrations` 内存模式），彻底干掉对 fs 路径的依赖
3. README Quickstart OTP 流再次精简到只剩 `AIWORKER_GATEWAY_URL` + 可选
   `AIWORKER_DISPLAY_NAME`，并加 e2e smoke 验证（无显式 `WORKER_*` env 跑通）。
4. （建议）写一个 `scripts/smoke-quickstart.sh`：在干净 `/tmp/...` 跑
   `bun apps/cli/dist/aiworker.js serve --gateway wss://...` 直到看到
   `gateway-client connected` 为止，CI 跑住。
