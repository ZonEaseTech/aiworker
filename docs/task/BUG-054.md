# BUG-054 `aiworker brain brief` emits spurious `undefined: not found` artifact line when no `--artifact` is passed

- **status**: completed
- **priority**: P2
- **owner**: aiworker-maintainer
- **createdAt**: 2026-05-04 22:15
- **discoveredAt**: 2026-05-04 22:15
- **completedAt**: 2026-05-05 02:00
- **plan**: PLAN-107
- **relatesTo**: PLAN-102, FEAT-054

## Observed Behavior

干净 init 过的 project（developer Soul），不传 `--artifact` 直接跑：

```bash
aiworker brain brief --task "调试本地 worker.db 写入异常"
```

输出 sections 中含 `artifact-summary` 段，body 为：

```text
# Referenced artifacts (redacted)
- undefined: not found in brain artifact registry
  _All requested artifacts were missing or unreadable._
```

对照：传 `--artifact missing-1 --artifact missing-2` 时 body 正常输出对应 id：

```text
# Referenced artifacts (redacted)
- missing-1: not found in brain artifact registry
- missing-2: not found in brain artifact registry
  _All requested artifacts were missing or unreadable._
```

说明 CLI 在 `artifactRefs` 数组为空时仍然向 compiler 传了 `[undefined]`，而不是空数组或不调用
artifact-summary section。

## Expected Behavior

不传 `--artifact` 时任一：

1. brief sections 不含 `artifact-summary` 段（最小变动）
2. 或 body 文案改成 `_未指定 artifact refs，本次 brief 不引用 artifact registry。_`

不应当出现字面 "undefined"。

## Source Code Root Cause（待确认）

CLI 解析 `--artifact` 重复参数时 `cac` 默认行为：未传时是 `undefined`，传一次是单值，
传多次是数组。CLI 包裹逻辑应当：

```ts
const artifacts = Array.isArray(opts.artifact)
  ? opts.artifact
  : opts.artifact ? [opts.artifact] : []
```

而当前实现疑似传了 `[opts.artifact]`（即 `[undefined]`）。在 `apps/cli/src/commands/worker/brain.ts`
`brain brief` 子命令需要做空处理。

## Scope of Fix（建议）

1. CLI 层：`apps/cli/src/commands/worker/brain.ts` 的 `brain brief` 子命令，在调用
   `BrainBriefCompiler.compile` 前规范 artifactRefs（filter undefined / empty string）
2. core 兜底：`BrainBriefCompiler` 输入 zod schema 也应过滤掉 undefined / empty 元素，避免
   未来其它 caller 漏处理
3. 测试：现有 PLAN-102 进度记录有 `CLI brief 6 个 case`，新增"不传 --artifact 时 sections 不
   含 artifact-summary"的快照 case
