## Background

The shared composer already deduplicated duplicate files inside a single paste
event, but the Worker Web follow-up composer appended every selected file to
its attachment state. Selecting or pasting the same file/image across multiple
events created duplicate preview cards and duplicate submitted materials.

## Acceptance Criteria

- File and image attachments are deduplicated across repeated add events.
- Deduplication works for file picker, paste, and mixed entry paths consumed by
  the follow-up composer.
- Duplicate attachments do not create extra preview URLs or submitted material
  records.
- Existing submit, remove and clear-after-submit behavior remains intact.

## Completion

Completed in `PLAN-384`:

- Added attachment-state deduplication in `SessionTurnComposer`.
- Reused the same `name:size:type` identity used by shared paste dedupe.
- Added a WorkerStudio regression covering repeated file selection before
  follow-up submit.
