# BUG-036 Codex executor returns app-server reconnect error during fleet validation

- **status**: in_progress
- **priority**: P1
- **owner**: Codex
- **createdAt**: 2026-04-29 10:01
- **discoveredAt**: 2026-04-29 10:04
- **plan**: PLAN-037
- **releaseTarget**: post-`@zonease/aiworker-cli@0.4.5`

## Description

During the `BUG-035` post-fix fleet validation, a temporary local worker using
`executor=codex/default` successfully stayed online, received an OTP, and was
approved into the test fleet. The first real `aiworker chat` turn against that
worker was accepted by the gateway, but the worker emitted `agent.done` with
`finishReason=error` and no assistant answer. A second turn on the same explicit
conversation id failed the same way.

Sanitized observed shape:

```text
accepted conversationId=<explicit-gateway-conversation-id>
chat.message role=user content=<redacted-or-empty>
done finishReason=error

[conversation] classifier error, defaulting to continue: Error: Reconnecting... 2/5
[orchestrator] executor error: Reconnecting... 2/5
```

The worker stayed online throughout this check, so this is separate from the
`aiworker serve` foreground lifecycle fixed by `BUG-035`.

## Expected Behavior

A `codex/default` worker that has joined the fleet should complete real chat
turns with `finishReason=stop` and stream an assistant response. Explicit
conversation id reuse should be able to prove continuity after the first turn
stores a marker.

## Root-Cause Candidate

Unknown. The immediate error string comes from the local Codex app-server path
used by `CodexExecutor`; local `codex-cli 0.125.0` is installed and exposes
`codex app-server`, but the app-server-backed turn fails with a reconnect
error during validation.

## Reproduction Steps

1. Create isolated local worker state outside the repository.
2. Configure the worker with
   `{ "executor": { "engine": "codex", "variant": "default" } }`.
3. Start `aiworker serve` against the test fleet in OTP mode.
4. Approve the OTP from an operator connected to the same fleet.
5. Send `aiworker chat <worker-id> <marker prompt> --conversation-id <id>`.
6. Observe `finishReason=error` and local Codex app-server reconnect logs.

## Acceptance Criteria

1. Identify whether the reconnect error is caused by local Codex auth/network
   state, Codex CLI protocol handling, or AIWorker executor lifecycle code.
2. Add a focused regression at the narrowest reproducible layer.
3. Re-run the test-fleet local Codex worker path:
   - OTP enrollment and approval;
   - explicit conversation id continuity;
   - default accepted-id continuity;
   - reset rotation;
   - `sessions list/show` metadata checks.
