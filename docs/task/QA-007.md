  `qualityGate.configuredMode=observe`,

### Admission 状态机 + secret 治理（BUG-061 / BUG-068 / BUG-074 / TODO-012 修复确认）

- CLI `aiworker brain admission propose` is now a first-class command
  (no `--i-know-this-is-debug` flag required).
- Full state machine verified against `worker.db`:
  pending → approved → applied (dry-run preview shows `secretScan
  policy=block, action=allow-clean`) → applied (commit) writes the
  body to `.aiworker/memories/<topic>.md` and appends an index line to
  `MEMORY.md`. Re-applying an applied proposal returns
  `cannot apply proposal "<id>" with status "applied" (must be
  "approved")`. Rejected proposals likewise refuse apply.
- Unsupported-kind path (`policy-update`) lands a real audit row in
  `brain_admission_decisions` with
  `decision=failed,
   failure_reason="MVP materializer only supports memory-add; kind
   \"policy-update\" requires manual follow-up"`.
- Secret-scan default policy=`block`: a fixture proposal whose
  payload.body contains `apiKey=sk-LIVE-...\nbearer=eyJabc` lands as
  `kind=blocked-by-secret-scan` and the target memory file does NOT
  exist on disk. Re-applying with `--allow-secret-body redact`
  rewrites the body to `apiKey=[REDACTED:sk-token]\nbearer=eyJabc`.
- Secret-scan rule set in 0.9.0 covers at least four classes:
  `sk-token`, `github-token` (`ghp_*`), `aws-access-key`
  (`AKIAIOSFODNN7EXAMPLE`), `jwt`
  (`eyJhbGciOiJIUzI1NiJ9.aaaaa.bbbb`). All four are inline-redacted
  in default `brain admission show` and in REST
  `/api/worker/brain/admission/<id>` responses (BUG-061 partial-redact
  is comprehensively fixed; TODO-012 is closed in spirit).
- Plaintext reveal requires both `AIWORKER_ADMIN_REVEAL=1` in the
  worker process env and `--show-sensitive` on the CLI. Either alone
  emits `WARN [aiworker brain admission show] --show-sensitive
  ignored: set AIWORKER_ADMIN_REVEAL=1 in the worker process env to
  unlock plaintext` and keeps payload redacted.
- Multi-turn turn 8 ("propose user preference as long-term memory")
  produced a real DB row `user-pref-zh-tldr|pending|memory-add|
  memories/user-preferences` on dev-cc and `prefer-cn-tldr|pending|
  memory-add|memories/user-communication-preferences` on dev-cx. LLM
  self-report ("Admission proposal 已提交，状态为 pending，等待
  operator 审批") matches DB authoritative state, eliminating BUG-074
  hallucination.
- developer-cc REST `/api/worker/brain/summary` exposes the new
  bypass-risk telemetry: `admissions.bypassRisk.{recentCount, status}`.
  This is the operator-facing observability surface that closes
  BUG-068.
