# BUG-051 Preserve hyphenated executor MCP arg values

- **status**: pending
- **priority**: P3
- **owner**: unassigned
- **createdAt**: 2026-05-03 23:33
- **discoveredAt**: 2026-05-03 22:28
- **plan**: PLAN-080

## Observed Behavior

`aiworker executor mcp add` supports repeated `--arg <value>` for stdio MCP
commands. Passing a hyphenated command argument as two tokens fails:

```bash
aiworker executor mcp add filesystem-probe \
  --engine codex \
  --transport stdio \
  --command npx \
  --arg -y
```

The CLI reports:

```text
ERROR Unknown option -y
```

The workaround is to use equals form:

```bash
--arg=-y
```

## Expected Behavior

Operators should be able to pass common stdio command arguments such as `-y`
without discovering parser-specific escaping rules by trial and error, or the
help/error output should clearly tell them to use `--arg=-y` / `--arg -- -y`.

## Acceptance Criteria

1. Decide whether to support `--arg -y` directly or document/enforce a clear
   passthrough form.
2. Keep existing repeated `--arg=value` behavior.
3. Add focused CLI coverage for hyphenated stdio MCP arguments.
4. Update command help or docs if the supported syntax remains equals-only.
5. Ensure the fix does not loosen unknown-option validation for the rest of
   the CLI.

## ActiveForm

Improving executor MCP stdio argument UX for hyphenated values.
