# BUG-135 Web approval and session parent navigation regressions

- **status**: completed
- **priority**: P0
- **owner**: codex
- **createdAt**: 2026-05-18
- **claimedAt**: 2026-05-18
- **plan**: PLAN-356
- **relatesTo**: FEAT-096, REFACTOR-080, PLAN-354, apps/web

## Background

After the `0.17.2` Web release, two user-visible regressions were reported:

1. Web profile patch review can fail to provide an enabled path to approve a
   valid README write.
2. The session route has no direct parent navigation back to the workspace /
   Soul workbench surface.

## Investigation Notes

- Profile patch approval is currently gated by `changedSectionCount > 0`. That
  only counts recognized HR README `##` sections. A valid promotable README
  patch whose change is document-level, title-level, intro-level or otherwise
  not represented by recognized sections can become ready but unapprovable.
- Real Ben workspace smoke also showed the native HR `person-profile` artifact
  can be an unfenced proposal artifact. The Web review path must therefore let
  the HR product synthesize a canonical accepted README instead of requiring the
  native skill to emit `aiworker-profile-readme` fenced markdown.
- Session routes intentionally removed Host-level workspace navigation during
  Host shell V9 cleanup, but the resulting session page has no visible
  same-surface parent return control.

## Acceptance Criteria

- A ready profile patch can be approved whenever the promotable README content
  differs from the current README, even if no recognized HR section changed.
- Profile Patch Review still renders a readable current/proposed comparison for
  document-level README changes.
- Session routes expose a clear direct control back to the parent workspace /
  Soul workbench route.
- Existing Host shell V9 and Soul workbench boundaries remain unchanged.
- Focused Worker Studio and HR model tests cover both regressions.

## Resolution

- HR Profile Patch Review now supports both fenced README drafts and unfenced
  HR `person-profile` artifacts by synthesizing a canonical accepted README in
  product-owned logic.
- Document-level README changes fall back to a full-document diff row when no
  canonical section-level diff is available.
- The synthesized README is passed to the profile promotion API as explicit
  `profileMarkdown`, so the server promotion gate still validates the accepted
  markdown rather than trusting raw proposal text.
- Session routes now expose a header icon button that returns directly to the
  parent workspace route.
