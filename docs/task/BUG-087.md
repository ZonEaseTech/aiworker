# BUG-087 Codex executor hard cap ignores longer validation turn budget

- **status**: completed
- **priority**: P1
- **owner**: local
- **createdAt**: 2026-05-07 13:35
- **claimedAt**: 2026-05-07 13:35
- **completedAt**: 2026-05-07 14:11
- **plan**: PLAN-159
- **relatesTo**: QA-020, PLAN-158, REL-024

## Problem

QA-020's `worker-source-local --matrix full --timeout-ms 240000` run failed on
two Codex pairs:

- `hr-recruiting-codex turn 6`
- `finance-ops-codex turn 5`

Both failed after roughly 120s with `codex child exited unexpectedly`. The
harness passed `aiworker run --timeout-ms 240000`, but the Codex executor
adapter still used the `codex/default` profile hard cap of 120000ms.

## Impact

- Operator-facing `aiworker run --timeout-ms` can wait longer than the
  selected executor is allowed to run.
- Long-running Codex turns in non-developer Souls can fail before the outer
  turn budget expires.
- Governance harness full-matrix evidence cannot be made smooth without
  manually editing worker config internals.

## Expected

Operators and harnesses must be able to set the selected executor profile's
per-turn hard timeout through the public CLI surface.

## Acceptance Criteria

1. `aiworker executor select --timeout-ms <n> --apply` persists
   `executor.overrides.timeoutMs`.
2. `aiworker worker executor select --timeout-ms <n> --apply` supports the
   same option.
3. The Governance Kernel harness sets the executor timeout to its per-turn
   `--timeout-ms` budget when selecting Codex / Claude Code.
4. Focused CLI tests and full source matrix validation pass.

## Notes

- 2026-05-07 13:35: Opened from QA-020 failure triage. The failure signature
  is adapter timeout mismatch, not a Brain admission or Soul semantic failure.

## Resolution

- Added `--timeout-ms <n>` to `aiworker executor select` and
  `aiworker worker executor select`.
- Persisted the value as `executor.overrides.timeoutMs`, which is already
  consumed by the Codex and Claude Code executor factories.
- Updated the Governance Kernel harness so each pair's executor profile uses
  the harness per-turn timeout budget.
