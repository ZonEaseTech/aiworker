## Problem

AIWorker now has enough Project Brain, executor-boundary, native skill, admission,
and Worker/Fleet governance behavior that future implementation sessions can
drift in several dangerous directions:

1. Rebuilding executor-native tool loops, plugins, sandbox, approvals, sessions,
   or model routing inside AIWorker.
2. Treating Project Brain as a generic memory bank instead of a governed
   customer-owned scope asset.
3. Narrowing Project to software repositories and PMA-only workflows.
4. Turning admission and audit into high-friction confirmation prompts instead
   of risk-based Brain governance.

The repository has the necessary facts spread across README, architecture, and
governance status docs, but it does not have one concise north-star contract
that every future development session can use before touching Brain, Executor,
Soul, Fleet, scope, memory, or capability surfaces.

## Expected

Add a root-level product north-star document and wire it into agent/developer
entry points so future sessions can quickly answer what AIWorker exists to do,
what it must not do, and how to test whether a proposed feature belongs here.

## Acceptance Criteria

1. `GOALS.md` exists at the repository root and defines AIWorker's product
   thesis, goals, non-goals, architecture commitments, and future decision tests.
2. `AGENTS.md` points future development sessions to `GOALS.md` before changing
   Brain / Executor / Soul / Fleet / scope / memory / capability behavior.
3. `docs/architecture.md` identifies `GOALS.md` as the product north star while
   keeping architecture as the implementation contract.
4. PMA task / plan / changelog / index state is synchronized.
5. Validation covers markdown formatting / trailing whitespace.
