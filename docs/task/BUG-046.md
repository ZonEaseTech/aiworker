# BUG-046 Executor tiny probe can hang beyond the configured timeout

- **status**: completed
- **priority**: P2
- **owner**: local
- **createdAt**: 2026-05-02 20:39
- **discoveredAt**: 2026-05-02 20:30

## Observed Behavior

On the Worker Admin Test page, `Test executor` without the tiny probe returned
healthy quickly. After enabling `Tiny probe`, the button entered a pending
state and stayed disabled well beyond the configured 5 second probe timeout.
The worker server did not log a completed `POST /api/worker/executor/test`
within the observed window.

Relevant code pointers:

- `packages/core/src/worker/management/executor-test.ts` sets
  `PROBE_TIMEOUT_MS = 5_000` and aborts the probe signal.
- `apps/web/src/worker/features/test/test-panel.tsx` disables the action while
  the mutation is pending and has no visible timeout/cancel fallback.

## Expected Behavior

The tiny probe should always settle within the configured timeout budget plus a
small response overhead. If the executor does not honor abort promptly, the API
should still return a degraded/timeout result and the UI should recover.

## Reproduction

1. Start a local worker with the Codex executor.
2. Open authenticated Worker Admin Test.
3. Enable `Tiny probe`.
4. Click `Test executor`.
5. Observe the button remaining pending past the 5 second probe timeout.

## Acceptance Criteria

1. Tiny probe requests return a success or degraded timeout result within a
   bounded interval.
2. Executor adapters used by the probe honor abort or are wrapped by a hard
   timeout at the management API boundary.
3. The UI re-enables the button and shows an actionable timeout/error state.
4. Focused tests cover an executor stream that ignores abort.
