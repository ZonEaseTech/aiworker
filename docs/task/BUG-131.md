## Background

The follow-up real profile proposal run produced an
`aiworker-profile-readme` fenced draft, but the draft's `Review State` said
that promotion was requested and still pending human review. That language is
correct for proposal notes, but it is not a clean accepted-profile state once
the product promotes the fenced draft into `README.md`.

## Root Cause

The HR profile proposal skill allowed the fenced draft to describe a requested
promotion state. The product contract needs the fenced block to represent the
post-approval accepted README state; pending review and requested decision
language belongs outside the fence.

## Resolution

Strengthened the HR profile proposal skill, workflow prompt, and review rubric
so the fenced `aiworker-profile-readme` draft must read as the accepted profile
after approval, while proposal/review-decision language stays outside the
promotable block.

## Verification

- Re-run a real profile proposal continuation turn before promotion.
- Verify the fenced draft no longer contains `promotion requested`, `pending
  human review`, or equivalent proposal-state language before invoking product
  promotion.
