# BUG-024 Codex executor fails against current Codex app-server protocol

- **status**: completed
- **priority**: P1
- **owner**: Codex
- **createdAt**: 2026-04-28 10:40
- **claimedAt**: 2026-04-28 10:40
- **completedAt**: 2026-04-28 10:50
- **plan**: PLAN-026

## Description

The `v0.4.0` release and test-server gateway upgrade succeeded, but the
requested real e2e check with a local worker configured for the Codex executor
failed. The worker joined the test fleet through OTP enrollment and reported
`executor=codex/default`, but `aiworker chat` completed with
`finishReason=error`.

Local worker logs showed that installed `codex-cli 0.125.0` rejects the legacy
`thread_start` request:

```text
Invalid request: unknown variant thread_start
```

The current app-server protocol uses `thread/start` and `turn/start`, and emits
notifications such as `item/agentMessage/delta`, `thread/tokenUsage/updated`,
and `turn/completed`. The existing executor only supports the older
`thread_start` / `newTurn` protocol and `codex/event/*` notifications. The
default Codex model is also stale for the current ChatGPT-backed Codex account.

## Acceptance Criteria

1. Codex executor keeps legacy `thread_start` / `newTurn` support.
2. Codex executor falls back to current `thread/start` / `turn/start` when the
   legacy thread-start request is rejected by current Codex CLI.
3. Current app-server notifications are normalized into shared `AgentEvent`s.
4. The Codex default model and Web model hints use a model accepted by current
   Codex CLI.
5. Focused Codex executor tests cover both protocol variants.
6. Publish a patch release (`0.4.1`) and rerun the test-server fleet +
   local Codex worker e2e chat successfully.

## Dependencies

- **blocked by**: BUG-023 release flow
- **blocks**: local Codex worker e2e validation after `v0.4.0`

## Completion Notes

Implemented the compatibility fix and released it as `v0.4.1`:

1. Codex executor keeps the legacy `thread_start` / `newTurn` path.
2. Current Codex CLI rejection of `thread_start` triggers fallback to
   `thread/start` and `turn/start`.
3. Current Codex notifications are normalized into shared `AgentEvent`s:
   assistant deltas, reasoning deltas, token usage, turn completion, and error
   notifications.
4. Codex default model metadata now uses `gpt-5.5`, and the Worker Web config
   catalog hints current Codex models.
5. Focused tests cover both Codex protocol variants.
