# BUG-075 quality_gate evaluator=llm fails because LLM call receives empty stdin and retries exhaust to heuristic fallback

- **status**: completed
- **priority**: P2
- **owner**: local
- **createdAt**: 2026-05-05 19:30
- **discoveredAt**: 2026-05-05 19:23
- **completedAt**: 2026-05-06
- **plan**: PLAN-123
- **relatesTo**: BUG-066, BUG-067, QA-007, PLAN-122

## Observed Behavior

After enabling LLM-backed quality gate via `aiworker config set` with
`orchestrator.decisionPipeline.qualityGate = {"evaluator":"llm","gateMode":"warn"}`,
`brain status` correctly reflects `qualityGate.evaluator=llm,
configuredMode=observe`. However, when running a real LLM turn the actual
quality-gate decision event reports:

```
"orchestrator.quality_gate" payload:
  evaluator: "heuristic"             ← fallback, not llm
  reason:    "llm-retry-exhausted: Error: Claude Code exited with code 127"
  action:    "pass"
  score:     8 (heuristic threshold)
```

Per fake-claude shim dumps captured during the same run, the AIWorker
quality-gate evaluator did issue two LLM calls (matching the configured
retry policy), both with the correct review system prompt:

```
--append-system-prompt 'Review an AIWorker assistant answer.
  Return only strict JSON: {"score":0..10, "threshold":number,
  "dimensions":{...}, "missing":[...], "suggestions":[...],
  "action":"pass|repair|warn|block", "reason":"short"}'
```

But the STDIN section in both quality-gate dumps is empty — no assistant
answer body, no message envelope, no JSON Lines stream. With empty stdin
plus `--input-format=stream-json`, the engine has nothing to review and
exits with status 127 (interpreted by the AIWorker side as "Claude Code
exited with code 127"). After the configured retry budget is exhausted,
the evaluator falls back to heuristic and the decision is recorded with
`evaluator: "heuristic"` and a truthful `reason` that pinpoints the
underlying retry failure.

In contrast, the intent classifier evaluator works correctly under the
same configuration: dumps show non-empty stdin carrying the recent
conversation snippet, the LLM returns valid JSON on the second attempt
(`attempt: 2`), and the resulting event has
`source: "intent-llm", evaluator: "llm", confidence: 0.92`.

## Expected Behavior

When `qualityGate.evaluator = "llm"` is configured:

1. The quality-gate evaluator must assemble a non-empty stdin for the
   engine call, including at minimum the assistant answer body to be
   reviewed and any required dimensions context.
2. The first LLM call should succeed often enough that the evaluator
   does not silently fall back to heuristic on every turn.
3. If the LLM call still fails, `quality_gate.evaluator` must remain
   honest about the fallback, which is already the case in 0.9.0.

## Source Code Root Cause (suspected)

The quality-gate prompt assembly path is sending only the system prompt
via `--append-system-prompt` and is omitting the assistant answer
envelope on stdin. The intent classifier path correctly serializes the
recent-message context as a `{"type":"user","message":...}` JSON line
and exits — that path should be the reference implementation for the
quality-gate evaluator.

## Scope of Fix

### P2

1. Locate the quality-gate LLM evaluator prompt assembly in the
   AIWorker runtime; ensure the assistant answer (and any expected
   dimensions context) is serialized into a JSON Lines envelope on
   stdin, mirroring the intent classifier evaluator.
2. Add a runtime regression that snapshots stdin length for both the
   intent classifier and the quality gate when the corresponding
   evaluator is set to `llm`, so empty-stdin regressions are caught
   automatically.

### P3

3. Update `brain status` and `/api/worker/brain/summary` to surface a
   non-zero `samples` and `lastFallbackReason` when CLI `run` exercises
   the LLM evaluator (see TODO-028 for the related ring-buffer
   coverage gap).
