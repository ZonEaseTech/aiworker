# BUG-130 CLI session start misses app-authored capability assets

- **status**: completed
- **priority**: P0
- **owner**: codex
- **createdAt**: 2026-05-17
- **claimedAt**: 2026-05-17
- **completedAt**: 2026-05-17
- **plan**: PLAN-346
- **relatesTo**: apps/cli/src/aiworker.ts, apps/cli/src/aiworker.test.ts

## Background

`PLAN-345` added HostRuntime metadata enrichment for Soul App capability prompt
and review assets, and worker runtime materialization into
`.aiworker/sessions/<session>/context/capability/{prompt,review}.md`.

The follow-up real HR regression run found that the first `aiworker session
start` turn still did not receive `capabilityPrompt` or
`capabilityReviewRubric` in `session.metadataJson` or `invocation.metadataJson`.
The workspace only had `active-context.md` and `capability/SKILL.md`, while
`prompt.md` and `review.md` were missing.

## Root Cause

`turn send` used `HostRuntime.enrichTemplateMetadata(...)`, but `session start`
was still manually constructing metadata from template fields. The first turn
therefore bypassed app-authored capability asset enrichment.

## Resolution

`session start` now uses the same HostRuntime metadata enrichment path as
continuation turns for both session metadata and first-turn invocation metadata.

## Verification

- Added a CLI regression test that runs `app install -> app enable -> worker
  create -> workspace create -> session start` with a deterministic fake Codex
  command and asserts first-turn capability assets are materialized.
- Re-ran a real Codex-backed HR `evidence-matrix` session in an isolated
  debug home and confirmed:
  - `session.metadataJson.capabilityPrompt` exists,
  - `invocation.metadataJson.capabilityReviewRubric` exists,
  - `.aiworker/sessions/<session>/context/capability/prompt.md` exists,
  - `.aiworker/sessions/<session>/context/capability/review.md` exists,
  - invocation `prompt.md` includes the app-authored prompt and review rubric.
