# BUG-059 Admission `apply --commit` on unsupported kind leaves proposal stuck in `approved` with no audit row

- **status**: pending
- **priority**: P3
- **owner**: unassigned
- **createdAt**: 2026-05-04 22:25
- **discoveredAt**: 2026-05-04 22:25
- **plan**: TBD
- **relatesTo**: PLAN-101

## Observed Behavior

approve 一条 `kind != 'memory-add'` 的 proposal（PLAN-101 MVP 仅支持 memory-add），再
`apply --commit`：

```text
$ aiworker brain admission apply prop_qa_2 --decided-by qa-bot --commit
{
  "outcome": {
    "kind": "unsupported",
    "proposalKind": "policy-update",
    "reason": "MVP materializer only supports memory-add; kind \"policy-update\" requires manual follow-up"
  }
}
```

之后查 proposal：

- `proposal.status` 仍为 `approved`（没变）
- `brain_admission_decisions` 没有新增 `unsupported` 类型的决策行
- list `--status approved` 永远能看到这条悬空 proposal，无 followup

## Expected Behavior

unsupported 路径应当：

1. 写一行 decision row，`decision='skipped'` 或 `decision='unsupported'`，记录 `decided_by /
   decided_at / reason='unsupported-kind:<kind>'`
2. `proposal.status` 移到 `failed`（带 `failureReason='unsupported-kind:<kind>'`），让 list
   `--status approved` 不再看到悬空 row
3. operator 后续可显式 `aiworker brain admission reject <id>`（如果 operator 选择放弃），但
   这是另一条决策路径

## Scope of Fix（建议）

`packages/core/src/worker/brain/admission/service.ts` `apply` 方法：

- unsupported 分支前补写决策 row + 状态机迁移到 `failed`
- 现有"必须 status=approved 才能 apply"约束保留；rejected / failed 仍不可 apply

测试新增："unsupported kind apply 后 proposal.status === 'failed' 且 decisions[0].reason 含
unsupported-kind"。
