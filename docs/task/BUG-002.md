# BUG-002 aim pair must persist gatewayUrl to aim.json

## Description

`aim pair --url ws://<host>:<port>/ws ...` succeeds (writes the device token
to fleet.db, returns workerId), but `apps/cli/src/aim/commands/pair.ts:30-33`
only persists `deviceToken` and `defaultWorkerId` to
`~/.aiworker/aim.json`. The `--url` argument is never written back. Every
subsequent `aim` command (`workers list`, `chat`, `config get`, ...)
re-reads `aim.json` and dials the **default** `ws://localhost:3000`, which
fails with `WebSocket connection ... failed: Expected 101 status code` on
any non-default port.

Operators currently work around this by hand-editing `aim.json` after
pairing. `aim gateway start` already writes back `gatewayUrl` after starting
the local daemon (`docs/cli.md:226-229`); pair should follow the same
contract.

### Acceptance criteria

- After `aim pair --url ws://127.0.0.1:20300/ws ...` succeeds, `aim.json`
  contains `gatewayUrl: ws://127.0.0.1:20300/ws`.
- When `--url` is omitted, behaviour is unchanged (existing `gatewayUrl`
  persists).
- `aim workers list` immediately after pair works without manual JSON edits.
- File mode `0600` on `aim.json` is preserved.

## ActiveForm

Persisting --url to aim.json after pair

## Notes

Implementation is one extra field in the `patchAimState` call:
```ts
await patchAimState({
  ...(opts.url === undefined ? {} : { gatewayUrl: opts.url }),
  deviceToken: result.deviceToken,
  defaultWorkerId: result.workerId,
})
```
