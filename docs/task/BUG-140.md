# BUG-140 Split Soul App configuration from Host platform settings

- **priority**: P0
- **owner**: codex

## Background

The current architecture already says Host settings and Soul App settings have
different ownership. Host owns platform settings such as execution mode,
language, appearance, engine, MCP and connector grants. Soul Apps own
app-specific configuration exposed through protocol.

The implementation still leaks the boundary in two ways:

- the shared manifest contract names the app-owned descriptor
  `ui.workbench.settings`, which keeps the same product word as Host settings;
- the HR workbench invokes the app-owned `HR settings` action and then opens the
  Host `SettingsDialog`, so a Soul App configuration entry visually and
  behaviorally falls back into Host platform settings.

## Scope

- Rename the app-owned workbench descriptor from `settings` to
  `configuration`.
- Rename app-owned workbench role handling from `settings` to `configure`.
- Keep `/api/local/settings` as the Host platform settings API.
- Update official HR/QA manifests, shared fixtures, scaffold output and mounted
  handlers to use app-owned configuration wording.
- Update Worker Web so app-owned configuration actions invoke protocol and do
  not open the Host settings dialog.
- Rename user-facing Host settings copy toward Platform Settings where the
  fixed Host shell is opening platform/global preferences.
- Update architecture and authoring docs with the three-layer settings
  boundary.

## Non-goals

- Do not add real HR/QA domain configuration persistence in this slice.
- Do not redesign the Host settings dialog layout.
- Do not add backward-compatible legacy `ui.workbench.settings` shims before
  1.0.0.
- Do not change session execution, artifact/profile/review behavior, or broker
  semantics.

## Acceptance

1. A Soul App workbench configuration descriptor is named
   `ui.workbench.configuration` and uses `role: "configure"` inside Worker Web.
2. Clicking HR app configuration invokes the HR mounted protocol action and
   does not open the Host settings dialog.
3. Fixed Host settings entries clearly open Platform Settings.
4. Shared manifest validation, official HR/QA fixtures/manifests, scaffolded
   apps, daemon action resolution, security review and Worker Web tests agree
   on the new contract.
5. Architecture, Soul App authoring docs and PMA records document the boundary
   change.
6. Focused tests, UI governance, docs checks, code-review-graph review and
   relevant package gates pass before closeout.

## Record

- 2026-05-19 20:19 CST: User identified that Host-initiated settings and
  Soul-initiated settings currently read as the same boundary. Investigation
  confirmed that docs split ownership, but HR workbench app settings currently
  falls through to the Host `SettingsDialog`.
- 2026-05-19 20:29 CST: Landed the contract split. Soul App workbench
