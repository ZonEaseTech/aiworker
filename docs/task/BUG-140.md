## Background

`FEAT-103` added the first Codex CLI activity parser and shared composer media
preview support, but review feedback exposed three visible gaps:

- status, artifact and review events still appeared as separate raw timeline
  pills instead of a Codex Desktop-style condensed activity signal;
- usage was rendered in the chat timeline instead of being connected to the
  composer surface;
- the active session follow-up composer consumed the shared shell but did not
  expose the default file/image input capability.

## Acceptance Criteria

- Codex CLI status/output events collapse into compact session signal rows
  rather than raw `status running` or repeated artifact/review pills.
- Usage is removed from the timeline stream and shown through the active
  composer action bar.
- Session follow-up composer exposes the same default file/image attachment
  input as the new-session composer.
- Follow-up attachments are persisted into workspace source-material files and
  referenced from the submitted turn prompt and metadata.
- Right-panel/full detail composer reuses the same follow-up composer component.
- Focused component and WorkerStudio tests cover signal collapse, composer
  usage and follow-up file submission.
- UI governance, focused web gates and code-review-graph review pass before
  closure.

## Completion

Completed in `PLAN-379`:

- Added shared `signal` timeline events and collapsed status/output rendering.
- Added shared composer usage status support.
- Added `SessionTurnComposer` for active session follow-ups with file/image
  attachments and lightbox preview through the shared `SessionComposer`.
- Wired follow-up attachments through workspace file persistence and turn
  metadata.
- Added focused tests for parser signal collapse, composer usage and follow-up
  source material submission.
