## Background

The universal workbench was designed as a quick-start, composer-centered
workbench shared by Soul Apps: workspace/session navigation, session chat,
timeline/detail surfaces and `SessionComposer` should live in the
Soul-owned mounted micro-app surface.

Current behavior has regressed. `/micro-app/workbench/universal` renders a
static bridge-proof card that says the micro-app receives Host context, but it
does not mount `UniversalWorkbenchApp`, does not load a browser client bundle,
and cannot create or continue sessions.

Investigation found the regression path:

- `cfb4a6e8` created `packages/soul-app-workbench` and the real
  `UniversalWorkbenchApp` React tree.
- `de87ff37` added `renderUniversalWorkbenchHtml(...)`, but the helper only
  contained a placeholder comment where `root.render(...)` should have mounted
  the React app.
- `6a106397` correctly removed Host Web's direct
  `@zonease/aiworker-soul-app-workbench` import and made Host mount
  `universal-workbench` through micro-app like any other Soul-owned route.
- Because the mounted HTML helper was still a placeholder, official mounted
  services now expose that placeholder as the visible universal workbench.

## Acceptance Criteria

1. `/micro-app/workbench/universal` mounts the shared `UniversalWorkbenchApp`
   browser client instead of a static placeholder card.
2. The mounted universal workbench exposes the quick-start composer-centered
   flow: workspace/session navigation, session creation or selection, timeline
   and composer entry points.
3. Host Web remains boundary-clean: it does not import or render
   `@zonease/aiworker-soul-app-workbench` directly and does not branch on
   `universal-workbench`.
4. Soul App mounted services serve any needed universal workbench client asset
   through app-owned `/micro-app/*` or `/assets/*` routes.
5. Thin session proxy behavior is implemented or wired where the universal
   client needs it, without putting domain semantics in Host.
6. Focused runtime, official app and Worker Web tests cover the interactive
   mounted universal workbench path.

## Scope

- Universal workbench mounted HTML and browser client bootstrap.
- Runtime/app asset serving needed by official Soul Apps.
- Thin session API proxy wiring needed by the universal workbench client.
- Focused tests for runtime, official mounted services and Host Web boundary.
- PMA and changelog tracking.

## Non-Goals

- Do not reintroduce Host Web rendering of `UniversalWorkbenchApp`.
- Do not add Host-owned domain actions/search/configuration routes.
- Do not make HR route priority the primary bug in this task.
- Do not redesign the HR domain workbench.

## Resolution

`/micro-app/workbench/universal` now serves a mounted browser client that
renders the shared `UniversalWorkbenchApp` instead of the static bridge-proof
card. Official Soul Apps build and serve
`assets/universal-workbench-client.js`, and their mounted services wire the
thin universal workbench API proxy for templates, workspaces, sessions and
turns.

The Host remains a generic micro-app mount surface. Host Web does not import
or branch on `@zonease/aiworker-soul-app-workbench`.
