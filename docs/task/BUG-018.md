# BUG-018 CLI engine 子进程 env 白名单（剔除 AIWORKER_MASTER_KEY 等）

- **status**: implemented
- **priority**: P1
- **owner**: bkd/g7jivp8m
- **createdAt**: 2026-04-27
- **discovered**: 2026-04-27 — root issue `nnid9urk` 的代码评审。

## Description

四个 CLI engine（claude-code / acp / codex / cursor）以及通用 `cli` provider 在
spawn 子进程时把整段 `process.env` 透传给二进制：

```ts
env: { ...process.env, ...(this.options.env ?? {}) }
```

worker 进程 env 含 `AIWORKER_MASTER_KEY`（解 vault 主密钥）、`INTERNAL_SHARED_SECRET`
（gateway bearer）、`AIWORKER_JOIN_TOKEN`（self-enroll bearer）以及 operator
习惯放的各种 `*_TOKEN` / `*_SECRET` / `*_API_KEY`。CLI engine 的子进程只要 LLM
读一下 `process.env` / `/proc/self/environ` 就能把这些拿到 prompt 里——master
key 一旦泄漏就能解开 fleet/worker.db 全部加密数据。

`--dangerously-skip-permissions` 不动（运维明确希望 worker 长期不被打断），本
issue 只修 env 白名单。

## Implementation

### 共建 helper

新增 `packages/core/src/worker/executor/safe-env.ts`，单一入口
`buildSafeChildEnv(extra?)`：

- **passthrough exact**：`PATH` / `HOME` / `USER` / `LOGNAME` / `SHELL` / `PWD` /
  `LANG` / `TZ` / `TERM` / `TMPDIR` / `TMP` / `TEMP`
- **passthrough prefix**（合并所有 engine 需要的 namespace）：`LC_*` / `NODE_*` /
  `NPM_CONFIG_*` / `XDG_*` / `CLAUDE_*` / `CODEX_*` / `CURSOR_*` / `GEMINI_*` /
  `QWEN_*`
- **block prefix**：`AIWORKER_*` / `INTERNAL_*` / `WORKER_*`
- **block suffix**：`_TOKEN` / `_SECRET` / `_API_KEY` / `_PRIVATE_KEY` /
  `_PASSWORD`
- block 优先级最高，即便 passthrough 命中也强制剔除（防御纵深，例如 worker 进程
  envs 里临时塞过的 `*_API_KEY`）
- `extra` 由 engine config 显式提供，最后叠加在结果上——operator 想给 claude-code
  传 `ANTHROPIC_API_KEY` 时通过 worker config 走，不走 worker 进程 env 兜底

### 落点

- `packages/core/src/worker/executor/engines/claude-code/executor.ts:122`
- `packages/core/src/worker/executor/engines/acp/harness.ts:153`
- `packages/core/src/worker/executor/engines/codex/executor.ts:113`
- `packages/core/src/worker/executor/engines/cursor/executor.ts:110`
- `packages/core/src/worker/executor/providers/cli.ts:46,77`（health probe + invokeTool）

每处都从 `env: { ...process.env, ...this.options.env }` 改成
`env: buildSafeChildEnv(this.options.env)`。

### 测试

`packages/core/src/worker/executor/safe-env.test.ts` 覆盖：

1. locale / shell context vars 全透传
2. 各 engine prefix vars 全透传
3. `AIWORKER_*` / `INTERNAL_*` / `WORKER_*` 强制剔除
4. `*_TOKEN` / `*_SECRET` / `*_API_KEY` / `*_PASSWORD` / `*_PRIVATE_KEY` 强制剔除
5. 既不命中 passthrough 也不命中 block 的（如 `AWS_REGION`）默认 drop
6. `extra` 可以注入任意 secret-shaped 名字（operator 显式选择，不被 block list 拦）

## Notes

- `process.env[agent.versionEnvVar]`（`harness.ts:75`）是 worker 进程内读自己的 env
  来选 CLI 版本，不是 spawn 给子进程，安全无问题，没改。
- `extra`（来自 worker config 的 engine env 字段）允许带 secret-shaped 名字——这是
  operator 主动选择，不是默认行为；worker config 里 secret 仍然走 SecretsVault
  ref 占位 + 启动时 hydrate（CLAUDE.md 不变量）。
- 按 engine 取交集本可以更细（claude-code 用不上 `CURSOR_*`），但跨注入无安全风险
  （子进程不识别就忽略），单一 helper 让接入面最小。如果未来某个 engine 需要更严
  格的隔离，加 opt-in 参数即可。
