## Description

`aim config set <workerId> ... --if-match N` always returns
`method_not_implemented: config.put handler not wired`. Root cause:
`apps/cli/src/commands/serve.ts:50-61` registers `configGet`,
`tokenRotate`, and `cron*` handlers on `startGatewayNode`, but never
populates `configPut`. The gateway-client dispatcher
(`packages/core/src/worker/gateway-client/dispatcher.ts:203-211`) treats a
missing `configPut` handler as `method_not_implemented`.

The HTTP route `PUT /api/worker/config`
(`apps/api/src/worker/management/routes.ts:101-151`) already implements the
correct flow: `putConfig` → `mirrorConfigToYaml` → `reloadRuntime`. The
gateway-client handler must do the same. The blocker is that `serve.ts`
only receives `state` from `bootstrapWorkerApp`, not the `reloadRuntime`
closure — so the bootstrap surface needs to expose `reloadRuntime` too.

### Acceptance criteria

- `aim config set <workerId> '<json>' --if-match <correct-version>` returns
  the new `version` and `runtimeReload: ok` (or equivalent), no longer
  `method_not_implemented`.
- `aim config set ... --if-match <wrong-version>` returns a
  `version-conflict`-class error (mapped to dispatcher error code, not
  `method_not_implemented`).
- The HTTP `PUT /api/worker/config` path keeps working unchanged.
- Behaviour is identical whether reload is triggered via gateway WS
  `config.put` or via worker HTTP `PUT /api/worker/config`.

## Notes

Implementation sketch (subject to PLAN-017 review):
- `bootstrapWorkerApp` returns `reloadRuntime` alongside `app/port/state`.
- `serve.ts` populates `configPut` handler with the same body as the HTTP
  route, calling the returned `reloadRuntime`.
- Dispatcher error codes for invalid-config / version-conflict map to
  meaningful operator-facing codes (not generic `internal_error`).
