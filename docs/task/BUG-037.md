# BUG-037 Fleet Audit log table scrolls the whole page

- **status**: in-review
- **priority**: P2
- **owner**: Codex
- **createdAt**: 2026-04-29 18:50
- **discoveredAt**: 2026-04-29 18:50
- **plan**: PLAN-044
- **reviewReadyAt**: 2026-04-29 18:55

## Description

Fleet Web UI `/admin/audit` renders up to 50 audit rows, but the table has no
vertical height constraint. The table content expands the route body, so the
entire fleet page scrolls instead of keeping the header, filters, and pager
stable while only the audit table scrolls.

## Expected Behavior

Audit log browsing should keep the fleet shell and route controls stable. Long
audit pages should scroll inside the table area, including horizontal overflow
for narrow viewports, without forcing the whole page to scroll through all rows.

## Acceptance Criteria

1. `/admin/audit` gives the audit rows an internal scroll container.
2. Fleet shell layout remains responsive at 390px and 430px widths.
3. Shared table changes, if any, remain backward-compatible for other Fleet and
   Worker tables.
4. Focused Web UI tests pass.

## Notes

- 2026-04-29 18:50: Claimed after user approved the proposal. Investigation
  found `AuditList` wraps `Table` in `overflow-hidden` without a vertical height
  limit, while the fleet root lets `main` own the route scroll.
- 2026-04-29 18:55: Implementation and validation evidence exists: fixed by
  making the Fleet shell viewport-bound, letting the
  Audit route reserve a `flex-1 min-h-0` table area, and adding a
  backward-compatible `Table.containerClassName` prop for internal scrolling.
  Added a responsive-shell regression that renders non-empty audit rows and
  asserts the table wrapper owns overflow. Kept in review because these changes
  remain in the dirty main worktree and have not been committed or explicitly
  accepted.
