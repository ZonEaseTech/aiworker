## Background

The HR People Workbench now routes profile actions into real worker sessions,
but the user can still lose orientation while the external engine is slow. A
session may already have written an artifact file while the local daemon has not
finished finalizing and indexing the artifact metadata yet. The UI currently
collapses these stages into generic active/completed labels, so users cannot
tell whether the engine is still working, the file is awaiting finalization, or
the artifact is ready for human review.

## Goals

- Make the session status chain visible without adding a separate status
  dashboard.
- Explain the three critical states in the existing session route:
  engine running, artifact file written but not indexed, and artifact indexed
  but awaiting human review.
- Keep the status model shared by the chat surface and artifact preview rail.
- Preserve the local worker contract: the UI only interprets existing session,
  turn, event, artifact, and review records.

## Non-goals

- Do not change engine execution, artifact indexing, DB schema, or API contracts.
- Do not add HR-only status state.
- Do not introduce automated review or memory admission.

## Acceptance Criteria

- A running session with no artifact shows a clear engine-running state.
- A session with a completed artifact file event but no indexed artifact shows a
  distinct finalizing/indexing state.
- A session with an indexed artifact and `needs_review` review state shows a
  clear human-review state instead of implying completion.
- The status appears in the session chat and artifact preview rail with
  consistent copy and tone.
- Focused WorkerStudio tests cover the finalizing state and review-ready state.
- Browser validation confirms the session route is readable and the status is
  positioned consistently in the real layout.
