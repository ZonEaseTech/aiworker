# BUG-049 User-scope init points to project-only executor doctor

- **status**: completed
- **priority**: P3
- **owner**: aiworker-maintainer
- **createdAt**: 2026-05-03 21:26
- **discoveredAt**: 2026-05-03 21:10
- **claimedAt**: 2026-05-03 21:26
- **completedAt**: 2026-05-03 21:27

## Observed Behavior

`aiworker init --global` prints `aiworker executor doctor --engine codex` as a next step, but executor capability diagnostics are project-scope only because they require `.aiworker/executor-capabilities.json`.

Following the printed next step from user or explicit scope exits with code 2 and asks the operator to initialize a project first.

## Expected Behavior

User-scope and explicit-scope initialization should not point operators at project-only executor capability commands.

Project-scope initialization should keep the executor capability readiness guidance because `.aiworker/executor-capabilities.json` exists there.

## Reproduction

```bash
tmp="$(mktemp -d)"
HOME="$tmp" aiworker init --global
HOME="$tmp" aiworker executor doctor --engine codex
```

## Acceptance Criteria

1. `aiworker init --global` next steps no longer include `aiworker executor doctor`.
2. Explicit `AIWORKER_HOME` init next steps no longer include `aiworker executor doctor`.
3. Project-scope init next steps still include executor readiness guidance.
4. Focused CLI integration tests cover the user/explicit-scope next-step output.

## Notes

- 2026-05-03 21:26 Claimed for pre-release polish after local review found the UX mismatch.
- 2026-05-03 21:27 Fixed by removing project-only executor doctor guidance from user/explicit init next steps while keeping it in project-scope init.
