# BUG-090 Settings autosave status and dialog scroll layout

- **status**: completed
- **priority**: P0
- **owner**: local

- **relatesTo**: apps/web/src/worker/worker-studio.tsx, apps/web/src/worker/studio.css, apps/web/src/worker/__tests__/worker-studio.test.tsx

## Background

Manual settings dialog testing surfaced two follow-up UI issues after the Worker
Web interaction polish pass:

- the autosave status pill starts as `saved`, so "All changes saved" is always
  visible even when no save action happened;
- long settings sections make the dialog content visually inconsistent instead
  of using a fixed-height body with vertical scrolling.

## Goal

Make the settings dialog stateful and visually stable: only show autosave status
after a real save/rescan event, and keep the dialog fixed-height with scrollable
settings content.

## Acceptance Criteria

- Opening settings does not show a saved autosave pill before any change.
- Saving/rescanning still shows saving/saved/failed status feedback.
- Saved feedback hides after a short confirmation window.
- Settings dialog uses a fixed height constrained to the viewport.
- Settings sidebar and content areas scroll vertically within the dialog body.
- Focused Worker Web validation passes.
