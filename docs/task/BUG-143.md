## Background

Review of the integrated composer exposed three state alignment gaps:

- a running session disabled the composer but did not put the send button into
  an explicit loading state;
- submitted file/image attachments stayed visible while the follow-up turn was
  already running;
- usage rendered as a text fraction, which looked reversed and competed with
  primary send affordances.

## Acceptance Criteria

- Running turns drive the follow-up composer busy state, not only the initial
  submit request.
- The send button exposes a loading state and `aria-busy` while the composer is
  busy.
- Follow-up attachments clear after material reads succeed and the turn submit
  starts.
- Usage is displayed as a compact token meter immediately left of send, with
  explicit `in/out` text and accessible full token counts.
- Focused component and WorkerStudio tests cover the busy state, usage
  placement and attachment clearing.

## Completion

- Added a shared send spinner state.
- Cleared follow-up attachments before awaiting the streaming turn lifecycle.
- Reworked usage into a compact circular meter near the send button.
