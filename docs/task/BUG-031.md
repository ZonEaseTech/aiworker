# BUG-031 Gateway start persists root WS URL instead of `/ws`

- **status**: completed
- **priority**: P1
- **owner**: Unassigned
- **createdAt**: 2026-04-28 20:18
- **discoveredAt**: 2026-04-28 20:18
- **releaseTarget**: `@zonease/aiworker-cli@0.4.4`
- **bkd**: 6kv9cqif

## Description

`aiworker gateway start` can start a local gateway, but it persists an operator
`gatewayUrl` that points at the HTTP root instead of the WebSocket upgrade path.
Follow-up operator commands then fail even though `/health` is healthy.

Observed behavior from a clean temporary project during `QA-001`:

1. `aiworker init --force` succeeded in a temp cwd.
2. `mkdir -p data` was required to work around `BUG-029`.
3. `aiworker gateway start --port <port> --no-serve-web` started the gateway,
   and `GET /health` returned HTTP 200.
4. `aiworker fleet list` exited `1` with:
   `WS connection to 'ws://localhost:<port>/' failed: Expected 101 status code`.
5. A separate black-box subtask reproduced the same issue on `:29218` across
   `fleet list`, `enroll list`, `fleet info`, `config get`, `chat`, and
   `token rotate`.
6. After manually normalizing temp `aim.json.gatewayUrl` to include `/ws`,
   `fleet list` returned `{ "workers": [] }` and `enroll list` returned
   `{ "pending": [] }`.

Root cause candidate:

- [apps/cli/src/aim/commands/gateway.ts](/home/ben/projects/aiworker/apps/cli/src/aim/commands/gateway.ts:47)
  and [apps/cli/src/aim/commands/gateway.ts](/home/ben/projects/aiworker/apps/cli/src/aim/commands/gateway.ts:76)
  persist `ws://localhost:${port}` without `/ws`.
- [apps/cli/src/aim/state.ts](/home/ben/projects/aiworker/apps/cli/src/aim/state.ts:24)
  uses the same root URL as the default.
- [apps/cli/src/aim/commands/common.ts](/home/ben/projects/aiworker/apps/cli/src/aim/commands/common.ts:42)
  passes the stored URL directly to the WS client.
- [packages/gateway/src/server.ts](/home/ben/projects/aiworker/packages/gateway/src/server.ts:88)
  only upgrades `/ws` and `/enroll-ws`.
- The black-box report notes that `docs/cli.md` local-state text currently says
  `ws://localhost:<port>`, while README/gateway protocol examples require
  `/ws`.

## Acceptance Criteria

1. `aiworker gateway start` persists `ws://localhost:<port>/ws` for both
   foreground and detached modes.
2. The default operator state points at `ws://localhost:9218/ws`.
3. Existing explicit URLs that already include `/ws` continue to work.
4. Bare origin gateway URLs are either normalized to `/ws` or rejected with an
   actionable validation error.
5. Add a regression smoke or unit test covering `gateway start` followed by an
   operator command such as `fleet list` against the started gateway.
