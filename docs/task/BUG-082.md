# BUG-082 Fleet-hosted Worker Admin cannot load brain governance routes

- **status**: completed
- **priority**: P1
- **owner**: local
- **createdAt**: 2026-05-06
- **discoveredAt**: 2026-05-06 14:19
- **completedAt**: 2026-05-06 14:29

- **relatesTo**: FEAT-040, PLAN-042, PLAN-103, BUG-081

## Observed Behavior

Fleet-hosted Worker Admin loads through `/w/:workerId/`, but the Brain page
cannot load its worker-local governance data. The UI shows:

- `Unsupported worker bridge path /api/worker/brain/summary`
- `Unsupported worker bridge path /api/worker/brain/admission`
- `Unsupported worker bridge path /api/worker/brain/artifacts`

## Expected Behavior

The fleet-hosted Worker Admin should be able to use the same Brain REST surface
that the worker-hosted Admin already uses, while preserving the gateway bridge
allowlist and worker/fleet data boundary.

## Actual Behavior

The worker HTTP bridge allowlist only maps `/api/worker/brain/test`. It does
not map the Brain summary, admission, or artifact routes used by the Worker
Admin Brain page, so gateway rejects those paths before forwarding a node RPC.

## Risk

P1 operator UX and governance observability risk. Worker-local REST works, but
operators using the canonical fleet-hosted Worker Admin cannot inspect or act
on Brain admission/artifact state.

## Validation

After fix:

1. Gateway bridge maps the Brain routes used by Worker Admin to explicit
   gateway proto methods.
2. Unknown worker bridge paths remain blocked; no generic proxy is introduced.
3. Worker bearer auth, redaction defaults, and bridge audit redaction continue
   to hold.
