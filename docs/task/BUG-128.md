## Background

The HR workbench promotion path passed artifact preview markdown as
`profileMarkdown`. If the artifact was a review proposal, the accepted
`README.md` could become proposal-shaped instead of a clean People Profile.

## Root Cause

The native skill boundary correctly treated skills as artifact producers, but
the product promotion path lacked a deterministic accepted-profile extraction
contract.

## Fix

- `profile-update-proposal` now requires an explicit
  `aiworker-profile-readme` fenced block for the exact accepted `README.md`
  draft.
- The HR product promotion path now extracts that fenced draft before calling
  `profile-revisions`; if no draft exists, it preserves the previous fallback.
- The skill now states the fenced draft must have an internally consistent
  `Review State`.
