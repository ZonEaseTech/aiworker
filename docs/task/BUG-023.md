# BUG-023 Release blockers after v0.3.0 prevent 0.4.0 publishing

- **status**: completed

- **owner**: Codex

## Description

Release review of `v0.3.0..HEAD` found several blockers before the next npm /
GitHub release can be cut:

1. `@zonease/aiworker-cli` still declares version `0.3.0`, which is already
   published as npm `latest`.
2. Brand-new project `aiworker init` deletes explicit
   `AIWORKER_MASTER_KEY` / `INTERNAL_SHARED_SECRET` env values before writing
   project-local `.env`, while later commands still let explicit env override
   `.env`. This can create an undecryptable `worker_identity` row on the next
   command.
3. GitHub Release compiled binaries are uploaded as raw files without sibling
   `web/` static assets or `drizzle/` migrations.
4. Root `bun run build` runs the Web build concurrently with the CLI build,
   while the CLI build also invokes the Web build and copies `apps/web/dist`.
   Stale chunks can leak into `apps/cli/dist/web`.

## Acceptance Criteria

1. Next publish target is a new semver version (`0.4.0`).
2. Project-scope init preserves explicit operator-provided secrets and
   `smoke:aiworker-run` passes without polluting the repository.
3. CLI publish manifest copies only fresh `fleet` and `worker` Web bundles and
   removes stale bundled assets before copying.
4. Root build no longer runs conflicting Web builds concurrently.
5. GitHub Release assets package compiled binaries with sibling `web/` and
   `drizzle/` directories.
6. Focused CLI tests, smokes, root quality gates, Web bundle checks, build, and
   publish dry-run pass.

## Dependencies

- **blocked by**: BUG-021, BUG-022
- **blocks**: `@zonease/aiworker-cli@0.4.0` release

## Completion Notes

Implemented the release hardening:

1. `apps/cli/package.json` now targets `0.4.0`.
2. `aiworker init` preserves explicit `AIWORKER_MASTER_KEY` and
   `INTERNAL_SHARED_SECRET` in brand-new project scope.
3. CLI subprocess tests cover `init` followed by `run --dry-run` under an
   explicit master key.
4. `smoke:aiworker-run` now uses an isolated temporary git project and HOME.
5. Root build sequences API -> Web -> CLI bundle to avoid concurrent Web dist
   writes.
6. CLI publish manifest clears `dist/web` and copies only
   `fleet` / `worker` production bundles.
7. Release workflow packages compiled binaries as tarballs with sibling
   `web/`, `drizzle/`, and `README.md`.
