## 历史记录标记 / Not Current Spec

本 bug 是 2026-04-30 对 `aiworker init` S2R 缺口的历史修复记录，不是当前 Skill/MCP/Tool 快速配置规格。文中“没有 `skill add` / `mcp add` / `toolset enable`”描述的是当时 FEAT-039 未完成范围。

当前边界：

- PLAN-041 S3 已落地为 brain/runtime project capability 草案的静态 validation 与 `aiworker doctor`。
- executor-native MCP projection 已拆到 FEAT-044 / PLAN-055，命令为 `aiworker executor mcp add/sync/doctor`。
- 不得从本文直接恢复顶层 `aiworker mcp add` 作为 executor config 命令。

## 描述

`aiworker init` 当前仍然沿用 S1 的安全预检与 bootstrap 行为：打印 preflight 后直接创建
`.aiworker/`、`local/worker.db` 和 stub persona 文件。它没有在初始化早期询问 Soul
预设值，也没有应用 Soul templates、customize flow、capability packs、adapter
projection、Soul update 治理或 self-iteration admission metadata。

这使 FEAT-039 的核心用户体验没有生效：用户期望通过 `aiworker init` 快速配置一个有
明确职责边界、能力预置和越权响应策略的项目级 worker；实际得到的是一个通用 stub
worker。

## 实际行为

在全新项目目录中执行：

```bash
aiworker init
```

实际流程是：

1. 输出 project-scope preflight。
2. 直接创建 `.aiworker/AGENT.md`、`.aiworker/SOUL.md`、`.aiworker/USER.md`、
   `.aiworker/MEMORY.md`、`.aiworker/ROLLUP.md`、`.aiworker/mcp.json`。
3. 直接 bootstrap `.aiworker/local/worker.db` 和 `.aiworker/local/.env`。
4. 打印 worker id 与 bootstrap token。

没有出现 Soul preset 选择，也没有 `customize` 问答。生成的 `SOUL.md` 仍是通用占位：

```markdown
# Voice & style

> Voice / style guide. Influences how the agent phrases responses across channels.
```

## 期望行为

对 brand-new project，`aiworker init` 应在创建 worker identity / worker.db 之前进入
Soul 配置阶段：

1. 询问或接受参数选择 Soul preset：
   `developer`、`project-manager`、`devops-sre`、`product-designer`、
   `qa-reviewer`、`support-operator`、`finance-ops`、`hr-recruiting`、
   `general-assistant`、`customize`。
2. `customize` 通过少量高信号问题生成职责、禁区、越权响应、沟通风格和高风险操作策略。
3. 选定 Soul 后生成非 stub 的 `SOUL.md` / `AGENT.md`，并写入最小
   `policy.json`、`toolsets.json`、capability pack 草案。
4. `--dry-run` 能展示将应用的 Soul/template/文件变更，且不创建 `.aiworker/local/worker.db`。
5. 非交互环境必须有明确路径，例如 `--soul developer` 或显式失败提示，不能静默写入通用 stub。

## 修复前排查结论

修复前分支只完成了 PLAN-041 S1，而不是 FEAT-039 的核心初始化体验。

已确认存在的实现：

- `apps/cli/src/commands/init.ts` 只有 `--global`、`--force`、`--dry-run` 行为。
- `aiworker init` 会调用 `ensureProjectAiworker()`，随后 bootstrap dotenv 与
  `loadWorkerContext()`，因此会直接创建 worker 本地状态。
- `apps/cli/src/commands/init.integration.test.ts` 覆盖的是 project layout、dry-run、
  no-overwrite、external agent detection 和 master key 保留。

已确认缺失的实现：

- 没有 `--soul`、`--pack`、`skill add`、`mcp add`、`toolset enable`、`soul update`
  等 CLI 入口。
- 没有 builtin Soul template registry。
- 没有 interactive Soul wizard 或 customize flow。
- 没有 `policy.json` / `toolsets.json` 生成。
- 没有 capability pack validation。
- 没有 `.aiworker/adapters/*`、managed section 或 external adapter sync。
- 没有 Soul update / pin / diff / approval / backup 流程。
- 没有 memory / skill / policy proposal admission metadata。

## 修复前 FEAT-039 验收缺口

逐项排查 FEAT-039 验收标准：

1. **部分满足**：现有 `.aiworker/`、`AGENTS.md`、`CLAUDE.md`、`.agents/`、`.claude/`
   不会被覆盖，外部 agent 文件只提示 future adopt/merge。
2. **未满足**：初始化 wizard 不支持 Soul preset 选择。
3. **未满足**：`customize` 不存在，不能生成 `SOUL.md`、`AGENT.md`、policy、toolsets
   或 capability pack 草案。
4. **未满足**：选择 Soul 后预置 Skill/MCP/Toolset/policy/adapters 的流程不存在。
5. **未满足**：Skill/MCP/Tool 快速配置命令和 validation 流程不存在。
6. **未满足**：职责外响应策略只存在于 PLAN-041 文档，没有进入 Soul template 或 runtime
   可消费配置。
7. **未满足**：`aiworker soul update` / diff / proposal / approval / backup / apply 不存在。
8. **未满足**：自我迭代写入 memory/skill/policy 前的 evidence/scope/confidence/source/
   review/rollback metadata 不存在。

## 修复范围

本次修复完成 PLAN-041 的 S2R 恢复切片：

1. 新增 builtin Soul preset registry，并支持 `developer`、`project-manager`、`devops-sre`、
   `product-designer`、`qa-reviewer`、`support-operator`、`finance-ops`、
   `hr-recruiting`、`general-assistant`、`customize`。
2. brand-new project 的 `aiworker init` 在创建 `.aiworker/`、worker identity 和
   worker.db 前先解析 Soul；非交互环境必须显式传 `--soul <preset>`，否则失败且不写文件。
3. `aiworker init --soul developer` 生成非 stub 的 `SOUL.md` / `AGENT.md`，并写入
   `policy.json`、`toolsets.json`、`capability-packs.json` 草案。
4. `customize` 在交互终端询问职责、禁区、职责外响应、沟通风格、高风险 approval 和默认能力。
5. `--dry-run --soul developer` 只预览 Soul/template/worker bootstrap 计划，不创建
   `.aiworker/` 或 worker.db。
6. 已存在 `.aiworker/` 或外部 agent 文件时继续保持 no-overwrite，只补缺失文件或提示
   adopt/merge candidate。

未纳入本 bug 的后续 PLAN-041 切片：

1. S3：Skill/MCP/Toolset/Policy pack validation 与快速配置命令。
2. S4：external adapter projection / managed section / conflict detection。
3. S5：Soul update / pin / diff / backup / approval。
4. S6：self-iteration proposal admission metadata 与 runtime Learning Loop 对接。

## 验收标准

1. `aiworker init` 在全新交互式项目中会先选择 Soul，再写 `.aiworker/` 和
   `.aiworker/local/worker.db`。
2. `aiworker init --soul developer` 能在非交互环境生成 developer Soul 的
   `SOUL.md` / `AGENT.md` / `policy.json` / `toolsets.json` 草案。
3. `aiworker init --dry-run --soul developer` 只预览 Soul/template 与计划写入，不创建
   `.aiworker/` 或 worker.db。
4. `customize` 能通过少量问题生成初始 Soul 与职责外响应策略。
5. 已存在 `.aiworker/` 或外部 agent 文件时仍保持 no-overwrite，只给出 adopt/merge 或
   patch proposal。
6. 所有新增 init 行为有聚焦 CLI integration tests 覆盖。
