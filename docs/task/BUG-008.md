# BUG-008 workerSummarySchema rejects self-enrolled worker (empty baseUrl)

- **status**: completed
- **priority**: P1
- **owner**: self
- **createdAt**: 2026-04-26 20:40
- **completedAt**: 2026-04-26 20:45
- **commits**: 9f79706

## Description

After PLAN-018 self-enroll lands, a worker that joins via
`AIWORKER_JOIN_TOKEN` is persisted to fleet.db with an empty `baseUrl`
(self-enrolled workers behind NAT have no inbound HTTP address —
this is precisely the case PLAN-018 unlocked).

`packages/gateway-proto/src/methods.ts::workerSummarySchema` declares
`baseUrl: z.string().min(1).optional()` — `optional()` allows
`undefined`, but the row from fleet.db comes back as the empty string
`''`, which fails `min(1)`. As a result `aim workers list`
(and any other consumer of `workerSummarySchema`, e.g.
`system.presence`) returns:

```
internal_error: workers.list 构造的 result 不符合 schema:
  String must contain at least 1 character(s) at workers[0].baseUrl
```

Reproduced live during PLAN-018 e2e validation (workstation `aiw`
self-enrolling to public gateway via wss URL form). The worker is
correctly persisted (`fleet.db` row + audit `gateway.worker.enrolled`)
but operators cannot list it.

### Acceptance criteria

1. After self-enroll, `aim workers list` returns the worker as
   `online: true` with `baseUrl` either omitted or empty without
   tripping result schema validation.
2. Existing pair / launch flows (which always set a non-empty
   `baseUrl`) keep returning the URL untouched.
3. New regression test in
   `packages/gateway-proto/test/parse.test.ts` (or equivalent) covering
   `workerSummarySchema` with empty / missing `baseUrl`.
4. No `apps/gateway` test regression.

## Notes

Trivial fix — single schema line; the row data itself is fine. Two
candidate fixes:

- A. Drop `.min(1)` from `baseUrl`, keep `.optional()` →
  `baseUrl: z.string().optional()`. Empty string passes; consumers
  that depend on `.length > 0` semantics (none today) would need to
  guard. Minimal blast radius.
- B. Coerce in handler: `baseUrl: row.baseUrl || undefined` in
  `apps/gateway/src/router/methods/workers.ts::handleWorkersList`.
  Doesn't fix `system.presence` if it also surfaces baseUrl.

Going with **A** — schema-level relaxation matches PLAN-018's intent
that self-enrolled workers may legitimately have no baseUrl.
