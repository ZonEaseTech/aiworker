# BUG-038 Worker info reports stale runtimeVersion after 0.4.8 upgrade

- **status**: pending
- **priority**: P2
- **owner**: unassigned
- **createdAt**: 2026-04-30 08:55
- **discoveredAt**: 2026-04-30 08:50
- **releaseTarget**: post-`@zonease/aiworker-cli@0.4.8`

## Observed Behavior

During the `0.4.8` test-fleet validation, the remote gateway and the temporary
local worker both ran the published `@zonease/aiworker-cli@0.4.8` package, but
worker info still reported:

```json
{
  "runtimeVersion": "0.2.0",
  "executor": {
    "type": "codex",
    "model": "gpt-5.5",
    "status": "healthy"
  }
}
```

This appeared through both operator and fleet-hosted worker paths:

- `aiworker fleet info <worker-id>`
- `GET /w/<worker-id>/api/worker/info`

## Expected Behavior

Worker info should expose a version that matches the running published CLI /
runtime package, or the field should be renamed/documented if it is not meant
to represent the installed AIWorker version.

## Sanitized Evidence

- Target release: `@zonease/aiworker-cli@0.4.8`.
- Gateway after upgrade: `aiworker/0.4.8 linux-x64 node-v24.3.0`.
- Temporary worker config: `executor=codex/default`, config version `2`.
- `fleet info` and bridged `/api/worker/info` both returned
  `runtimeVersion: "0.2.0"`.
- Source inspection shows `packages/core/src/worker/management/info.ts` still
  uses a hard-coded `WORKER_RUNTIME_VERSION = '0.2.0'`.

Sensitive values such as server id, tokens, OTP, public host, and worker token
were omitted.

## Root-Cause Candidate

`WORKER_RUNTIME_VERSION` is hard-coded instead of being derived from the
published package metadata or a build-time constant copied into the publish
artifact.

## Acceptance Criteria

1. A worker launched from `@zonease/aiworker-cli@<version>` reports the same
   `<version>` through `fleet info` and `/w/<worker-id>/api/worker/info`.
2. Existing worker info tests are updated to avoid pinning stale release
   literals.
3. Release validation can trust `runtimeVersion` as a version signal, or the
   API field is renamed/documented to make its semantics explicit.
