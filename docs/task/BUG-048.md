# BUG-048 `aiworker init` skips Soul prompt when legacy home looks like project scope

- **status**: completed
- **priority**: P1
- **owner**: aiworker-maintainer
- **createdAt**: 2026-05-02 21:26
- **discoveredAt**: 2026-05-02 21:20
- **plan**: PLAN-067

## Observed Behavior

After installing `@zonease/aiworker-cli@0.5.0`, running `aiworker init` can skip the Soul preset prompt even when the operator expects a fresh project-level initialization.

The prompt is present in the published package and appears in a truly brand-new interactive directory. The skip happens when `init` does not enter the brand-new project branch, especially when the current directory or an ancestor already contains `.aiworker/`.

One important case is running `aiworker init` from `$HOME` after a previous user-scope install has created `~/.aiworker/`. Current project detection sees `$HOME/.aiworker/` and treats `$HOME` as an existing project root, so `init` takes the idempotent re-init path and does not require or prompt for Soul.

## Expected Behavior

`aiworker init` should not silently treat the legacy user-scope home as a project initialization target.

For a project init that lacks Soul material, the CLI should either:

- prompt for Soul in an interactive terminal; or
- fail closed in non-interactive mode with the existing `--soul <preset>` guidance.

## Reproduction

```bash
# Simulates running from a home directory that already has legacy ~/.aiworker/
tmp="$(mktemp -d)"
mkdir -p "$tmp/.aiworker"
cd "$tmp"
HOME="$tmp" aiworker init --dry-run
```

Current output enters project-scope preflight and preserves the existing `.aiworker/` directory without asking for Soul.

## Acceptance Criteria

1. Running `aiworker init` from `$HOME` with an existing legacy `~/.aiworker/` no longer silently skips Soul selection for project initialization.
2. Already initialized project roots with valid `.aiworker/SOUL.md` and `.aiworker/AGENT.md` remain idempotent and do not prompt unexpectedly.
3. Existing explicit/user-scope paths remain available through `AIWORKER_HOME` or `--global`.
4. Non-interactive brand-new project init still requires `--soul <preset>`.
5. Tests cover legacy home collision, initialized project re-init, brand-new interactive/non-interactive behavior, and `aiworker scope` reporting.
