# BUG-076 Claude Code conversation classifier can execute tools and mutate Brain state before orchestrator turn handling

## Observed Behavior

During the published `@zonease/aiworker-cli@0.9.0` local-worker matrix under
`/home/ben/projects/debug-aiworker-cx/release-0.9.0-governance`, every
Claude Code pair emitted `conversation.classifier` events whose
`rawOutput` was not a classifier-only JSON response. The raw classifier output
described tool activity such as creating files, checking `aiworker`, and
submitting brain admission proposals.

On admission turns, the classifier path could create the admission proposal
before the normal orchestrator turn began. The later orchestrator turn then
saw the proposal as already present and emitted
`brain.governance.bypass_suspected` with
`assistant-claimed-admission-without-db-delta`.

This was reproduced across all five Claude Code Souls in the current matrix:

- `developer-claude-code`
- `hr-recruiting-claude-code`
- `finance-ops-claude-code`
- `qa-reviewer-claude-code`
- `general-assistant-claude-code`

Sanitized summary:

- `/home/ben/projects/debug-aiworker-cx/release-0.9.0-governance/sanitized/matrix-summary.md`
- `/home/ben/projects/debug-aiworker-cx/release-0.9.0-governance/reports/summary.json`

Representative raw evidence:

- `raw/developer-claude-code/turn08.stdout`
- `raw/developer-claude-code/turn09.stdout`
- `raw/hr-recruiting-claude-code/turn03.stdout`
- `matrix/developer-claude-code/.aiworker/local/worker.db`

## Expected Behavior

The conversation classifier must be a control-plane evaluator only:

1. It should return strict classifier JSON and no natural-language answer.
2. It must not receive tool-capable executor context.
3. It must not create files, call `aiworker`, submit admission proposals, or
   mutate `worker.db`.
4. Any `rawOutput` retained for fallback diagnosis must be bounded and
   redacted.

## Actual Behavior

The Claude Code classifier path can behave like a normal executor turn:

1. It emits non-JSON, long natural-language output.
2. The output contains tool-like activity and admission side effects.
3. `worker.db` admission rows can exist before the orchestrator's own turn
   handles the user message.
4. The later bypass detector can flag the assistant because no new DB delta
   occurred during the orchestrator phase, even though the classifier phase
   already mutated state.

## Risk

P1 / blocking for Brain Governance Kernel correctness.

This crosses the boundary between Brain hard logic and executor runtime:
classifier evaluation is supposed to be governance telemetry, not a
tool-capable workflow engine. It also makes admission provenance ambiguous
because a control evaluator can create durable Brain proposals before normal
message handling and audit expectations.

```sh

```

Then inspect:

```sh
rg -n 'conversation.classifier|brain.governance.bypass_suspected' \
  "$RUN/raw/developer-claude-code/turn08.stdout"
sqlite3 "$SCOPE/.aiworker/local/worker.db" \
  'select id,status,kind,target from brain_admission_proposals order by created_at;'
```

## Validation

After fix:

1. Claude Code classifier calls are tool-less and cannot mutate files or
   `worker.db`.
2. `conversation.classifier` fallback raw output is bounded and redacted.
3. Admission rows are only created through the normal orchestrator turn or an
   explicit operator CLI/API action, never by the classifier path.
4. The same 5-Soul Claude Code matrix has zero classifier tool-like rawOutput.

## Completion Evidence

- Suppressed control calls pass `AgentRunInput.tools=[]`; Claude Code adapter
  projects that into no-tool CLI flags and a defensive deny policy for control
  requests.
- Conversation classifier, intent classifier, quality gate, repair and
  compaction control paths now use the explicit no-tools contract.
- Focused gate: `bun test packages/core/src/worker/conversation/router.test.ts packages/core/src/worker/executor/engines/claude-code/executor.test.ts packages/core/src/worker/orchestrator/service.claude-code.test.ts` -> included in 58 pass / 0 fail batch.
