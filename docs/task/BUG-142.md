## Background

Review of the shared Session Kit follow-up work exposed four polish and
behavior gaps:

- the composer still read as separate attachment, textarea and action-bar
  regions rather than one professional input surface;
- the browser textarea resize affordance remained visible and made the composer
  feel like a raw form control;
- pasted images could be added twice when clipboard files and clipboard items
  represented the same image with different `File.lastModified` values;
- `Session running` and `Session output` signal rows used a narrower
  `fit-content` width than command/read-file activity rows.

## Acceptance Criteria

- The shared composer renders one integrated field shell containing attachments,
  textarea, warnings and action bar.
- Composer textarea resize is disabled; sizing is controlled by the shared
  composer layout instead of the browser resize handle.
- Clipboard file deduplication treats identical pasted files/items as one
  attachment even when `lastModified` differs.
- Session signal rows use the same row width grammar as activity/tool rows.
- Focused component tests cover composer field structure and duplicate paste
  suppression.
- UI governance, focused web gates, browser smoke and code-review-graph review
  pass before closure.

## Completion

Completed in `PLAN-381`:

- Added the shared composer field shell and moved composer internals into that
  surface.
- Disabled composer textarea resizing and aligned attachment tray, textarea and
  action bar spacing.
- Fixed pasted file/image duplicate suppression by normalizing clipboard file
  keys without `lastModified`.
- Unified session signal row width with activity/tool rows.
