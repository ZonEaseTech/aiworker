# BUG-073 Unknown subcommand silently falls back to top-level help — `aiworker soul --help` etc. show no error

## DOC-006 framing

This remains an onboarding polish task after the P1/P2 governance work. It
should make command discovery explicit without changing the Brain/Executor
boundary.

## Observed Behavior

```bash
$ aiworker soul --help
aiworker/0.8.0

用法:
  $ aiworker <command> [options]

使用引导:
  ...
```

The output is the *top-level* help, identical to `aiworker --help`. No
"unknown command" error, no hint that `soul` is not a stand-alone command,
no listing of available subcommands under the `soul` namespace. Same
behaviour for `aiworker brain --help`, `aiworker executor --help`,
`aiworker fleet --help`, etc.

The only way to discover that `aiworker soul list` and `aiworker soul show`
exist is to grep the top-level help for the `soul` prefix.

## Why this matters

- New operators try the obvious discovery pattern first
  (`aiworker <group> --help`). When it returns top-level help, they assume
  the namespace exists but has no inline documentation, or worse, that
  there are no subcommands.
- Confused-deputy risk: if a future release adds `aiworker brain` as an
  actual command, every old `aiworker brain --help` invocation in user
  notes silently changes meaning.

## Expected Behavior

`aiworker soul --help` (and analogous group-level invocations) should:

1. Print a focused help section listing only the subcommands under that
   namespace (`soul list`, `soul show`).
2. Or, if the group is purely a prefix with no canonical group command,
   print an explicit message:
   `aiworker soul: this is a command group. Run \`aiworker soul list\` or \`aiworker soul show <preset>\`.`
3. Either way, exit code should differ from `--help` on a real command if
   the lookup actually failed.

## Reproduction

```bash
$AIW soul --help     # currently top-level help
$AIW brain --help    # currently top-level help
$AIW executor --help # currently top-level help
$AIW fleet --help    # currently top-level help
```

## Acceptance Criteria

1. Group-level `--help` returns scoped help or a clear "this is a group"
   message.
2. Behaviour is consistent across `soul`, `brain`, `executor`, `fleet`,
   `gateway`, `worker`, `sessions`, `schedule`, `approvals`, `config`,
   `token`.
3. A snapshot test pins the help output for at least one group.
