# BUG-012 `aiworker gateway start` 在 npm install 场景下不能启动（仓库布局假设）

- **status**: completed
- **priority**: P1
- **owner**: (unassigned)
- **createdAt**: 2026-04-27 11:30
- **completedAt**: 2026-04-27 11:45
- **commits**: 0490888 (in-process gateway 重构 — 方案 D 落地)
- **discovered**: 2026-04-27 11:26 — REFACTOR-004 测试服迁移 step 7（cutover）首次 atomic swap 后 gateway 卡 activating，journal 报：
  ```
  ERROR  gateway start 失败: gateway 入口未找到。请设置 AIWORKER_GATEWAY_ENTRY 或使用 --entry <path>；
  或确保仓库内存在 apps/gateway/src/index.ts。
  ```

## Description

`aiworker gateway start`（`apps/cli/src/aim/daemon.ts::resolveGatewayEntry`）需要找到 `apps/gateway/src/index.ts` 文件作为 spawn 目标。当 cli 是 `bun install -g @zonease/aiworker-cli@<v>` 装的（npm registry tarball 仅含 `aiworker.js + README.md + package.json`），仓库布局**根本不存在**——命令无路可走。

测试服 cutover 实测（`/root/.bun/bin/aiworker gateway start`，systemd `aiworker-gateway.service`）：

```
Apr 27 11:26:15 localhost aiworker[233676]:  ERROR  gateway start 失败:
gateway 入口未找到。请设置 AIWORKER_GATEWAY_ENTRY 或使用 --entry <path>；
或确保仓库内存在 apps/gateway/src/index.ts。
Apr 27 11:26:15 systemd[1]: aiworker-gateway.service: Main process exited, code=exited, status=1/FAILURE
```

= **REFACTOR-004 完全阻塞**——cli npm install 路径不能跑 gateway，测试服迁移无路可走。

### Root cause

`apps/cli/src/aim/daemon.ts:133-150`（`resolveGatewayEntry`）：

```ts
function resolveGatewayEntry(explicit?: string): string {
  if (explicit && explicit.length > 0) return path.resolve(explicit)
  const fromEnv = process.env.AIWORKER_GATEWAY_ENTRY
  if (fromEnv) return path.resolve(fromEnv)
  const repoRoot = locateRepoRoot()
  if (repoRoot) {
    const candidate = path.join(repoRoot, DEFAULT_GATEWAY_WORKSPACE_REL, 'src', 'index.ts')
    if (existsSync(candidate)) return candidate
  }
  throw new Error('gateway 入口未找到。…')
}
```

设计假设：cli 跑在 monorepo 内，能 walk-up 找 `apps/gateway/src/index.ts`。npm install 的 dist bundle 只装 `aiworker.js`，没有 sibling apps 目录。

`runGatewayDaemonStart` 后续 spawn 一个 bun 子进程：`bun <entry>`（见 `apps/cli/src/aim/daemon.ts::runGatewayDaemonStart`）——本质是把 gateway 作为外部 .ts 文件 spawn，不是 cli 内 in-process。

### Acceptance criteria

1. `bun install -g @zonease/aiworker-cli@<next>` 后 `aiworker gateway start` 在**任意工作目录**（非仓库内）都能起 gateway 进程，监听默认 9218 端口（或 env `AIWORKER_GATEWAY_PORT` 覆盖）。
2. systemd 形态：`ExecStart=/root/.bun/bin/aiworker gateway start`（无任何 `--entry` / `AIWORKER_GATEWAY_ENTRY` env）能跑通；`/health` 响应 `{"ok":true,"service":"aiworker-gateway",...}`。
3. **不破坏开发体验**：`bun apps/cli/src/aiworker.ts gateway start`（仓库内 dev mode）仍按原有路径走。
4. cli bundle 体积 < 2 MB（当前 0.72 MB；含 gateway 后预计 < 1.5 MB）。

### 修复策略（推荐 D：in-process）

| 方案 | 工作量 | bundle 涨 | 适配性 |
|------|--------|-----------|--------|
| **A. AIWORKER_GATEWAY_ENTRY env** | 0（已支持） | 0 | ✗ user 必须自己提供 .ts 文件，违 REFACTOR-004 |
| **B. cli build 时 also bundle gateway → dist/gateway.js** | 小 | +0.5MB | daemon.ts fallback 找 ../gateway.js |
| **C. gateway 单独 publish `@zonease/aiworker-gateway`** | 中 | 0 | cli `gateway start` 走 `require('@zonease/aiworker-gateway')` |
| **D. gateway server in-process（推荐）** | 中 | +0.5MB | 把 `apps/gateway/src/{server,supervisor,...}` 抽到 `packages/gateway` 或 packages/core；cli `gateway start` 直接 import 同进程跑 |

D 优势：
- 单 bundle，install 体验最简
- `gateway start` 命令进程模型简化（不再 spawn 子进程）；signal 处理 / log 流统一
- gateway logic 与 cli 共用 `packages/{shared,gateway-proto,storage-sqlite,fs-layout}`，已经是 transport-agnostic 的，物理移动小幅度

### 短期 workaround（B，1 commit 可发 0.2.1）

最小改动让今天能 deploy：

1. `apps/cli/scripts/build-publish-manifest.ts`：build dist/aiworker.js 后 also `bun build --target=bun --minify apps/gateway/src/index.ts --outdir=apps/cli/dist --outfile=gateway.js`
2. dist `package.json` `files` 加 `"gateway.js"`
3. `daemon.ts::resolveGatewayEntry` 加 fallback：
   ```ts
   const cliBinDir = path.dirname(fileURLToPath(import.meta.url))
   const sibling = path.join(cliBinDir, 'gateway.js')
   if (existsSync(sibling)) return sibling
   ```
4. bump `apps/cli/package.json` `0.2.0 → 0.2.1`
5. `bun publish --access public` from `apps/cli/dist/`
6. 测试服 `bun install -g @zonease/aiworker-cli@0.2.1` + 重跑 REFACTOR-004 cutover
