# BUG-022 Web admin SPA mount paths break fleet routing and deep links

- **status**: completed
- **priority**: P1

- **claimedAt**: 2026-04-28 09:05

## Description

PLAN-022 restored the dual Fleet / Worker Web UI and serves both bundles under
`/admin/*` in production. The current bundle setup has two mount-path defects:

1. Fleet UI is served under `/admin/*`, but the fleet TanStack Router is created
   without `basepath`, so `/admin/` has no route match.
2. Production build assets use relative `./assets/...` URLs while the static
   servers fall back nested client routes to `index.html`. A direct reload at a
   nested path such as `/admin/workers/<workerId>` resolves JS/CSS under
   `/admin/workers/assets/...` instead of `/admin/assets/...`.

Dev-mode chooser links also point to `/fleet/` and `/worker/`, so both bundles
need runtime basepath inference that supports dev mounts and production
`/admin`.

## Acceptance Criteria

1. Fleet UI route matching works at `/admin/` and `/admin/workers`.
2. Worker UI route matching still works at `/admin/` and `/admin/config`.
3. Dev-mode mounts `/fleet/*` and `/worker/*` route correctly.
4. Production build emits `/admin/assets/...` URLs so nested admin deep links
   load JS/CSS from the stable admin root.
5. Focused Web lint, typecheck, tests, build, shared cycle check, and size report
   pass.

## Completion Notes

Implemented a shared router basepath resolver for the two Web bundles:

1. Production-hosted Fleet and Worker UI now use `/admin` as TanStack Router
   basepath.
2. Dev chooser mounts keep working at `/fleet/*` and `/worker/*`.
3. Production Vite builds now emit `/admin/assets/...` and `/admin/favicon.svg`
   URLs, so nested admin deep-link reloads resolve assets from the stable admin
   root.
4. Bootstrap tests cover production and dev mount paths for both route trees.
