# BUG-149 HR mounted reading-room layout falls back to one column

## Background

After the Host shell refactor, the HR Soul App renders through the Host
`micro-app` child surface but its reading-room workbench falls back to a single
vertical column at desktop width.

Investigation confirmed that the child app can still observe the Host viewport:
`matchMedia('(min-width: 80rem)')` is true inside the mounted page. The broken
contract is the Tailwind arbitrary grid selector used by the HR app:
`xl:grid-cols-[...]` does not survive the `@micro-zoe/micro-app` scoped CSS
rewrite, so the computed layout remains one column.

## Acceptance Criteria

1. HR mounted desktop workbench renders the profile list, reading room and
   composer as computed three columns through the Host `micro-app` path.
2. Narrow viewport behavior remains one column.
3. HR layout ownership stays inside `apps/aiworker-hr`; Host Web does not gain
   HR-specific layout logic.
4. Static HR tests assert the stable app-owned layout hook instead of a fragile
   Tailwind arbitrary class.
5. Mounted smoke coverage measures the computed layout after micro-app scoped
   CSS has run.
6. Focused HR tests, UI governance check, diff check and code-review-graph are
   run or any residual risk is recorded.

## Scope

- HR app-owned reading-room layout class and CSS.
- HR static mounted route assertions.
- Host mounted smoke script computed-layout assertion.
- PMA and changelog tracking for this bug.

## Non-Goals

- No Host Web HR renderer or HR-specific Host layout logic.
- No change to micro-app runtime options.
- No broad redesign of the HR workbench.
- No migration of unrelated profile draft or engine bridge work.

## Resolution

Replaced the HR reading-room grid contract with app-owned scoped-safe CSS.

- The HR route surface now exposes `hr-reading-room-grid` plus the existing
  `data-left-panel` and `data-right-panel` state attributes.
- HR CSS owns the narrow one-column default and desktop panel-state grid
  templates through ordinary selectors that survive micro-app scoped CSS
  rewriting.
- The last Tailwind `grid-cols-1` utility was removed from the route surface so
  Tailwind utility layer ordering cannot override the HR-owned desktop grid.
- Static HR tests assert the stable hook and reject the old arbitrary Tailwind
  grid selector.
- The Host mounted smoke script now verifies computed desktop and narrow grid
  layouts in a real browser after micro-app scoped CSS has run.
