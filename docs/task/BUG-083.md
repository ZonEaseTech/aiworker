# BUG-083 Fleet-hosted Worker Admin cannot continue selected chat conversations

- **status**: pending
- **priority**: P1
- **owner**: unassigned
- **createdAt**: 2026-05-06
- **discoveredAt**: 2026-05-06 14:35
- **relatesTo**: FEAT-040, PLAN-042, BUG-078, BUG-082

## Observed Behavior

Fleet-hosted Worker Admin chat can create a new task, list conversations, and
read messages, but continuing a selected conversation reports that the method
or bridge path is unavailable.

## Expected Behavior

`POST /api/worker/orchestrator/conversations/:id/messages` should work through
the same fleet-hosted gateway bridge as worker-local REST. The request should
append a prompt to the selected conversation and return the created task.

## Actual Behavior

The worker REST endpoint exists and Worker Admin calls it for continuation, but
the gateway bridge only maps `GET /api/worker/orchestrator/conversations/:id/messages`
to `orchestrator.messages.list`. The matching `POST` continuation path has no
explicit bridge method/mapping.

## Evidence

- `apps/web/src/worker/api.ts` calls
  `POST /api/worker/orchestrator/conversations/:id/messages` from
  `continueConversation`.
- `apps/api/src/worker/orchestrator/routes.ts` serves
  `POST /conversations/:id/messages` and calls
  `orchestrator.continueConversation(...)`.
- `packages/gateway/src/router/bridge.ts` currently allows only `GET` for the
  messages bridge path.
- `BUG-078` already records this POST path as part of the working worker REST
  contract.

## Proposed Fix

Add a narrow gateway bridge continuation method, for example
`orchestrator.messages.create` or `orchestrator.conversations.continue`, then
map `POST /api/worker/orchestrator/conversations/:id/messages` to it. The node
handler should call `state.runtime.orchestrator.continueConversation(id, prompt)`
and return `{ task }`.

## Non-Scope

- Do not change this in the 0.9.5 Brain bridge release.
- Do not introduce a generic worker HTTP proxy.
- Do not rewrite Worker Admin chat UI.

## Validation

When implemented:

1. Gateway bridge regression covers `POST /conversations/:id/messages`.
2. Node dispatcher regression covers the new continuation method.
3. Existing new-task, conversation list, message list, and SSE behavior remains
   unchanged.
