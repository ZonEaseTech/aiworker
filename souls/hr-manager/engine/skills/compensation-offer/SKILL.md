# 薪酬带宽分析 + offer 方案 + 谈判话术（TTPOS 岗位）
## 输出纪律

回答从结果开始：先给结论、交付物、必要假设或需要用户补充的关键信息，再给细节。可以在内部读取 AGENTS、knowledge、templates 或 MCP 配置，但不要把内部过程写成用户可见开场。不要以“使用 `skill` / 我会按 / 我会先 / 我先读取 / 已确认”开头；除非用户明确要求解释过程或需要说明阻塞原因，否则不叙述工具调用和资产读取过程。


**产出物**：一份**薪酬带宽分析 + offer 方案（脱敏）+ 谈判话术 + 审批单**，可走内部审批后据以发 offer。**本 soul 不内置具体薪资数值**——所有金额留占位 / 区间口径，实际数字须来自 TTPOS 实际购买 / 调研的市场数据。

## 前置输入（缺则先问）

岗位族与确定职级、目标分位策略（P25/P50/P75）、薪档 min–max 与中点（来自公司调研）、内部同级 compa-ratio 分布、候选人期望区间、是否有期权 / 奖金、用人预算与授权范围。

## 引用资产

- 方法论：`knowledge/hr-playbook.md` §4（分位、compa-ratio、宽幅、谈判）。
- 基准口径：`knowledge/benchmarks.md` §3（P25/P50/P75、80–120%/70–130% 宽幅）+ §4（职级对标，非官方）。
- 骨架：`templates/offer-approval.md`。

## 步骤

1. **定带宽分位**：据岗位稀缺度与预算选定位（TTPOS 里 Go 后端 / Flutter 较稀缺，偏 P50–P75；客服按城市偏 P25–P50）；核对薪档宽幅与内部公平（同级 compa-ratio 不畸高、防倒挂）。
2. **定 offer 结构**：base + 浮动 / 奖金 + 期权（如有）+ 试用期与目标；算出总包对应分位与 range penetration。**所有金额用占位 / 区间，绝不编造具体数字。**
3. **谈判策略与让步**：定底线与目标分位，按顺序让步（先给区间不给点位 → 用总包谈 → 非现金筹码如期权 / Title / 发展 / 远程弹性）；备话术。
4. **审批**：填审批单，草稿标「需法务 / 负责人审批（需送审）」。

## 边界

- **不内置具体薪资数值；具体数字须来自 TTPOS 实际调研。**

- 正式 offer letter 须经审批后发出（需送审）；薪酬数据保密，不明文外传。
