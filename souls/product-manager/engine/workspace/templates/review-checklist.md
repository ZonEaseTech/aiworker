# 需求评审 + 质量门 + 上线检查清单

> 用于评审前自检、过 ttpos-bot 质量门、上线前 gate。方法见 `knowledge/product-playbook.md` §2.5 / §6。

## A. 5 维质量门逐维自检（issue/PRD 发出前必过）
> gating 满分 8（4 维），pass 阈值默认 **bug 6 / feature 5 / epic 4**（`ISSUE_QUALITY_THRESHOLD_*` 可覆盖）。逐维打 0/1/2 自评。

| 维度 | gating | 自评 | 过 2 分要点 |
| --- | --- | --- | --- |
| title_specificity | 是 | _/2 | 动作+症状/价值；**无 `[FEAT]`/`[POS]` 方括号前缀**（带前缀封顶 1） |
| narrative_completeness | 是 | _/2 | feature: `## 背景`+`## 用户故事`+`## 验收标准` 全且实 |
| verifiable_items | 是 | _/2 | **≥3 条可测 AC**（Given/When/Then） |
| code_locality | 否(咨询) | _/2 | `## 代码定位` 给真实表/模型/终端（不卡门但建议写满） |
| context_links | 是 | _/2 | `## 关联`：父 Epic / 相似 issue / 受影响终端+版本 |

- [ ] 4 个 gating 维之和 ≥ 对应类型阈值（feature 默认 5/8、epic 4/8、bug 6/8；建议尽量满 8）。
- [ ] 标题无方括号前缀。
- [ ] AC ≥3 条且可测，覆盖边界/空/错误。
- [ ] 写了 `## 代码定位` 与 `## 关联`。

## B. 需求评审清单（评审前 PM 自检）
- [ ] 目标与 Job 写清，区分了问题与方案（不是直接接收用户给的方案）。
- [ ] 目标角色 × 终端明确，落在交易闭环某一环。
- [ ] 范围与**非目标**都写出（含：本期哪些终端/市场/单店还是连锁）。
- [ ] **多租户**：shop{company_uuid} or saas 库说明；新表/改表有 migration + 旧 app 兼容。
- [ ] **终端影响面 + 风险分级**：涉 pos/支付/订单(高风险)标注 100% 覆盖 + 回滚开关。
- [ ] 优先级有 Priority 依据（RICE/Kano），且算了 `sprintCandidateScore`（见 `sprint-priority-table.md`）。
- [ ] SP 已估（无 SP 会被标 needs_estimate；>13 拆分）。
- [ ] 经营指标口径无歧义（分子/分母/时间窗/数据源表/时区 Asia/Bangkok），含护栏。
- [ ] 依赖、风险、关键假设及验证方式列出；标清事实/假设/猜想，无臆造数据。

**评审产出**：结论（通过 / 修改后通过 / 不通过）+ 待办 + 负责人 + 时间。

## C. 上线前检查（Go/No-Go gate，含多租户/终端）
- [ ] **埋点/指标**：经营指标 + 护栏指标数据口径就位并验证（按表 lineage）。
- [ ] **多租户灰度**：按 company_uuid/门店切；内部店 → 少量真实门店 → 扩量 → 全量。
- [ ] **终端兼容**：受影响终端全测；高风险(pos/支付/订单) 100% 覆盖；旧版本 app 降级兼容（server v2.23.x / flutter v2.22.x 版本不齐）。
- [ ] **回滚**：一键回滚开关可用，回滚阈值事前定；shop 库 schema 变更可回退。
- [ ] **HQ/连锁**：连锁与单店行为差异验证；`hq_control_setting`/`hq_field_override` 下发正确。
- [ ] **市场**：默认市场 + 各市场（支付/税费/多语言）差异验证；泰国主市场单独过。
- [ ] **监控/告警**：核心 + 护栏指标看板 + 告警就绪。
- [ ] **通知/沉淀**：变更说明、客服/门店知会；高频问题预备 KB。

**Go/No-Go 结论**：<上线 / 推迟 / 缩范围上线> + 理由 + 灰度切口。
