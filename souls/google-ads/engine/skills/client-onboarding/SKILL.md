# 餐厅客户 Onboarding 简报 + 初始账户方案
## 输出纪律

回答从结果开始：先给结论、交付物、必要假设或需要用户补充的关键信息，再给细节。可以在内部读取 AGENTS、knowledge、templates 或 MCP 配置，但不要把内部过程写成用户可见开场。不要以“使用 `skill` / 我会按 / 我会先 / 我先读取 / 已确认”开头；除非用户明确要求解释过程或需要说明阻塞原因，否则不叙述工具调用和资产读取过程。


**产出物**：一份填好的餐厅客户 onboarding 简报 + 初始账户方案，符合 `templates/client-brief.md`。

## 前置：必须先确认的输入

- 菜系 / 业态、客单价 AOV 与毛利、门店数 / 地址
- 商圈 / 覆盖半径、目标食客
- 首要本地动作目标（到店 / 来电 / 路线 / 订餐 / 外卖）+ 月预算
- GBP 现状（有无 / 是否 verified / 主类目）、现有转化追踪
- 文案语言、外卖平台

## knowledge / templates 引用

- 方法论：`knowledge/local-restaurant-ads-playbook.md` §1（客户画像四问 + 本地动作目标）/ §6（盈亏平衡反推）/ §8（代运营组合 + 利益冲突披露）
- 骨架：`templates/client-brief.md`
- 基准：`knowledge/benchmarks.md`（Restaurants & Food 行，判断预算 / 成本目标是否现实）

## 步骤（端到端）

1. **画像采集**：菜系 / AOV / 毛利 / 商圈 / 门店数 / 目标 / 预算（playbook §1 四问）。
2. **盈亏平衡反推**：到店 / 订单成本上限 = AOV × 毛利（playbook §6），作为后续出价目标天花板。
3. **现状盘点**：GBP 是否认领 verified（决定是否 gbp-optimization 先行）、转化追踪、历史投放。
4. **冷启动渠道顺序**：默认 GBP 优化 → 本地搜索攒量 → 达门槛上 PMax 门店目标（playbook §2 决策树）。
5. **初始出价**：本地小店常 Max Conversions / Max Clicks 起步（playbook §5）。
6. **风险披露**：到店建模 / 外卖归因缺口（§6）、同商圈竞品客户披露与错位（§8）、PDPA。

## 填好的范例（曼谷泰式火锅店 onboarding）

**客户**：「สุกี้บ้านเรา / 我家火锅」，曼谷素坤逸（สุขุมวิท）单店泰式火锅 + buffet；AOV ฿550、毛利 ~60% → **盈亏平衡到店价值 ≈ ฿330**；目标：到店 + 来电 + 订位；月预算 ฿30,000；GBP 已认领但**未 verified**、主类目误设为泛「Restaurant」；无转化追踪；文案泰语主、中文辅（华人游客）；外卖接 LINE MAN。

| 简报项 | 填写 |
| --- | --- |
| 业态 / AOV / 毛利 | 泰式火锅+buffet / ฿550 / 60% → 到店成本上限 ฿330 |
| 商圈 / 半径 | 素坤逸；驾车 ~5 km + 步行圈（火锅驾车圈为主）|
| 目标 / 预算 | 到店>来电>订位；฿30,000/月 |
| GBP 现状 | 已认领、**未 verified**、主类目泛「Restaurant」（待修 ร้านสุกี้）|
| 冷启动顺序 | ① GBP 优化（先 verify + 改类目）② 本地搜索攒量 ③ 达门槛上 PMax 门店目标 |
| 初始出价 | 本地搜索 Max Conversions（来电/路线/订位为转化）攒到 ≥30/月 |
| 预算分配 | GBP 0（免费先做）/ 本地搜索 ฿18,000 / 预留 ฿12,000 待 PMax |

**多客户对照（次要客户）**：同代运营已有清迈一家咖啡馆，**不同城不同菜系 → 无直接利益冲突**；若未来接素坤逸第二家火锅店则触发 §8 同商圈竞品披露。

**首月里程碑**：GBP verified + 类目改 ร้านสุกี้ + 本地搜索上线 + 来电 / 路线 / 订位追踪就绪。

**决策点**：GBP 未 verified → **不先砸 PMax**（playbook §3，地基未稳付费打水漂）；฿30,000 月预算按餐饮 CPC（泰国应低于 $2.05 聚合值）估算可承接相当量本地搜索点击，但到店成本须盯 ฿330 上限。

## 交付前自检清单

- [ ] AOV × 毛利已算出成本上限（出价目标天花板）
- [ ] GBP verified 状态已确认，未 verified 则 gbp-optimization 排在付费前
- [ ] 冷启动渠道顺序符合 playbook §2 决策树（小店先本地搜索后 PMax）
- [ ] 到店建模 / 外卖归因缺口已写入简报并告知客户
- [ ] 同商圈竞品客户冲突已检查与披露（§8）
- [ ] 文案语言 + 泰国 PDPA 合规已记录

## 边界

不保证到店 / ROI；到店为建模值、外卖有归因缺口；真实 API 接入是 Phase 2（`knowledge/integrations.md`），密钥不进 descriptor/DB/日志；酒类 / 食品 / PDPA 合规以官方政策与本地法规为准。
